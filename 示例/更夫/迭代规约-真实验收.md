# 第八轮迭代共享契约：真实环境验收逼近（v1.1 / M4 延伸）

> 前七轮的能力基本都在「本地模拟」口径：混沌未真杀进程、压测无真实并发、GitHub 闭环无真实仓库、无生产守护。
> 本轮用**真实 OS 进程、真实并发、本地 git 仓库**把 PRD §12 第 2、3、4 项中本地可真实验证的部分推进到真实执行，并补生产进程守护。
> 沿用「四子代理并行 + 主代理独占契约/入口/文档/最终验收」分工。

## 0. 范围与诚实边界

- **本轮做**：真实 `kill -9` 子进程 ×10 与恢复验证；真实并发压测与 p95 对照；本地临时 git 仓库跑通 Issue → 分支 → PR 载荷 → review → merge → `ended(merged)`；systemd / supervisor 守护模板与轮询兜底说明。
- **本轮不做**：接真实 GitHub / 飞书 / 企微、发真实网络请求、真实云主机部署、真实 observe 一周运行。
- **诚实口径**：
  - 本地 `kill -9` 是真实 OS 信号，但环境是开发机，不等于生产环境 ×10 全部场景；
  - 本地 git 仓库是真实 git 操作，但不是真实 GitHub 的 webhook / 权限 / CI；
  - p95 ≤ 单会话基线 60% 若未达成，必须如实记录为未达成，不得改口径硬凑。
- **测试约定（Python 层）**：一律用 `sys.executable` 启动子进程（CI 克隆后无 `.venv` 路径），临时文件用 `tempfile` 并在退出时清理，**禁止硬编码 `.venv/bin/python`**。

## 2. 接口与验收要求

### A `test_chaos_real_process.py`（真实进程混沌）

- 用 `subprocess.Popen([sys.executable, main.py, 脚本.道], cwd=示例/更夫)` 启动**真实 Python 子进程**运行道语言脚本（可选 `GENGFU_NO_LLM=1` 避免 ollama 依赖）。
- 至少 10 轮：进程启动后发 `kill -9`（用 `proc.kill()` / `os.kill(pid, SIGKILL)`），等待退出，验证：
  - 退出码为负信号（-9）；
  - 重启后从持久化存储恢复，Outbox 中已投递消息**不重复**、未投递消息**不丢失**（用幂等键校验）。
- 用 `tempfile.TemporaryDirectory()` 隔离每轮数据库；子进程 cwd 必须是 `示例/更夫`（模块搜索基于 os.getcwd()）。
- 加 `pytest.mark.slow` 之类的可选标记也好，但默认应能在 `pytest tests/ -q` 中跑完（单轮 ≤2 秒）。
- 测试中不得依赖真实网络 / ollama；不得修改产品代码来「让测试通过」。

### B `test_load_real_concurrency.py`（真实并发压测）

- 用 `concurrent.futures.ThreadPoolExecutor` 或真实多线程发**真实并发请求**（可用 `urllib` 打本地 `DaoHttpServer`，或并发调用解释器线程），不再是纯 CPU 串行模拟。
- 对照两组：① 单会话基线；② Router 批处理组。记录 p50 / p95 / max。
- **硬指标**：噪音误建单 = 0；「p95 ≤ 基线 60%」若未达成，测试应 `pytest.skip` 或在断言中如实标注未达成（不得伪造数据），并在交付消息里报告实测数字。
- 端口用 0 自动分配；服务器线程要正确关闭，避免端口泄漏。

### C `test_local_git_loop.py`（本地 git 真实闭环）

- 用 `tempfile.TemporaryDirectory()` 创建 bare 仓库 + 工作克隆（`git init --bare` / `git clone`，git config user.email/user.name 本地设置）。
- 跑通：**初始提交 → 模拟 Issue 事件 → 建分支 → 应用 PR 载荷（真实文件改动 + commit + push）→ review 检查 → merge 回主干 → 工单状态 ended(merged)**。
- PR 载荷可复用第七轮 GitHub 适配器 / 执行器的输出结构；若需调用道语言脚本，用 `sys.executable` + `main.py`（cwd=`示例/更夫`）。
- 断言分支存在、commit 可达、合并后文件内容正确、工单信号为 `ended(merged)`。
- 不接真实 GitHub、不设置 remote 到外网。

### D `示例/更夫/部署/`（生产守护）

- `systemd/更夫.service`：ExecStart 用绝对 Python 路径 + 入口脚本绝对路径，WorkingDirectory 设为 `示例/更夫`，Restart=always，环境变量说明（`GENGFU_NO_LLM`、`更夫端口`、`更夫数据库`）。
- `supervisor/更夫.conf`：等价的 supervisor 配置。
- `README.md`：安装步骤、`systemctl enable --now` / `supervisorctl` 命令、日志位置、环境变量、轮询兜底说明（PRD NFR「轮询兜底容忍 webhook 丢失」），并写清**未做真实云主机部署验证**。

## 3. 验收口径

- 每代理自检：实际运行自己新增的测试 / 校验配置文件语法，贴出关键输出与退出码。
- 主代理独立复验（不凭代理消息下结论）：全量 pytest + 全部 `.道` 回归 + 入口演示 + ruff + 提交。
- 本轮可**部分勾选** PRD §12 第 3 项中的「真实 kill -9 ×10 在本地 OS 已执行」，但完整语义（生产环境、断网 ×10、重复投递 ×10 的真实外部消息计数）仍未达成，**整项 DoD 继续保持未勾选**；第 2、4 项同理只在注记中写「本地真实部分已验证」。
