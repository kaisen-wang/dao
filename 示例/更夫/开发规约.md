# 更夫 Nightwatch — 并行开发规约

## 0. 任务背景

用**本项目道语言**实现 PRD《常驻研发协作 Agent》（`任务/常驻研发协作 Agent.md`，代号「更夫 Nightwatch」）的**非 GitHub 部分**。

**本轮明确不做（GitHub 相关）**：webhook 接入、PR 创建、Issue/PR 评论投递、webhook 验签、GitHub API 封装、IM 适配器、CI 状态源。
所有事件源在本轮用「本地模拟事件」替代，Outbox 只做本地持久化与投递记录，不真正发网络请求。

**本轮要做**：领域模型与状态机、SQLite 持久化与崩溃恢复、准入矩阵与白名单、不可变授权、语义评估(Eval)、三级执行模式、Slot 调度、Outbox 幂等、成本熔断、Worker 与六类报告、异步工具模拟、Web 看板骨架、全局暂停、Watchdog 巡检。

产出全部放在 `示例/更夫/`，入口为 `接入层/入口.道`。

1. 字符串模板 `` `文本{变量}` `` 用反引号；插值里放**简单变量或属性访问**最稳；复杂函数调用先算成中间变量再插值。

## 4. 共享契约：`领域层/领域.道` 已导出内容（只读，直接用）

**常量**
- 阶段：`阶段排队` `阶段执行中` `阶段等事件` `阶段待审核` `阶段受阻` `阶段失败` `阶段结束`
- 模式：`模式关闭`(off) `模式审计`(observe) `模式自动`(auto)
- 准入：`准入显式` `准入候选` `准入忽略` `准入机器人`
- 报告：`报告进度` `报告等待` `报告就绪` `报告受阻` `报告失败` `报告丢弃`

**类型与字段**
- `工单(编号,标题,来源,外部编号,发起人,内容,模式=模式审计,策略版本="v0.1")`；字段：编号/标题/来源/外部编号/发起人/内容/阶段/模式/策略版本/准入/授权/绑定/未交付输入(列表)/创建时间/结束原因；方法：`描述()` `已结束()` `加入输入(消息)` `取输入()` `待交付数()` `结束(原因)`
- `授权(工单编号,授权人,策略版本,范围)`；方法：`覆盖(请求范围)`→逻辑、`描述()`
- `触发(来源,外部编号,话题编号,发起人,内容,是否机器人=假,是否CI=假)`；方法：`去重键()`→SHA256、`描述()`；字段含 `准入`/`策略版本`/`时间`
- `报告(工单编号,类型,消息,数据=空)`；方法 `描述()`
- `执行绑定(工单编号,执行者,槽位)`；字段 `编号`/`状态`(pending/running/ended)；方法 `开始()` `结束()` `描述()`
- `决策(触发编号,结论,理由,策略版本)`；方法 `描述()`
- `话题(编号,名称)`；方法 `订阅(工单编号)` `退订(工单编号)` `已订阅(工单编号)`；字段 `工单列表`

**函数**
- `推导阶段(工单对象, 报告列表)` → 阶段常量
- `可重开(工单对象, 消息来源, 是否授权内)` → 逻辑
- `新工单编号()` → 文本
- `建报告(工单编号, 类型, 消息, 数据=空)` → 报告对象

## 5. 各模块必须实现的接口（签名已定，按此实现）

### 5.1 基础设施层/存储.道【子代理A】
```
导出 函数 打开存储(路径="更夫.db")            // 建表+WAL，返回连接；模块级保存
导出 函数 保存工单(单)                         // 真/假
导出 函数 读取工单(编号)                       // 工单对象或空
导出 函数 列出工单()                           // 工单对象列表
导出 函数 保存触发(触)                         // 新事件真，重复假（按去重键幂等）
导出 函数 列出触发()                           // 触发对象列表
导出 函数 保存报告(报)
导出 函数 列出报告(工单编号)                   // 报告对象列表
导出 函数 保存决策(决)
导出 函数 列出决策(话题编号=空)                // 空=全部
导出 函数 保存授权(授)
导出 函数 读取授权(工单编号)                   // 授权对象或空
导出 函数 投递入队(工单编号, 类型, 内容, 幂等键="")  // 返回投递ID
导出 函数 待投递列表()                         // 字典列表
导出 函数 标记投递(投递ID)
导出 函数 统计()                               // 字典：各表计数
```
要求：表结构自建；对象↔字典转换正确（尤其 `未交付输入` 用 JSON 编码存文本）；参数一律用 `?` 绑定。

### 5.2 应用层/恢复.道【子代理A】
```
导出 函数 恢复检查点()   // 结束所有未结束绑定；对每个工单补投一条恢复说明；返回字典 {结束绑定数, 补投数, 说明}
```

### 5.3 应用层/准入.道【子代理B】
```
导出 函数 创建准入器(白名单列表)   // 返回准入器对象
  准入器.判定(触) -> 准入常量       // 白名单+明确请求→显式；CI/普通评论→候选；机器人→机器人；其余→忽略
  准入器.加白(用户名)
  准入器.移除白(用户名)
  准入器.白名单() -> 列表
导出 函数 是噪音(文本) -> 逻辑       // 空内容/纯符号/已知噪音短语
```

### 5.4 应用层/授权.道【子代理B】
```
导出 函数 授予(单, 授权人, 策略版本, 范围) -> 授权对象
导出 函数 校验(授, 请求范围) -> 逻辑
导出 函数 拒绝扩权(单, 请求范围, 请求人) -> 决策对象   // 结论="needs_reauth"，理由说明越权须重新授权
```

### 5.5 应用层/评估.道【子代理B】
```
导出 函数 创建评估器(规则列表, 策略版本="v0.1") -> 评估器对象
  评估器.评估(触, 模式) -> 决策对象    // 命中规则且模式非关闭→结论"would_accept"；否则"would_ignore"；理由为中文
  评估器.版本() -> 文本
导出 函数 串行评估(评估器, 触发列表, 模式) -> 决策列表   // 按话题顺序逐条评估（同 Thread 串行）
```
规则字典格式：`{"名称":"...", "关键词":["..."], "结论":"would_accept", "范围":["..."]}`

### 5.6 应用层/调度.道【子代理C】
```
导出 函数 创建调度器(槽位数=2) -> 调度器对象
  调度器.占用() -> 槽位号或空      // 无空闲返回空
  调度器.释放(槽位号)
  调度器.排队数() / 运行中数() / 容量()
导出 函数 创建预算(单票调用上限=80, 单票token上限=100000, 全局日上限=5.0, 单次成本=0.01) -> 预算对象
  预算.记账(工单编号, 调用数=1, token数=0) -> 逻辑   // 未超限真，超限假
  预算.用量(工单编号) -> 字典
  预算.全局超额() -> 逻辑
  预算.日重置()
```
要求：用 `原子整数` 计数，保证并发安全；不依赖外部模块。

### 5.7 应用层/执行.道【子代理C】
```
导出 函数 执行工单(单, 调度器, 预算, 报告回调, 步骤列表=空) -> 报告对象
   // 占用槽位→模拟执行步骤→依次回调六类报告→释放槽位→返回末报告
导出 函数 生成报告序列(工单编号) -> 报告列表   // 依次 progress/waiting/ready/blocked/failed/dropped 各一条的演示数据
导出 函数 运行异步工具(命令名, 秒数, 完成回调)   // 用 调度.延迟执行 模拟 start，到时回调回投结果
```
要求：不调用真实 LLM/网络；报告回调为道语言函数，接收报告对象。

### 5.8 基础设施层/看板.道【子代理D】
```
导出 函数 创建看板(取工单函数, 取决策函数, 状态字典) -> 看板对象
  看板.注册(服务器)          // 注册 GET /、/审计、POST /暂停 等路由
  看板.首页() -> 文本 HTML   // 工单看板（按阶段分组）
  看板.审计页() -> 文本 HTML // Trigger/Decision 审计流
导出 函数 处理暂停(状态字典, 请求) -> 字典  // 切换 状态字典["暂停中"]，返回 {"状态码":200,"内容":"..."}
```
要求：HTML 手写即可；不依赖模板引擎；状态字典含 `暂停中`(布尔)、`模式`(文本)。

## 6. 编码规范与验收

1. 所有标识符、注释、用户可见消息用**中文**。
2. 注释独占一行；不要用 `匹配`。
3. 每个文件顶部用注释写清职责与对应 PRD 需求编号。
4. **只实现上述接口**，不要臆造标准库函数；不确定 API 就读 `文档/` 下对应文件。
5. 每个模块写完必须**自检**：在 `示例/更夫/` 下临时建一个 `_测_xxx.道` 导入该模块并调用全部导出函数，用第 2 节命令运行通过后再交付；临时测试文件运行完删除。

7. 代码尽量简单稳健，避免复杂嵌套与长字符串模板。
