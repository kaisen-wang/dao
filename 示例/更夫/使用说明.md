# 更夫 Nightwatch 使用说明

## 一、项目定位

「更夫 Nightwatch」是用**本项目道语言**实现的一个**常驻研发协作 Agent** 演示。
它对应 PRD《常驻研发协作 Agent》的**非 GitHub 部分**：观察环境事件（本地模拟），做准入判定、语义评估、授权、调度与执行，并把过程沉淀到工单、报告、决策与审计流中。

本轮明确**不实现 GitHub 相关能力**（webhook 接入、PR 创建、Issue/PR 评论投递、webhook 验签、GitHub API 封装等），所有事件源以「本地模拟事件」替代。

## 二、如何运行

模块的导入路径**相对运行时 cwd 解析**，不支持 `./` 或 `../` 前缀。因此**当前工作目录必须切到 `示例/更夫`**：

```bash
cd /home/carson/WorkBuddy/Worktrees/道/heads-main-032a6f50/示例/更夫
python3 /home/carson/WorkBuddy/Worktrees/道/heads-main-032a6f50/源码/main.py 入口.道
```

- 第一行 `cd` 不可省略：若在项目根目录直接运行，导入 `核心.领域` 等会失败。
- 入口为 `入口.道`，由它组装各模块并跑端到端演示。
- 当前入口只渲染看板首页与审计页并打印长度摘要，不启动 HTTP 服务（避免演示阻塞）。
- 若要实际访问 Web 看板：创建服务器后调用看板的 `注册(服务器)`，再 `启动(端口)`；路由为 `GET /`（工单看板）、`GET /审计`（决策审计流）、`POST /暂停`（切换全局暂停）。示例：`从 网络 导入 创建服务器` → `定义 服务器 = 创建服务器()` → `看板对象.注册(服务器)` → `服务器.启动(8080)`。

## 三、模块清单与职责

共享契约位于 `核心/领域.道`，定义工单、授权、触发、报告、执行绑定、决策、话题等类型与阶段/模式/准入常量，以及状态机函数。其余模块一律从此处导入，不另定义契约。

| 模块 | 职责 |
|---|---|
| `核心/领域.道` | 领域模型与状态机：工单、授权、触发、报告、绑定、决策、话题；阶段推导与重开规则；全局共享契约（只读） |
| `核心/存储.道` | SQLite 持久化与幂等：工单/触发/报告/决策/授权存取，Outbox 入队与投递标记，WAL，统计 |
| `核心/恢复.道` | 崩溃恢复：结束所有未结束的绑定，为每个工单补投一条恢复说明 |
| `核心/准入.道` | 准入矩阵与白名单：明确请求判显式，CI/普通评论判候选，机器人单列，噪音忽略 |
| `核心/授权.道` | 不可变授权：建授权、范围校验、越权评论生成拒绝扩权决策（无 UPDATE 路径） |
| `核心/评估.道` | 语义评估（Eval）：按规则与策略版本逐条评估触发，产出 would_accept / would_ignore 决策 |
| `核心/调度.道` | Slot 调度与成本熔断：原子槽位占用/释放，调用数/token/日成本预算记账与超限判定 |
| `核心/执行.道` | Worker 与六类报告：工单执行模拟、progress/waiting/ready/blocked/failed/dropped 报告序列、异步工具模拟 |
| `核心/看板.道` | Web 看板骨架与审计流：按阶段分组展示工单、决策审计页、全局暂停路由 |

## 四、演示的四类流程

1. **显式请求**：白名单用户明确请求 → 判定为 `explicit` 准入 → 建工单并绑定不可变授权 → 进入调度与执行，回调各类报告。
2. **observe 候选审计**：CI 变化或普通评论 → 判定为 `candidate` → Eval 语义评估产出决策（采纳或忽略）→ 记入决策与审计流，在审计页可逐条查看。
3. **评审跟进**：工单处于「等事件 / 待审核」阶段时，交付未交付输入或依据重开规则处理人工跟进消息，推动阶段流转，报告随步回调。
4. **中断恢复**：模拟崩溃后调用恢复检查点 → 结束所有未结束绑定 → 补投恢复说明；Watchdog 巡检展示异常工单，全局暂停可随时切换。

## 六、已知范围限制

- **GitHub 相关未实现**：webhook 接入、PR 创建、Issue/PR 评论投递、验签、GitHub API 封装、IM 适配器、CI 状态源；事件源全部为本地模拟。
- **LLM 为本地模拟**：不调用真实大模型或网络，评估报告与决策由本地规则/脚本生成。
- **Web 看板为骨架**：手写简单 UTF-8 文本 HTML，仅演示分组展示与路由切换，无完整样式与前端交互。

## 七、道语言开发陷阱备忘

1. **禁止行尾 `//` 注释**：注释必须独占一行，写成行尾注释会触发解析错误（如「无法解析的表达式: '，'」）。
2. **不要用 `匹配` 语句做值分派**：实测 `匹配` 总命中第一个分支，一律改用 `如果 / 否则 如果 / 否则`。
3. **`否则 如果` 中间要有空格**：写成 `否则如果` 不可用，`否则 如果` 才通过。
4. **匿名函数必须单行**：写成 `函数(参数) => 表达式`，多行匿名函数会报「匿名函数需要 '=>'」。复杂逻辑放进具名函数，匿名函数只做一行调用。
5. **字符串模板插值只放简单变量**：`` `文本{变量}` `` 里放简单变量或属性访问最稳，复杂调用先算成中间变量再插值。
6. **`规则` 是保留关键字**：不要用作变量名。
7. **原子整数自增方法是 `加(增量)`**：不是文档里写的 `加并获取`。
8. **布尔与空值**：`真` / `假` / `空`；成员判断用 `x 在 列表`、`x 不在 列表`。
