# 更夫 Nightwatch 使用说明

## 一、项目定位

「更夫 Nightwatch」是用**本项目道语言**实现的一个**常驻研发协作 Agent** 演示。
它对应 PRD《常驻研发协作 Agent》的**非 GitHub 部分**：观察环境事件（本地模拟），做准入判定、语义评估、授权、调度与执行，并把过程沉淀到工单、报告、决策与审计流中。

本轮明确**不实现 GitHub 相关能力**（webhook 接入、PR 创建、Issue/PR 评论投递、webhook 验签、GitHub API 封装等），所有事件源以「本地模拟事件」替代。

## 二、如何运行

模块的导入路径**相对运行时 cwd 解析**，不支持 `./` 或 `../` 前缀。因此**当前工作目录必须切到 `示例/更夫`**：

```bash
cd /home/carson/code/test/道/示例/更夫
python3 /home/carson/code/test/道/源码/main.py 接入层/入口.道
```

也可以直接运行项目（推荐）——命令会读取项目根目录的 `道.配置`，自动定位「入口」并切换到项目根目录：

```bash
cd /home/carson/code/test/道/示例/更夫
python3 /home/carson/code/test/道/源码/main.py run
# 中文命令等价：python3 /home/carson/code/test/道/源码/main.py 运行
```

- 第一行 `cd` 不可省略：若在项目根目录直接运行，导入 `领域层.领域` 等会失败（`run` 命令会自动完成这一步）。
- 入口为 `接入层/入口.道`，由它组装各模块并跑端到端演示。
- 当前入口只渲染看板首页与审计页并输出长度日志摘要，不启动 HTTP 服务（避免演示阻塞）。
- 若要实际访问 Web 看板：创建服务器后调用看板的 `注册(服务器)`，再 `启动(端口)`；路由为 `GET /`（工单看板）、`GET /审计`（决策审计流）、`POST /暂停`（切换全局暂停）。示例：`从 网络 导入 创建服务器` → `定义 服务器 = 创建服务器()` → `看板对象.注册(服务器)` → `服务器.启动(8080)`。

## 三、模块清单与职责

共享契约位于 `领域层/领域.道`，定义工单、授权、触发、报告、执行绑定、决策、话题等类型与阶段/模式/准入常量，以及状态机函数。其余模块一律从此处导入，不另定义契约。

| 模块 | 职责 |
|---|---|
| `领域层/领域.道` | 领域模型与状态机：工单、授权、触发、报告、绑定、决策、话题；阶段推导与重开规则；全局共享契约（只读） |
| `基础设施层/存储.道` | SQLite 持久化与幂等：工单/触发/报告/决策/授权存取，Outbox 入队与投递标记，WAL，统计 |
| `应用层/恢复.道` | 崩溃恢复：结束所有未结束的绑定，为每个工单补投一条恢复说明 |
| `应用层/准入.道` | 准入矩阵与白名单：明确请求判显式，CI/普通评论判候选，机器人单列，噪音忽略 |
| `应用层/授权.道` | 不可变授权：建授权、范围校验、越权评论生成拒绝扩权决策（无 UPDATE 路径） |
| `应用层/评估.道` | 语义评估（Eval）：按规则与策略版本逐条评估触发，产出 would_accept / would_ignore 决策 |
| `应用层/调度.道` | Slot 调度与成本熔断：原子槽位占用/释放，调用数/token/日成本预算记账与超限判定 |
| `应用层/执行.道` | Worker 与六类报告：工单执行模拟、progress/waiting/ready/blocked/failed/dropped 报告序列、异步工具模拟 |
| `基础设施层/看板.道` | Web 看板骨架与审计流：按阶段分组展示工单、决策审计页、全局暂停路由 |
| `基础设施层/语言模型.道` | L1 大模型适配器：惰性可用性探测、语义判断 JSON 提取、对话生成与失败降级（业务层经此调用 LLM） |

## 四、演示的四类流程

1. **显式请求**：白名单用户明确请求 → 判定为 `explicit` 准入 → 建工单并绑定不可变授权 → 进入调度与执行，回调各类报告。
2. **observe 候选审计**：CI 变化或普通评论 → 判定为 `candidate` → Eval 语义评估产出决策（采纳或忽略）→ 记入决策与审计流，在审计页可逐条查看。
3. **评审跟进**：工单处于「等事件 / 待审核」阶段时，交付未交付输入或依据重开规则处理人工跟进消息，推动阶段流转，报告随步回调。
4. **中断恢复**：模拟崩溃后调用恢复检查点 → 结束所有未结束绑定 → 补投恢复说明；Watchdog 巡检展示异常工单，全局暂停可随时切换。
5. **工具驱动执行**（第三轮新增）：声明工具回调并注入执行器 → 模型通过 `tool_calls` 点名调用工具 → 结果回填后继续下一轮 → 记录工具调用日志；原有四类演示不变，详见第十章。

## 六、已知范围限制

- **GitHub 相关未实现**：webhook 接入、PR 创建、Issue/PR 评论投递、验签、GitHub API 封装、IM 适配器、CI 状态源；事件源全部为本地模拟。
- **LLM 为本地模拟**：不调用真实大模型或网络，评估报告与决策由本地规则/脚本生成。
- **Web 看板为骨架**：手写简单 UTF-8 文本 HTML，仅演示分组展示与路由切换，无完整样式与前端交互。

## 七、道语言开发陷阱备忘

1. **匿名函数必须单行**：写成 `函数(参数) => 表达式`，多行匿名函数会报「匿名函数需要 '=>'」。复杂逻辑放进具名函数，匿名函数只做一行调用。
2. **字符串模板插值只放简单变量**：`` `文本{变量}` `` 里放简单变量或属性访问最稳，复杂调用先算成中间变量再插值。
3. **`规则` 是保留关键字**：不要用作变量名。
4. **原子整数自增方法是 `加(增量)`**：不是文档里写的 `加并获取`。
5. **布尔与空值**：`真` / `假` / `空`；成员判断用 `x 在 列表`、`x 不在 列表`。

## 八、第二轮：LLM 接入（本地 ollama gemma4:e4b）

本章节为第二轮迭代新增，运行方式与环境要求**以本章节为准**；第六节「已知范围限制」中关于「LLM 为本地模拟」的描述适用于第一轮关键词规则版，第二轮已接入真实本地模型并保留自动降级。整体分层与数据流见《架构说明.md》。

### 8.1 运行命令

模块的导入路径相对**运行时 cwd** 解析，因此必须先切到演示目录（`cd` 不可省略），再运行入口：

```bash
cd 示例/更夫
python ../../源码/main.py 接入层/入口.道
```

若从项目根目录出发，上面的 `cd 示例/更夫` 即从根目录进入演示目录；`../../源码/main.py` 相对演示目录指向项目根的 `源码/main.py`。

### 8.2 前置条件：启动 ollama 并拉取模型

1. 安装 ollama 后启动服务：`ollama serve`（保持该终端运行）。
2. 拉取模型：`ollama pull gemma4:e4b`。
3. 验证模型就绪：`ollama list` 能看到 `gemma4:e4b`，或访问 `http://localhost:11434/api/tags` 有返回。

> 不启动 ollama 也能跑演示——会自动降级，详见 8.4。

### 8.3 环境变量

`OLLAMA_HOST` / `OLLAMA_MODEL` 由 L1 适配器 `基础设施层/语言模型.道` 读取，均带默认值，通常无需设置；`GENGFU_NO_LLM` 由 `接入层/入口.道` 读取，用于强制关闭 LLM：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OLLAMA_HOST` | `http://localhost:11434` | ollama 服务地址 |
| `OLLAMA_MODEL` | `gemma4:e4b` | 使用的模型名 |
| `GENGFU_NO_LLM` | 未设置 | 设为 `1` 时强制禁用 LLM，评估走关键词规则、Worker 走模板报告 |

自定义示例：

```bash
OLLAMA_HOST=http://127.0.0.1:11434 OLLAMA_MODEL=gemma4:e4b python ../../源码/main.py 接入层/入口.道
```

### 8.4 ollama 未启动时的降级行为

LLM 是增强项而非依赖，任何失败都静默降级，演示不中断：

- **探测**：适配器惰性调用 `列出模型()` 判断可用性，未启动或无模型则视为不可用，结果缓存避免反复探测。
- **评估**：LLM 不可用或语义判断失败（含 JSON 解析失败、结论非法）→ 自动退回关键词规则；理由前缀为「关键词规则：」，可用时为「LLM语义判断：」，审计页据此区分来源。
- **Worker**：LLM 不可用或 `.对话()` 失败 → 末报告退回模板文本，数据标记 `{"模型来源":"降级"}`。
- **强制降级开关**：设 `GENGFU_NO_LLM=1` 可强制禁用 LLM——入口把空的语言模型传给评估器与执行器，评估走关键词规则、Worker 走模板报告，全程**不发起任何模型请求**。适合本机未启动 ollama 时快速演示降级路径，例如：`GENGFU_NO_LLM=1 python ../../源码/main.py 接入层/入口.道`。
- **演示**：四类流程照常跑完；看板首页标注「LLM 模式：本地 ollama gemma4:e4b（不可用时自动降级为关键词规则）」。

### 8.5 与上一轮关键词版的区别

| 维度 | 第一轮（关键词版） | 第二轮（LLM 接入） |
| --- | --- | --- |
| 评估来源 | 仅关键词规则 | 优先 LLM 语义判断，失败降级关键词规则 |
| Worker 结论 | 模板文本 | 优先 LLM 生成一句中文结论，失败降级模板 |
| 成本记账 | 仅调用数/本地记账 | 模型 usage（生成 token）计入工单预算 |
| 审计可追溯 | 理由无来源标记 | 理由前缀区分「LLM语义判断：」/「关键词规则：」 |
| 看板首页 | 仅模式/暂停 | 增加 LLM 模式与降级说明 |

每个工单最多调用 1 次 LLM（不在步骤循环里逐条调用），成功的生成 token 通过 `预算.记账` 计入预算，沿用 FR-12 成本熔断。

全部通过时输出 `总计: 13, 通过: 13, 失败: 0` 且退出码为 0；任一用例失败时失败数会记入报告，并以退出码 1 结束，便于命令行与 CI 直接判定。断言失败不会中断后续用例。

## 十、第三轮：工具调用驱动执行

本章节为第三轮迭代新增。第二轮把 LLM 接入为「生成一句文本」，第三轮补全 `chat_with_tools` 协议，Worker 改用**工具调用**驱动执行步骤——工具即「能力」，模型在需要时点名调用，结果回填后继续，直到给出结论或达到轮次上限。整体分层与数据流见《架构说明.md》「工具驱动执行」。

### 10.1 运行方式

运行命令、导入路径要求与 §8.1 完全一致（`cd` 不可省略）：

```bash
cd 示例/更夫
python ../../源码/main.py run
# 或：python ../../源码/main.py 接入层/入口.道
```

环境变量 `OLLAMA_HOST` / `OLLAMA_MODEL` / `GENGFU_NO_LLM` 同 §8.3，默认值不变。独立的最小示例见 `示例/AI对话/工具调用示例.道`，运行方式：`cd 示例/AI对话 && python ../../源码/main.py 工具调用示例.道`。

### 10.2 新增的第五类演示：工具驱动执行

入口新增一类「工具驱动执行」演示，流程为：声明 2~3 个道语言工具回调（如「查工单状态」「生成报告」）→ 构造工具列表 → 注入执行器 → 模型通过工具调用逐步推进 → 记录工具调用日志（名称／参数／结果）。原有四类演示保持不变。

执行器 `执行工单` 在保持既有导出签名向后兼容的前提下，新增两个**可选**参数 `工具列表`、`工具回调`：两者非空且 `.支持工具()` 为真时，用工具对话结果作为末报告结论来源，成功时末报告数据附 `{"工具调用记录": [...], "模型来源": "ollama"}`，生成 token 计入工单预算；无工具或工具失败时退回原模板报告。

### 10.3 工具调用降级

仍沿用 §8.4 的原则——**LLM 是增强项而非依赖**：

| 场景 | 表现 |
|---|---|
| `GENGFU_NO_LLM=1` | 入口传空语言模型，工具调用全程不发起，Worker 走模板报告；适合无 ollama 时快速演示，例如 `GENGFU_NO_LLM=1 python ../../源码/main.py run` |
| 后端不支持工具调用 | `工具对话` 返回 `{"成功": 假, "错误": ...}`，末报告退回模板 |
| 模型调用失败 | 同上，已完成的工具调用记录随失败字典带回，便于排查 |
| 工具回调抛异常 | 转成「工具执行失败：...」结果文本回填，不中断演示 |
| 达到轮次上限（默认 5） | 返回失败字典并保留全部记录，防止死循环 |

### 10.4 测试

回归测试在 `测试/测试LLM接入.道` 中新增工具调用用例（用假语言模型对象／假回调模拟，不依赖真实 ollama），总数由 13 扩至 16 以上：

## 十一、可靠性验证（第四轮）

本章节为第四轮「可靠性工程」新增。混沌、压测、看板服务与守护的脚本均由本轮按《迭代规约-可靠性.md》交付；与第八～十章一样，**所有导入路径相对运行时 cwd 解析，必须先 `cd 示例/更夫`**。这些验证全部在**道语言层本地模拟**——不接 GitHub、不发真实 HTTP 对外投递、不做真实操作系统 `kill -9`，也**无需启动 ollama**（压测走关键词规则，不调 LLM）。逐条 DoD 状态与实测数据见《验收报告.md》。

### 11.1 混沌测试

```bash
cd 示例/更夫
python ../../源码/main.py 测试/测试混沌.道
```

- **预期输出**：打印测试报告，含用例总数 / 通过数 / 失败数（≥ 10 个用例）；全部通过时失败数为 0，**退出码为 0**；任一用例失败会以退出码 1 结束，便于 CI 判定。
- **覆盖场景**：重复投递幂等（同一触发连续入库 10 次只产生 1 条）、崩溃恢复（未结束绑定与未交付输入的 `恢复检查点()`）、断网降级（`OLLAMA_HOST` 指向不可达地址时 `.判断()` / `.对话()` 返回失败字典而不抛异常）、预算熔断（上限 2 的第 3 次记账返回假）、Outbox 幂等（同幂等键入队 2 次仅 1 条）、暂停后只入库不执行，以及噪音不建单、越权不扩权等自选用例。
- **口径提醒**：「崩溃恢复」是道语言层恢复逻辑验证，不是真实 OS 进程 `kill -9 ×10`；恢复率与 0 丢 0 重的真实环境结论仍需外部验证，见《验收报告.md》。

### 11.2 合成负载压测

```bash
cd 示例/更夫
python ../../源码/main.py 测试/压测.道
```

- **预期输出**：打印中文报告——5 轮（每轮 300 条消息：280 噪音 + 20 显式请求）的噪音误建单数、请求建单数、重复投递产生的 Trigger 数，以及处理耗时 **p50 / p95 / 最大值** 与「单会话基线」对照数字；失败数为 0、**退出码为 0**，报告必须含 p95 数字。
- **硬指标**：噪音误建单 = 0、20 条请求全部建单、同一请求重复投递 10 次仅 1 条 Trigger。
- **口径提醒**：p95 仅作观测指标写入报告（纯 CPU 串行模拟无真实并发收益），**不做硬断言**；PRD §12「p95 ≤ 单会话基线 60%」的真实环境验收仍缺项，不得据本轮模拟数据勾选。

### 11.3 独立看板服务

```bash
cd 示例/更夫
python ../../源码/main.py 看板服务.道
```

- **预期输出**：输出中文启动日志（监听地址与端口），随后保持 HTTP 服务运行。端口读环境变量 `更夫端口`，默认 **8765**（如 `更夫端口=8765 python ../../源码/main.py 看板服务.道`）。

### 12.2 Router 会话：会话保持、批处理、统一回复与全局记忆

`应用层/路由.道` 导出 `创建路由(会话集合=空, 语言模型=空)`，返回一个有状态路由对象。典型用法：

```text
从 领域层.领域 导入 信道飞书, 信道企微
从 应用层.路由 导入 创建路由

定义 路由 = 创建路由()
定义 会话对象 = 路由.开通会话("S-1", 信道飞书, "登录缺陷话题")   // 同一编号再次开通返回既有会话（幂等）

定义 响应 = 路由.收消息("S-1", "请修复登录崩溃", 信道飞书, "张三")
// 响应字典：{"成功": 真/假, "会话编号": ..., "回复": 文本, "工单编号": ..., "消息数": n}
// 文本含「请修复/请处理/崩溃/失败」等建单意图时生成本地工单记录并返回工单编号；
// 未命中时仅记录消息并给中文确认回复；不传语言模型或调用失败均静默降级。

定义 批量 = 路由.批处理(["请修复缺陷", "请处理超时", "闲聊"], "S-1", 信道飞书)  // 逐条收消息，等长响应列表
定义 汇总 = 路由.统一回复("S-1")          // 取该会话最近助手消息拼成中文文本；无会话返回中文提示
定义 记忆 = 路由.全局记忆("登录缺陷话题")  // 跨会话：同话题下所有会话的最近消息
定义 计数 = 路由.会话数()
```

要点：

- 同一会话编号重复开通**幂等**，不新增会话；每次追加消息刷新「最后活跃」。
- `收消息` 命中建单意图走本地工单记录（或调用 `执行工单`），不发起网络 IO；LLM 只是增强项。
- `全局记忆(话题键)` 是 FR-17 的跨会话记忆：多个会话共享同一话题键即可汇总。
- 所有状态在内存集合中，不做 fork / 线程；`接入层/入口.道` 新增「流程六」串起：飞书本地事件 → 归一化 → Router 收消息 → 建单/回复 → 链式召回 → 统一回复。

### 12.3 链式召回

`应用层/召回.道` 导出 `创建召回器(存储=空)` 与 `串联召回(片段列表, 最大跳数=3)`：

```text
从 领域层.领域 导入 召回片段
从 应用层.召回 导入 创建召回器, 串联召回

定义 召回器 = 创建召回器()
定义 工单片段 = 召回器.按工单("T-1")                // 来源类型 "工单"
定义 决策片段 = 召回器.按话题("Th-1")               // 来源类型 "决策"（按话题编号）
定义 关键词片段 = 召回器.按关键词(["崩溃", "登录"])  // 来源类型 "报告" 等

定义 片段列表 = [
    召回片段("工单", "T-1", "登录崩溃", 0.9),
    召回片段("决策", "D-1", "登录修复决策", 0.8)

定义 线索 = 串联召回(片段列表, 3)
// 以首片段为起点，按「来源编号相同 / 内容关键词重叠」逐跳扩出相关片段；
// 最多 3 跳，结果按相关度降序，已访问片段不重复。
```

要点：三类查询均返回 `召回片段` 列表；存储为空或参数校验失败时**返回空列表、不抛异常**（中文降级）。召回器只操作领域对象与存储取数函数，不导入 LLM / 网络标准库。

### 12.4 IM 第二信道：飞书 / 企微适配器

`基础设施层/即时通信.道` 导出 `创建飞书适配器(应用ID="", 应用密钥="", 本地模式=真)`、`创建企微适配器(企业ID="", 应用密钥="", 本地模式=真)` 与语法糖 `归一化事件(适配器, 事件字典)`：

```text

定义 飞书 = 创建飞书适配器("", "", 真)   // 本地模式为真（默认）
定义 可用 = 飞书.可用()                    // 本地模式恒为真

定义 事件 = {
    "header": {"event_id": "E-1"},
    "event": {
        "message": {"message_id": "M-1", "content": "请修复崩溃"},
        "sender": {"sender_id": {"open_id": "张三"}},

    }
}
定义 消息字典 = 归一化事件(飞书, 事件)  // 等价 飞书.解析消息(事件)

// 缺字段时返回 {"成功": 假, "错误": 中文提示}，不抛异常。

定义 触发对象 = 飞书.生成触发(事件)        // 仅当成功且 @机器人 时返回 触发 对象，否则 空
定义 回执 = 飞书.回复消息("Th-1", "已收到")  // 本地模式返回 {"成功": 真, "已回复": ..., "本地模拟": 真}
```

企微事件形如 `{"FromUserName": ..., "Content": ..., "ChatId": ...}`，同样用 `创建企微适配器` 解析，归一化字段与飞书一致（来源信道为 `"wecom"`）。两套适配器对缺字段都做容错。

**本地模拟口径**：

### 13.2 会话存储接口（L1）

`基础设施层/会话存储.道` 导出工厂 `创建会话存储(路径="更夫.db")`。传入 `/tmp` 路径可拿到独立 SQLite 库；建库失败时各方法自动降级，不抛异常。

```text
从 基础设施层.会话存储 导入 创建会话存储
从 领域层.领域 导入 会话, 消息, 信道飞书

定义 存储 = 创建会话存储("/tmp/gengfu-session.db")
定义 会话对象 = 会话("S-1", 信道飞书, "登录缺陷话题")
存储.保存会话(会话对象)            // 幂等 UPSERT：同一编号重复保存只留一条，返回真/假
定义 读回 = 存储.读取会话("S-1")    // 返回 会话 对象（含消息列表）；不存在返回 空
存储.保存消息("S-1", 消息("用户", "请修复崩溃", 信道飞书, ""))  // 追加一条并刷新最后活跃
定义 消息列表 = 存储.列出消息("S-1") // 按时间升序（同一时间按插入顺序）
定义 编号列表 = 存储.列出会话编号()   // 字符串列表，最近活跃在前
存储.删除会话("S-1")               // 级联删除该会话及其全部消息
定义 数量 = 存储.会话数()           // 整数
```

要点：所有 SQL 用 `?` 占位符绑定，无字符串拼接；`读取会话` 会重建内存消息列表，因此恢复后可直接在 Router 中续用。

### 13.3 Router 注入存储与会话恢复（L3）

`应用层/路由.道` 的 `创建路由(会话集合=空, 语言模型=空, 会话存储=空)` 新增可选 `会话存储` 与 `.恢复会话(编号)`：

```text

路由.开通会话("S-1", 信道飞书, "登录缺陷话题")   // 首次开通即 UPSERT 会话元数据
路由.收消息("S-1", "请修复崩溃", 信道飞书, "张三") // 用户消息 + 助手回复各落库 1 条，共 2 条

// 进程重启 / 新建 Router：从存储载回内存会话表，消息数与最近消息不变
定义 路由二 = 创建路由(会话存储=存储)
```

### 13.4 Webhook 接入与服务（L1 / L4）

`基础设施层/webhook接入.道` 导出 `创建Webhook接入(平台="feishu", 应用ID="", 应用密钥="", 本地模式=真, 回调=空)`；`平台` 取 `"feishu"` / `"wecom"`：

```text
从 基础设施层.日志 导入 日志器
```

| `更夫企微应用ID` | 企微接入的企业 ID | 空串；企微密钥为空时回退作 token |
| `更夫企微token` | 企微验签 token | 空串；为空时企微真实验签恒失败 |
| `GENGFU_NO_LLM=1` | 强制 LLM 降级 | 不连接 ollama，回复走「关键词规则」；会话落库 / webhook 验签不受影响 |

`GENGFU_NO_LLM=1` 下第六轮测试与演示均可跑通：Router 不注入语言模型即静默降级为关键词规则，IM/webhook 路径本就不依赖 ollama。

### 13.6 边界：本地可接入 ≠ 真实平台已验证

| 维度 | 本轮交付（本地可接入） | 真实平台验证（本轮未做） |
| --- | --- | --- |
| webhook 端点 | 两条 POST 路由 + 验签 + 归一化 + 回执可离线跑通 | 公网可达、飞书/企微后台回调配置、重试与幂等 |
| 验签 | HMAC-SHA256 / token 比对均按契约实现并有本地正反用例 | 真实密钥下发、时间戳防重放、加密事件解密 |
| 会话存储 | 单进程 SQLite 文件，重开同路径可恢复 | 多进程 / 分布式会话与并发写冲突治理 |
| 消息出口 | 回调载荷与本地回执字典，不发起网络请求 | 调用 IM 开放平台 API 投递并确认送达 |
| 建单出口 | 本地工单记录 / 执行工单 | GitHub Issue / PR 创建、评论投递与状态回写 |

**真实接入的必要条件**：把 `webhook服务.道` 中的 `定义 本地模式 = 真` 改为 `假`（或自行用 `创建Webhook接入(..., 本地模式=假, 回调=...)` 组装），并通过上表环境变量配置真实应用 ID / 应用密钥 / token；否则验签分支不会启用，且服务仍只监听本机、不发起外部请求。

因此第六轮测试全绿仅证明**本地模拟能力闭环**成立；PRD 中真实 IM / GitHub 闭环、观察期与进程守护项仍只加注记、不勾选。
