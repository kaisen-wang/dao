# 更夫 Nightwatch 使用说明

## 一、项目定位

「更夫 Nightwatch」是用**本项目道语言**实现的一个**常驻研发协作 Agent** 演示。
它对应 PRD《常驻研发协作 Agent》的**非 GitHub 部分**：观察环境事件（本地模拟），做准入判定、语义评估、授权、调度与执行，并把过程沉淀到工单、报告、决策与审计流中。

本轮明确**不实现 GitHub 相关能力**（webhook 接入、PR 创建、Issue/PR 评论投递、webhook 验签、GitHub API 封装等），所有事件源以「本地模拟事件」替代。

## 二、如何运行

模块的导入路径**相对运行时 cwd 解析**，不支持 `./` 或 `../` 前缀。因此**当前工作目录必须切到 `示例/更夫`**：

```bash
cd /home/carson/code/test/道/示例/更夫
python3 /home/carson/code/test/道/源码/main.py 接入层/入口.道
```

- 第一行 `cd` 不可省略：若在项目根目录直接运行，导入 `领域层.领域` 等会失败。
- 入口为 `接入层/入口.道`，由它组装各模块并跑端到端演示。
- 当前入口只渲染看板首页与审计页并打印长度摘要，不启动 HTTP 服务（避免演示阻塞）。
- 若要实际访问 Web 看板：创建服务器后调用看板的 `注册(服务器)`，再 `启动(端口)`；路由为 `GET /`（工单看板）、`GET /审计`（决策审计流）、`POST /暂停`（切换全局暂停）。示例：`从 网络 导入 创建服务器` → `定义 服务器 = 创建服务器()` → `看板对象.注册(服务器)` → `服务器.启动(8080)`。

## 三、模块清单与职责

共享契约位于 `领域层/领域.道`，定义工单、授权、触发、报告、执行绑定、决策、话题等类型与阶段/模式/准入常量，以及状态机函数。其余模块一律从此处导入，不另定义契约。

| 模块 | 职责 |
|---|---|
| `领域层/领域.道` | 领域模型与状态机：工单、授权、触发、报告、绑定、决策、话题；阶段推导与重开规则；全局共享契约（只读） |
| `基础设施层/存储.道` | SQLite 持久化与幂等：工单/触发/报告/决策/授权存取，Outbox 入队与投递标记，WAL，统计 |
| `应用层/恢复.道` | 崩溃恢复：结束所有未结束的绑定，为每个工单补投一条恢复说明 |
| `应用层/准入.道` | 准入矩阵与白名单：明确请求判显式，CI/普通评论判候选，机器人单列，噪音忽略 |
| `应用层/授权.道` | 不可变授权：建授权、范围校验、越权评论生成拒绝扩权决策（无 UPDATE 路径） |
| `应用层/评估.道` | 语义评估（Eval）：按规则与策略版本逐条评估触发，产出 would_accept / would_ignore 决策 |
| `应用层/调度.道` | Slot 调度与成本熔断：原子槽位占用/释放，调用数/token/日成本预算记账与超限判定 |
| `应用层/执行.道` | Worker 与六类报告：工单执行模拟、progress/waiting/ready/blocked/failed/dropped 报告序列、异步工具模拟 |
| `基础设施层/看板.道` | Web 看板骨架与审计流：按阶段分组展示工单、决策审计页、全局暂停路由 |
| `基础设施层/语言模型.道` | L1 大模型适配器：惰性可用性探测、语义判断 JSON 提取、对话生成与失败降级（业务层经此调用 LLM） |

## 四、演示的四类流程

1. **显式请求**：白名单用户明确请求 → 判定为 `explicit` 准入 → 建工单并绑定不可变授权 → 进入调度与执行，回调各类报告。
2. **observe 候选审计**：CI 变化或普通评论 → 判定为 `candidate` → Eval 语义评估产出决策（采纳或忽略）→ 记入决策与审计流，在审计页可逐条查看。
3. **评审跟进**：工单处于「等事件 / 待审核」阶段时，交付未交付输入或依据重开规则处理人工跟进消息，推动阶段流转，报告随步回调。
4. **中断恢复**：模拟崩溃后调用恢复检查点 → 结束所有未结束绑定 → 补投恢复说明；Watchdog 巡检展示异常工单，全局暂停可随时切换。

## 六、已知范围限制

- **GitHub 相关未实现**：webhook 接入、PR 创建、Issue/PR 评论投递、验签、GitHub API 封装、IM 适配器、CI 状态源；事件源全部为本地模拟。
- **LLM 为本地模拟**：不调用真实大模型或网络，评估报告与决策由本地规则/脚本生成。
- **Web 看板为骨架**：手写简单 UTF-8 文本 HTML，仅演示分组展示与路由切换，无完整样式与前端交互。

## 七、道语言开发陷阱备忘

1. **匿名函数必须单行**：写成 `函数(参数) => 表达式`，多行匿名函数会报「匿名函数需要 '=>'」。复杂逻辑放进具名函数，匿名函数只做一行调用。
2. **字符串模板插值只放简单变量**：`` `文本{变量}` `` 里放简单变量或属性访问最稳，复杂调用先算成中间变量再插值。
3. **`规则` 是保留关键字**：不要用作变量名。
4. **原子整数自增方法是 `加(增量)`**：不是文档里写的 `加并获取`。
5. **布尔与空值**：`真` / `假` / `空`；成员判断用 `x 在 列表`、`x 不在 列表`。

## 八、第二轮：LLM 接入（本地 ollama gemma4:e4b）

本章节为第二轮迭代新增，运行方式与环境要求**以本章节为准**；第六节「已知范围限制」中关于「LLM 为本地模拟」的描述适用于第一轮关键词规则版，第二轮已接入真实本地模型并保留自动降级。整体分层与数据流见《架构说明.md》。

### 8.1 运行命令

模块的导入路径相对**运行时 cwd** 解析，因此必须先切到演示目录（`cd` 不可省略），再运行入口：

```bash
cd 示例/更夫
python ../../源码/main.py 接入层/入口.道
```

若从项目根目录出发，上面的 `cd 示例/更夫` 即从根目录进入演示目录；`../../源码/main.py` 相对演示目录指向项目根的 `源码/main.py`。

### 8.2 前置条件：启动 ollama 并拉取模型

1. 安装 ollama 后启动服务：`ollama serve`（保持该终端运行）。
2. 拉取模型：`ollama pull gemma4:e4b`。
3. 验证模型就绪：`ollama list` 能看到 `gemma4:e4b`，或访问 `http://localhost:11434/api/tags` 有返回。

> 不启动 ollama 也能跑演示——会自动降级，详见 8.4。

### 8.3 环境变量

`OLLAMA_HOST` / `OLLAMA_MODEL` 由 L1 适配器 `基础设施层/语言模型.道` 读取，均带默认值，通常无需设置；`GENGFU_NO_LLM` 由 `接入层/入口.道` 读取，用于强制关闭 LLM：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OLLAMA_HOST` | `http://localhost:11434` | ollama 服务地址 |
| `OLLAMA_MODEL` | `gemma4:e4b` | 使用的模型名 |
| `GENGFU_NO_LLM` | 未设置 | 设为 `1` 时强制禁用 LLM，评估走关键词规则、Worker 走模板报告 |

自定义示例：

```bash
OLLAMA_HOST=http://127.0.0.1:11434 OLLAMA_MODEL=gemma4:e4b python ../../源码/main.py 接入层/入口.道
```

### 8.4 ollama 未启动时的降级行为

LLM 是增强项而非依赖，任何失败都静默降级，演示不中断：

- **探测**：适配器惰性调用 `列出模型()` 判断可用性，未启动或无模型则视为不可用，结果缓存避免反复探测。
- **评估**：LLM 不可用或语义判断失败（含 JSON 解析失败、结论非法）→ 自动退回关键词规则；理由前缀为「关键词规则：」，可用时为「LLM语义判断：」，审计页据此区分来源。
- **Worker**：LLM 不可用或 `.对话()` 失败 → 末报告退回模板文本，数据标记 `{"模型来源":"降级"}`。
- **强制降级开关**：设 `GENGFU_NO_LLM=1` 可强制禁用 LLM——入口把空的语言模型传给评估器与执行器，评估走关键词规则、Worker 走模板报告，全程**不发起任何模型请求**。适合本机未启动 ollama 时快速演示降级路径，例如：`GENGFU_NO_LLM=1 python ../../源码/main.py 接入层/入口.道`。
- **演示**：四类流程照常跑完；看板首页标注「LLM 模式：本地 ollama gemma4:e4b（不可用时自动降级为关键词规则）」。

### 8.5 与上一轮关键词版的区别

| 维度 | 第一轮（关键词版） | 第二轮（LLM 接入） |
| --- | --- | --- |
| 评估来源 | 仅关键词规则 | 优先 LLM 语义判断，失败降级关键词规则 |
| Worker 结论 | 模板文本 | 优先 LLM 生成一句中文结论，失败降级模板 |
| 成本记账 | 仅调用数/本地记账 | 模型 usage（生成 token）计入工单预算 |
| 审计可追溯 | 理由无来源标记 | 理由前缀区分「LLM语义判断：」/「关键词规则：」 |
| 看板首页 | 仅模式/暂停 | 增加 LLM 模式与降级说明 |

每个工单最多调用 1 次 LLM（不在步骤循环里逐条调用），成功的生成 token 通过 `预算.记账` 计入预算，沿用 FR-12 成本熔断。

## 九、运行测试

回归测试使用**道语言内置的「测试」标准库**编写，共 13 个用例，覆盖层级结构、领域契约、准入/授权/调度/评估/执行/存储/看板，以及降级路径端到端。测试脚本位于 `测试/测试LLM接入.道`：

```bash
cd 示例/更夫
python ../../源码/main.py 测试/测试LLM接入.道
```

全部通过时输出 `总计: 13, 通过: 13, 失败: 0` 且退出码为 0；任一用例失败时失败数会记入报告，并以退出码 1 结束，便于命令行与 CI 直接判定。断言失败不会中断后续用例。

`测试/测试LLM接入.py` 只是一个 pytest 薄壳入口，负责让既有 pytest / CI 调用上面的道语言脚本，不重复实现任何断言。单元测试风格为「导入被测模块 → 调用导出函数 → 用 `断言等于` / `断言为真` 等函数断言」，与 Python pytest 的写法完全解耦。
