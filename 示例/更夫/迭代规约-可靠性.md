# 更夫 Nightwatch — 第四轮迭代规约（可靠性工程与验收）

> 本文件是本轮并行开发的**共享契约**，所有子代理必须先读，严格按此实现。
> 前三轮产物：领域/持久化/恢复/准入/授权/评估/调度的关键词规则版 → 本地 LLM 接入 +
> 四层目录 → 工具调用协议层。本轮转攻**可靠性与可运维性**，对应 PRD §12（v1.0 DoD）
> 中「混沌测试」「合成负载测试」两项，以及文档 18 §18.9 第 3 项「Web 面板静态服务
> 与进程守护、压测/混沌脚手架」。
> 范围仍是**非 GitHub 部分**：不接 webhook、不发 PR、不做真实网络投递；所有故障
> 与负载均在道语言层本地模拟。

---

## 1. 目标与非目标

**目标**：
1. 混沌测试脚手架：模拟重复投递、进程崩溃后的悬挂绑定、断网降级、预算超额熔断，
   验证「恢复率 100%、外部消息 0 丢失 0 重复」；
2. 合成负载压测：300 消息（280 噪音 + 20 请求）×5 轮，验证「噪音误建单 = 0」，
   输出 p95 耗时与基线对照；
3. Web 面板运维增强：预算仪表页、审计 JSON 导出、独立看板服务入口与轻量守护；
4. 验收报告：PRD DoD 逐条状态 + 本轮实测数据。

**非目标**：GitHub 事件源、真实 HTTP 对外投递、真实 kill -9 操作系统进程、
改动 LLM 接口层或工具调用协议（第三轮已交付并验收）。

## 3. 已具备能力（直接用，不要重造）

- `从 基础设施层.存储 导入 打开存储, 保存触发, 列出触发, 列出工单, 保存工单, 投递入队, 待投递列表, 标记投递, 统计, 取连接`
  —— `保存触发(触)` 按去重键幂等：新事件返回真，重复返回假。
- `从 应用层.恢复 导入 恢复检查点()` → `{"结束绑定数", "补投数", "说明"}`。
- `从 应用层.准入 导入 创建准入器, 是噪音` → `准入器.判定(触)` 返回 `准入显式/准入候选/准入忽略/准入机器人`。
- `从 应用层.评估 导入 创建评估器, 串行评估` → 用关键词规则（语言模型为空）即可，不调 LLM。
- `从 应用层.调度 导入 创建调度器, 创建预算` → `预算.记账(单号, 调用数, token数)` 未超限真、超限假。
- `从 基础设施层.语言模型 导入 创建语言模型` → `.判断()`/`.对话()` 失败返回含「成功":假」的字典，不抛异常。
- `从 测试 导入 测试套件, 断言等于, 断言不等于, 断言为真, 断言为假, 断言包含, 测试报告`
  —— **函数式 API**（不是 DSL），套件方法 `record_pass/record_fail` 英文；末尾必须
  `如果 套件.failed > 0 退出(1)`，否则 CI 判不出失败。
- `从 系统 导入 取环境变量, 退出, 执行命令`；`从 网络 导入 创建服务器, 请求`；
  `从 编码 导入 JSON`；`从 时间 导入 时间戳`。
- 测试模块陷阱：`规则` 是关键字不能作变量名；断言被 `尝试/捕获` 吃掉后脚本仍正常退出，
  故末尾的 `退出(1)` 不可省。

## 4. 子代理 A — 混沌测试脚手架【`测试/测试混沌.道`】

用测试套件实现 ≥ 10 个用例，每个用例用 `尝试/捕获` 保护，失败记 `套件.record_fail(名称, 原因)`，
成功记 `套件.record_pass(名称)`。至少覆盖：

1. **重复投递幂等**：同一 `触发` 连续 `保存触发()` 10 次，断言仅第 1 次返回真、
   `列出触发()` 中该去重键只有 1 条；
2. **崩溃恢复**：构造含未结束绑定与未交付输入的工单并落库，调 `恢复检查点()`，
   断言结束绑定数 ≥ 1、补投数 ≥ 工单数、每个工单的绑定状态为 `ended`；
3. **断网降级**：把 `OLLAMA_HOST` 指向不可达地址（如 `http://127.0.0.1:1`），
   调语言模型 `.判断()` 与 `.对话()`，断言返回字典且「成功」为假，不抛异常；
4. **预算熔断**：`创建预算(单票调用上限=2)`，连续 `记账(单号)` 3 次，
   断言第 3 次返回假、用量字典调用数为 2；
5. **Outbox 幂等**：同一幂等键 `投递入队()` 两次，断言 `待投递列表()` 中只有 1 条；
6. **暂停后只入库不执行**：`状态字典["暂停中"]=真`，调 `处理暂停()` 切换并断言返回值；
7. 其余自选：噪音消息不建单、越权不扩权、重开规则拒绝 bot、阶段推导优先级等。

**自检**：`cd 示例/更夫 && python ../../源码/main.py 测试/测试混沌.道` → 退出码 0、失败 0。

## 5. 子代理 B — 合成负载压测【`测试/压测.道`】

1. 构造 300 条消息：280 条噪音（空内容、纯符号、已知噪音短语）+ 20 条显式请求，
   跑 5 轮（每轮重新构造）；
2. 每轮用 `创建准入器(["维护者"])` + `创建评估器(规则列表)`（**不传语言模型**，走关键词规则），
   逐条 `判定()` → 仅显式请求进入评估 → `评估()` → 统计建单数；
3. 硬指标断言：
   - 噪音误建单 = 0（280×5 条噪音中进入建单流程的数量）；
   - 20 条显式请求全部建单（每轮）；
   - 重复投递 10 次同一请求只产生 1 条 Trigger；
4. 性能观测：用 `时间戳()` 记录每条耗时，输出 5 轮汇总的 p50 / p95 / 最大值；
   同时记录「单会话基线」（逐条串行评估同一批数据的耗时）与「批处理」耗时作对照，
   **p95 只作观测指标写入报告，不做硬断言**（纯 CPU 模拟无真实并发收益）；
5. 输出中文报告（含上述数字），末尾 `如果 套件.failed > 0 退出(1)`。

**自检**：`cd 示例/更夫 && python ../../源码/main.py 测试/压测.道` → 退出码 0、失败 0、
报告含 p95 数字。

## 6. 子代理 C — Web 面板运维增强

**保持现有 `创建看板` / `处理暂停` / `.首页()` / `.审计页()` / `.注册()` 签名不变**，只增方法：

1. `看板.预算页() -> 文本 HTML`：从状态字典的「预算」子字典（键：单票调用/单票token/全局日上限）
   渲染成本仪表，含中文表格与当前用量；无「预算」键时显示「未提供预算数据」；
2. `看板.审计导出() -> 文本 JSON`：把 `取决策函数()` 的结果列表转成 JSON 文本，
   用 `JSON.编码()`；决策对象须先转中文键字典 `{触发编号,结论,理由,策略版本}`；
3. `.注册()` 增加路由 `GET /预算`、`GET /审计导出`；
4. **新建 `示例/更夫/看板服务.道`**：L4 入口——打开存储、组装状态字典与看板、
   `创建服务器()` → `看板.注册(服务器)` → `启动(端口)`；端口读环境变量 `更夫端口`，
   默认 8765；打印中文启动提示；
5. **新建 `示例/更夫/守护.道`**：轻量守护——用 `周期执行(毫秒, 回调)` 每 5 秒打印一次
   心跳（含时间戳与工单统计），捕获异常后继续运行；提供清晰的中文退出说明。
   不做真实进程重启（道语言无 fork 原语），文档中说明生产环境应配合 shell/systemd。

**自检**：临时脚本导入看板并调用 `.预算页()`/`.审计导出()`，断言 HTML 含「成本仪表」、
JSON 可 `JSON.解码()`；`python ../../源码/main.py 看板服务.道` 启动后能收到 HTTP 200
（可用 curl 或朝本地发一次请求后退出，不要留下常驻进程）。
