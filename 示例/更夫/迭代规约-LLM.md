## 1. 分层架构（依赖只能自上而下，禁止反向依赖）

```text
┌──────────────────────────────────────────────────────────────────┐
│ L4 接入层 / Interface                                            │
│   接入层/入口.道 —— 流程编排、四类演示、全局对象、组装与打印     │
├──────────────────────────────────────────────────────────────────┤
│ L3 应用层 / Application                                          │
│   应用层/评估.道  应用层/执行.道  应用层/恢复.道                 │
│   应用层/准入.道  应用层/授权.道  应用层/调度.道                 │
│   （业务规则与流程；可调用 L1 基础设施层与 L2 领域层）           │
├──────────────────────────────────────────────────────────────────┤
│ L2 领域层 / Domain                                               │
│   领域层/领域.道 —— 工单/触发/决策/报告/授权/话题/阶段推导       │
│   （纯数据结构与规则，**不得依赖任何外部模块或 LLM**）           │
├──────────────────────────────────────────────────────────────────┤
│ L1 基础设施层 / Infrastructure                                   │
│   基础设施层/存储.道（SQLite）   基础设施层/看板.道（HTTP 呈现） │
│   基础设施层/语言模型.道（LLM 适配器，新增）                     │
│   标准库：数据库 / 密码 / 调度 / 网络 / 编码 / 大模型            │
└──────────────────────────────────────────────────────────────────┘
```


**依赖规则**：
- L4 可调用 L3/L2/L1；L3 可调用 L2/L1；L2 只依赖自身；L1 各模块互不依赖（除标准库）。
- `领域层/领域.道` 是**只读共享契约**，本轮任何子代理都不得修改。
- LLM 只在 L3（评估、执行）通过 L1 的 `基础设施层/语言模型.道` 调用；业务层不得直接
  `从 大模型 导入`，更不得在领域层出现任何模型/HTTP 字样。

## 3. 已具备的标准库能力（直接使用，不要重新实现）

「大模型」模块（`从 大模型 导入 消息, 创建客户端, 对话, 列出模型`）：

```
定义 客户端 = 创建客户端("ollama", {"host":主机, "model":模型, "timeout":超时})
定义 应答 = 对话(客户端, [消息("user", 提示词)], {"温度": 0.1})
// 应答["成功"] 为真/假；真时 应答["内容"] 为文本，应答["用量"]["生成token"] 为整数
定义 模型表 = 列出模型(客户端)   // 成功为文本列表，失败为 {"成功":假,"错误":...}
```

- `创建客户端` 配置键用英文 `host` / `model` / `timeout`。
- 环境变量：`OLLAMA_HOST`（默认 `http://localhost:11434`）、`OLLAMA_MODEL`（默认 `gemma4:e4b`），用
  `从 系统 导入 取环境变量` 读取。
- 错误约定：`对话`/`列出模型` 失败返回 `{"成功": 假, "错误": ...}` 字典，不抛异常；
  `创建客户端` 失败抛中文运行时错误，需 `尝试/捕获`。
- JSON 解析：`从 编码 导入 JSON`，`JSON.解码(文本)`；解码失败会抛异常，须 `尝试/捕获`。
- 输出常带 Markdown 代码块（```json ... ```）或前后解释文字，提取 JSON 时要做容错清洗。

## 4. 基础设施层/语言模型.道【子代理 A】必须实现的接口

```
导出 函数 本地模型配置() -> 字典
    // 读环境变量 OLLAMA_HOST/OLLAMA_MODEL，返回 {"host":..., "model":..., "timeout":120}
导出 函数 创建语言模型(提供者="ollama", 配置=空) -> 语言模型对象
    // 配置为空时用 本地模型配置()；创建客户端失败要 尝试/捕获 并降级为"不可用"对象，不能让程序崩

语言模型对象 方法：
  .可用() -> 逻辑
      // 惰性探测：调 列出模型() 成功且列表非空为真；失败为假。探测结果缓存，避免每次都探测。
  .对话(提示词, 系统提示="") -> 字典
      // 返回 {"成功":真/假, "内容":文本, "错误":文本, "用量":字典}
      // 失败不抛异常；系统提示非空时放一条 system 消息在前
  .判断(提示词, 系统提示="") -> 字典
      // 调 .对话()，从内容里提取 JSON，返回
      // {"成功":真/假, "结论":"would_accept"|"would_ignore"|空, "理由":文本, "用量":字典, "错误":文本}
      // 只接受结论值恰为 would_accept / would_ignore；其它一律视为失败（成功=假）
      // JSON 提取容错：先试整体解码，失败则截取首个 "{" 到最后一个 "}" 再解码；仍失败则 成功=假
```

**约束**：模块级只做定义，不在导入时发起任何网络请求；所有中文 docstring/注释；
不修改其它文件；自检时临时建 `_测_语言模型.道`，跑通后删除。

## 5. 应用层/评估.道【子代理 B】改造要求

保持现有导出名与调用方式**向后兼容**，只增加可选参数：

```
导出 函数 创建评估器(规则列表, 策略版本="v0.1", 语言模型=空) -> 评估器对象
导出 函数 串行评估(评估器, 触发列表, 模式) -> 决策列表      // 不变
```

`评估器.评估(触, 模式)` 行为：
1. 模式为 `模式关闭` → 仍返回 `would_ignore`（原逻辑不变）。
2. 语言模型非空 且 `.可用()` 为真 → 构造中文提示词请模型判断该触发是否值得接受：
   - 提示词须包含触发的 `内容`、`来源`、`发起人`，并要求只输出 JSON：
     `{"结论":"would_accept或would_ignore","理由":"中文简由"}`
   - 调 `.判断()`；成功且结论合法 → 返回 `决策(编号, 结论, 理由, 策略版本)`，
     **理由文本前缀必须是「LLM语义判断：」**，便于看板与审计区分来源。
   - 失败 → 降级到关键词规则（第 3 步）。
3. 关键词规则（现有逻辑，原样保留）→ 理由文本前缀必须是「关键词规则：」。
4. 未命中 → `would_ignore`，理由前缀同样按来源标注。

**约束**：不得修改 `领域.道`；不得自己 `从 大模型 导入`；LLM 调用失败必须静默降级，
不能让演示中断；自检覆盖「LLM 可用」「LLM 不可用降级」两条路径（可用路径可用假语言模型对象模拟）。

## 6. 应用层/执行.道【子代理 C】改造要求

保持现有导出名与调用方式**向后兼容**，只增加可选参数：

```
导出 函数 执行工单(单, 调度器, 预算, 报告回调, 步骤列表=空, 语言模型=空) -> 报告对象
导出 函数 生成报告序列(工单编号) -> 报告列表   // 不变
导出 函数 运行异步工具(命令名, 秒数, 完成回调)  // 不变
```

`执行工单` 行为：
1. 槽位占用、未交付输入取走、预算记账、释放槽位、受阻分支——**全部保持原逻辑不变**。
2. 新增：步骤循环结束后、生成末报告前，若语言模型非空且 `.可用()`，调 `.对话()`
   一次，请它依据工单标题与步骤生成一句中文执行结论（提示词要求 60 字以内、只输出结论文本）。
   - 成功 → 末报告消息用模型返回的结论文本（可拼接工单编号前缀），数据里加
     `{"模型来源":"ollama", "生成token": n}`。
   - 失败 → 末报告消息退回现有模板文本，数据里加 `{"模型来源":"降级"}`。
3. **usage 记账**：模型调用成功时，把生成 token 计入预算：
   `预算.记账(单.编号, 0, 生成token数)`（调用数前面已记过 1，这里只加 token，不要重复加调用数）。
4. 每个工单最多调 1 次 LLM，不要在步骤循环里逐条调用（避免演示过慢）。

**约束**：不得修改 `领域.道`；不得自己 `从 大模型 导入`；LLM 失败必须降级；
自检覆盖「LLM 可用」「LLM 不可用」两条路径。
