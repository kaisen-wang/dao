# 第七轮迭代共享契约：GitHub 事件源与验收补齐（v1.1 / M4 延伸）

> 前六轮始终按 PRD §3「非 GitHub」范围推进，GitHub 事件源（§13 开放问题 #1 的默认首源）完全空白；
> 同时第六轮注记明确 `webhook服务` 未桥接 Router、无重放防护。本轮补这两处，并推进 PRD §12 第 5、6 项 DoD 的本地可验证部分。
> 沿用「四子代理并行 + 主代理独占契约/领域层/入口/文档/最终验收」分工。

## 0. 范围与诚实边界

- **本轮做**：GitHub webhook 事件适配器（Issue / PR / 评论归一化 + 验签 + 触发生成 + merged 信号）；webhook 服务桥接 L3 Router 并加重放防护；observe 一周审计的本地压缩模拟（含误接受/误忽略计数）；PRD §10 安全清单的本地可验证项与对照说明。
- **本轮不做**：接真实 GitHub webhook、使用真实 token、创建真实 PR / 评论、合并分支、开启 `auto` 模式、真实一周运行、真实 OS 进程守护。
- **诚实口径**：本地模拟通过 ≠ 真实闭环；§12 六项 DoD 本轮仍全部不勾选，只在验收报告里写明「本地已验证 / 需真实环境」的区分。
- **LLM 增强项**：全部测试与演示用 `GENGFU_NO_LLM=1` 可跑，不依赖 ollama。

## 1. 分层与依赖方向

```
L4 入口.道 / webhook服务.道 ──► L3 应用层/{路由,召回,观察审计}.道 ──► L2 领域层/领域.道
                                        ▲
L1 基础设施层/{GitHub事件,webhook接入,即时通信,会话存储,存储}.道 ──┘
```

L1 可依赖 L2 类型/常量，不得依赖 L3/L4；L2 禁止出现 `LLM` / `HTTP` / `网络.请求` 等禁用词（含否定句注释）——历史踩坑：注释里写「不依赖 HTTP」也会命中禁用词。

## 2. 接口契约（跨代理严格遵守，按此并行开发）

### A `基础设施层/GitHub事件.道`（新建）

仿照 `即时通信.道` 的适配器风格：

```text
导出 函数 创建GitHub适配器(仓库="", 令牌="", 本地模式=真)
  .可用()                         # 本地模式恒真；非本地模式需仓库+令牌
  .验证签名(请求对象, 签名密钥="")  # X-Hub-Signature-256: HMACSHA256(密钥, body)
  .解析事件(事件字典)              # 归一化为统一事件字典（中文键）
  .生成触发(事件字典)              # 触发(来源=github, 外部编号, 话题编号, 发起人, 内容, 是否机器人, 是否CI)
  .回复消息(话题键, 文本)          # 只返回待投递载荷，不发真实请求

导出 函数 验签GitHub请求(请求对象, 签名密钥)   # 供 B 复用
```

支持事件：`issues.opened` / `issues.edited`、`pull_request.opened` / `synchronize` / `closed`、`issue_comment.created`。
PR `closed` 且 `merged=true` 时，归一化字典须含 `["已合并"] = 真`，供 L4 编排 `工单 ended(merged)` 信号（只生成信号，不做真实 merge）。
所有缺字段降级，不抛未捕获异常；中文键与 `即时通信.道` 保持一致（成功/来源信道/消息ID/文本/发送人/话题键/是否@机器人）。

### B `基础设施层/webhook接入.道` + `webhook服务.道`（修改，向后兼容）

```text
创建Webhook接入(平台, 应用ID, 应用密钥, 本地模式, 回调)   # 既有签名不变
  # 新增：.验证签名() 成功时记录签名键（时间戳+nonce）到最近 N 条去重表
  # 新增：.是重放(请求对象) -> 布尔；重复签名键返回 真
webhook服务.道：
  # 用回调把成功解析的事件送入 L3：若事件["是否@机器人"]为真，
  # 则 路由.收消息(会话编号, 事件["文本"], 事件["来源信道"], 事件["发送人"])
  # 会话编号由 话题键 派生；会话存储可选注入
  # 重放请求直接返回 {"状态码": 409, "内容": "重复事件"}
```

不传路由时保持第六轮行为；本地模式仍默认放行验签，但**重放防护在本地模式也生效**（用请求体哈希+nonce）。

### C `应用层/观察审计.道` + `测试/测试观察审计.道`（新建）

```text
导出 函数 创建观察审计()
  .记录事件(事件字典, 准入结论, 实际是否应接受)   # 结论/实际均为布尔
  .生成报告()               # 中文报告字典：总数/正确接受/误接受/正确忽略/误忽略/误接受率/误忽略率
  .误接受率() / .误忽略率()
  .导出JSON()               # 字符串，字段中文
```

用内存列表累计，不依赖数据库；`误接受率 = 误接受 / (正确忽略 + 误接受)`，`误忽略率 = 误忽略 / (正确接受 + 误忽略)`，分母为 0 时返回 0.0。
测试脚本：构造压缩的一周模拟事件流（如 7 天 × 若干条），断言计数与比率；写清**压缩模拟 ≠ 真实一周运行**。

### D `测试/测试安全清单.道` + `安全说明.md`（新建）

逐条对照 PRD §10 五条：
1. 独立账号 / 分支保护 / 无 merge 权限：本地验证「Worker 执行器只产出 PR 载荷、不调用 merge」；真实环境项标注需配置。
2. 凭据不进模型上下文 / 日志脱敏：本地验证传给语言模型的 prompt 不含密钥；日志脱敏函数覆盖令牌/密钥字段。
3. 外部事件标记「数据非指令」/ 高危操作人工确认：本地验证 prompt 模板含标记、merge 类操作需人工确认开关。
4. 白名单仅 AI 本人 / auto 前置 observe ≥2 周且误接受率 ≤5%：本地验证准入器白名单与门禁函数；真实运行项标注未开展。
5. 原型级风险告知：文档写明代码出境到模型 API 的风险。
不可真实验证的项必须在 `安全说明.md` 与测试输出中显式标注「需真实环境」，不得写成已通过。
