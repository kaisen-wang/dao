# 第十二轮迭代共享契约：Outbox HTTP 投递闭环、Watchdog 真实定时巡检与同口径 p95 判定（v1.1 / M4 延伸）

> 前十一轮已覆盖事件源、Router、持久化、Webhook、GitHub、observe/安全、真实 kill -9 / 并发 / 本地 git、生产守护与轮询兜底、断网 ×10 / observe 落盘 / 守护重启、真跨进程 observe / Watchdog 时间化 / 真 `.道` 规则链子进程。
> 第十一轮验收注记（PRD §12 / 文档 18 §18.19.3 / 验收报告 §12.3）留下三项**诚实缺口**：
> ① Outbox 只有入队/标记，没有真正把消息 POST 到 HTTP sink 的投递执行器，「外部消息 0 丢失 0 重复」仍是本地 SQLite 行数口径（FR-11/FR-15）；
> ② 第十一轮 Watchdog 用注入 `perf_counter` 历史时间戳模拟停滞，`.巡检()` 未在长驻入口真实周期调度里调用（FR-16「30 分钟内被发现」真实定时发现仍缺）；
> ③ 第八/十一轮 p95 口径缺陷未解：p95 为单条耗时、基线为整轮合计，无法直接相除，「p95 ≤ 基线 60%」始终只观测不判定（§12 第 2 项）。
> 本轮把三项推进到「本机真实 HTTP 回环 / 真实周期调度 / 同口径可比」程度。沿用「子代理并行 + 主代理独占契约/入口演示/文档/最终验收」分工。

## 0. 范围与诚实边界

- **本轮做**：① 真 HTTP 回环 sink + Outbox 投递执行器（断网→补发，按幂等键验证外部消息 0 丢失 0 重复）；② 在长驻入口注册真实周期调度调用 Watchdog `.巡检()`，把 nudge/告警落库为决策，用真实子进程验证「周期触发 + 停滞被发现」；③ 用同一负载、同一计时口径对照单会话逐条 vs 批处理，真正判定 p95 比值是否 ≤60%。
- **本轮不做**：接真实 GitHub / 飞书 / 企微 / 真实 ollama、发真实外部网络请求（HTTP 均为本机回环）、真实云主机 systemd、真实 ≥1 周 observe、开启 auto 模式、改 L2 `领域.道` 与 L1 `存储.道` 既有 API 语义。
- **诚实口径**：HTTP sink 是本机 `DaoHttpServer` 回环，≠ 真实平台 webhook；Watchdog 定时用真实 `周期执行`，但停滞分钟仍靠注入 `perf_counter` 回拨（不是真等 30 分钟），且周期毫秒在测试里缩短到加速验证；p95 同口径比值即使达成也仅代表本机真子进程，≠ 生产真实流量。**PRD §12 六项 DoD 全部继续保持未勾选**，只在注记写「本地可验证部分已实现」。
- **关键陷阱（务必读）**：内置 `时间戳()` 返回 `time.perf_counter()`（单调钟、进程各自起点），**不可跨进程比较绝对值**，只可用于同进程内差值计算。任何「注入历史时间戳」必须在同一进程内完成注入与判定；跨进程场景禁止传递 `时间戳()` 原始值做差值。
- **测试约定（Python 层，跨平台硬约束）**：一律 `sys.executable` 启子进程；禁 `signal.SIGKILL`；停止用 `proc.terminate()` fallback `proc.kill()`；`tempfile.TemporaryDirectory()` 清理；禁硬编码 `.venv/bin/python`；`.道` 子进程 cwd 必须是 `示例/更夫`。端口用 0 自动分配、服务器 `关闭()` + `join()` 回收，避免端口泄漏。
- **本机**：Linux x86-64 / Python 3.13.12；第十一轮末全量基线 `1673 passed / 2 skipped / 1 xpassed`。`.道` 实跑：`cd 示例/更夫 && GENGFU_NO_LLM=1 python ../../源码/main.py <脚本>`。

## 2. 接口契约（跨代理严格遵守，按此并行开发）

### A `outbox-http`：`基础设施层/投递执行器.道`（新建）+ `测试/测试投递闭环.道`（新建）+ `源码/tests/test_outbox_http_delivery.py`（新建）

保持 L1 `存储.道` 既有 API 不变（只调用，不修改）。

```text
从 网络 导入 请求
从 编码 导入 JSON
从 基础设施层.存储 导入 待投递列表, 标记投递, 投递入队

导出 函数 创建投递器(接收URL, 请求超时=2)
  # 返回 投递器对象，字段：接收URL/请求超时/最近投递明细=[]/累计成功=0/累计失败=0

类型 投递器
    函数 刷新()
      # 遍历 待投递列表()：对每条用 请求(接收URL, {"方法":"POST","数据":JSON.编码({"幂等键":...,"工单编号":...,"类型":...,"内容":...}),"请求头":{"Content-Type":"application/json"},"超时":请求超时})
      # 状态码 2xx → 标记投递(id) + 累计成功+1；否则累计失败+1、保留 pending。
      # 请求异常（含连接拒绝）捕获为失败，不抛异常；明细项 {"幂等键","状态码","结果"}。
      # 返回 {"成功":N,"失败":N,"剩余待投递":M,"明细":列表,"说明":中文边界说明}
    函数 投递统计()
      # 返回 {"累计成功","累计失败","最近明细数"}
```

- `测试/测试投递闭环.道`：同进程内用本地 sink 钩子（注入一个假的 `请求函数`，签名与 `网络.请求` 一致，返回带 `.状态码` 的对象）验证：投递成功标记、断网（假请求抛异常）保留 pending、恢复后补发、幂等键重复只标一次、失败明细中文。≥8 用例，`从 系统 导入 退出`。
- `源码/tests/test_outbox_http_delivery.py`：**真 HTTP 回环**——用 `from dao.stdlib.network import DaoHttpServer`（或 `从 网络 创建服务器`）在 Python 主线程起 sink，路由 `POST /outbox` 按 `幂等键` 去重计数并返回 200；用 `sys.executable` 启动 `.道` 工作负载（cwd=`示例/更夫`，ASCII 环境变量传端口与库路径）调用 `创建投递器(...).刷新()`：
  - 场景 1：先入队 3 条（含 1 条重复幂等键），sink 在线 → 刷新后 sink 收到唯一键数 2、待投递清零、标记成功；
  - 场景 2（断网补发）：sink 未启动时入队并刷新（失败、保留 pending）→ 启动 sink 再刷新 → sink 收到、待投递清零；
  - 断言「外部消息丢失 0、重复 0」按 sink 记录的唯一幂等键口径，并注释写清「本机回环 sink ≠ 真实 GitHub，不勾选 DoD」。
  - ≥4 用例；单用例 ≤10 秒；中文断言消息。
- 不得修改 `基础设施层/存储.道`、任何既有测试或文档。

### B `watchdog-timer`：`应用层/调度巡检.道`（新建）+ `测试/测试周期巡检.道`（新建）

第十一轮 `应用层/巡检.道` 保持不动（只读导入）。

```text
从 调度 导入 周期执行, 取消调度
从 基础设施层.存储 导入 保存决策
从 应用层.巡检 导入 创建看门狗, 工单   // 若 工单 未从巡检导出，改从 领域层.领域 导入

导出 函数 创建周期巡检(看门狗对象, 周期毫秒=50, 当前时间=空)
  # 返回 巡检调度器对象：
  #   .启动() → 用 周期执行(周期毫秒, 回调) 注册，返回调度ID；回调内：
  #       构造 2 个停滞工单（注入 31/61 分钟，用同一 perf_counter 基准）；
  #       调用 看门狗对象.巡检([...], 空, 当前时间) 得到 nudge/告警数；
  #       对每条明细用 看门狗对象.生成nudge决策/生成告警决策 产出 L2 决策并 保存决策()；
  #       累计 .巡检轮次、.累计nudge、.累计告警。
  #   .停止() → 取消调度(调度ID)，返回是否取消成功。
  #   .状态() → {"巡检轮次","累计nudge","累计告警","运行中"}
  # 注意：perf_counter 注入与 当前时间 必须同一进程同基准，禁止跨进程传时间戳。
```

- `测试/测试周期巡检.道`：`从 系统 导入 退出`；同进程内固定 `基准时间 = 时间戳()`，创建 `创建看门狗(30,60)`、`创建周期巡检(狗, 50, 基准时间)`，`.启动()` 后 `睡眠(0.4)` 再 `.停止()`，断言：`.巡检轮次 >= 3`、`累计nudge >= 1`、`累计告警 >= 1`、`保存决策` 后 `列出决策()` 中 nudge/alert 各 ≥1、`.停止()` 后轮次不再增长。≥7 用例；注释写清「真实周期调度器驱动 + 注入时间戳加速，非真等 30 分钟；不勾选 DoD」。
- 另加一个 `源码/tests/test_watchdog_periodic.py`：用 `sys.executable` 真子进程跑上述 `.道` 测试，断言退出码 0 且 stdout 含中文统计（证明周期调度在真实 OS 进程里跑通，非同进程 mock）。≥2 用例。
- 不得修改 `应用层/巡检.道`、`领域层/领域.道`、`接入层/常驻入口.道`、任何既有测试。

### C `p95-metric`：`源码/tests/test_p95_same_metric.py`（新建）

不得修改 `test_load_real_concurrency.py`、`test_rule_engine_real_process.py`（保留两种既有口径作对照）。

- 用 `sys.executable` 启真 `.道` 子进程（cwd=`示例/更夫`，`GENGFU_NO_LLM=1`），工作负载在临时目录生成，逐条调用真 `.道` `判定()`/`评估()`。
- **同口径对照**：两种模式处理**完全相同的 300 条消息**（280 噪音 + 20 显式）：
  - **单会话基线模式**：单进程内逐条串行处理 300 条，逐条记录单条耗时（毫秒列表）；
  - **批处理模式**：把 300 条切成 4 批，用 4 个真子进程并发处理，每条仍记录单条耗时（毫秒列表，跨子进程汇总到 JSON）。
- 两种模式都从**逐条耗时列表**计算 p50/p95/max（同一口径，可直接相除），并额外记录端到端墙钟；断言 `p95批处理 / p95基线 <= 0.60`。
- 硬指标同时成立：噪音误建单 0、显式建单 20/20；若 p95 比值未达 0.60，用 `pytest.xfail(strict=False)` 如实记录，**不伪造数据、不改口径硬凑**。
- ≥4 用例；单用例 ≤10 秒；注释写清「同口径逐条耗时可比，弥补第八/十一轮 p95 与整轮基线不可除的缺陷；本机真子进程 ≠ 生产真实流量，即使达成也不勾选 DoD」。
