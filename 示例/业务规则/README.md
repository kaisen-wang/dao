# 业务规则 DSL 示例（纯道语言实现）

用「`@` 注解 + 逻辑知识库」在**道语言层**实现声明式规则注册与判定，不修改解释器核心。定位是展示多范式融合能力，而非生产级规则引擎。

## 文件

| 文件 | 作用 |
|------|------|
| `规则引擎.道` | DSL 库本体：注册、排序、判定、清空 |
| `风控演示.道` | 4 个注解处理器 + 逻辑知识库 + 动态事实的三类场景演示 |

## 运行方法

模块搜索基于当前工作目录，请从本目录启动：

```bash
cd 示例/业务规则
python ../../源码/main.py 风控演示.道            # 解释器模式（默认）
python ../../源码/main.py --mode vm 风控演示.道  # VM 模式，输出一致
```

也可从 `源码/` 目录运行，但需把本目录加入模块搜索路径；推荐上面的方式。

测试：

```bash
cd 源码
./.venv/bin/python -m pytest tests/test_examples_rules_dsl.py -q
```

## DSL 语法

### 1. 注册（注解函数）

```dao
从 规则引擎 导入 标注规则, 判定, 全部判定, 规则表, 清空规则

@标注规则(名称="拦截", 优先级=100, 条件="高风险")
函数 拦截(对象)
    返回 "拦截:" + 对象
```

- `标注规则(处理器, 名称, 优先级, 条件)` 的第一个参数是解释器传入的被装饰函数；
  注解参数（`名称` / `优先级` / `条件`）**必须在注解函数内部捕获进规则表**——
  道语言读不到 `__注解__`。注解函数必须 `返回 处理器`，否则被装饰函数丢失。
- 优先级数值大者先执行；`规则表` 是共享列表，元素为
  `{"名称", "优先级", "条件", "处理器"}` 字典。
- 注解在声明时求值，故 `标注规则` 必须先定义（导入需写在注解之前）。
- `规则` 是上下文关键字，注解函数不要命名为 `规则`，用 `标注规则`。

### 2. 事实与判定

业务侧用**正谓词** `风险(对象, 标签)` 表达命中，知识库由调用方创建：

```dao
逻辑 风控库
    事实: 风险("甲", "高风险")
    规则: 命中(?人, ?标签) 如果 风险(?人, ?标签)

添加事实(风控库, "风险", "乙", "低风险")   // 运行时动态注入

定义 r = 判定("乙", 风控库)
定义 rs = 全部判定("甲", 风控库)            // 全部命中，按优先级降序
清空规则()                                  // 测试隔离用
```

`判定` 返回 `{"命中": 布尔, "规则名": 文本, "优先级": 数值, "结果": 处理器返回值}`；
无命中返回 `{"命中": 假, "规则名": "", "优先级": 0, "结果": 无}`（`无` 是 `空` 的别名，即 `None`）。
`全部判定` 返回同结构字典的列表。

## 能力边界（重要）

1. **规则体内只有正谓词调用有效**：`非`、`剪枝`、比较式（如 `?分数 >= 90`）会被
   静默忽略，不会报错也不会生效。阈值类条件必须先在道语言侧算成标签事实，例如
   `如果 分数 >= 90: 添加事实(kb, "风险", 人, "高分")`，再用 `条件="高分"` 登记。
2. **注解附着到 `逻辑` 块不受支持**：知识库只能由普通函数/变量标注或手工构造。
3. 查询结果字典的键带 `?` 前缀，取值用 `解["?标签"]`，不能用属性访问。
4. 不要依赖 `并且` / `或者` 的短路行为；需要分支时用嵌套 `如果` 或提前返回。
5. `清空规则()` 就地弹出元素，已导入的 `规则表` 引用同步可见。
6. 示例不依赖外网、ollama 或绝对路径。
