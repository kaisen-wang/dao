# 结构化日志示例

本目录演示道语言标准库 `日志` 的结构化日志能力，设计参考 OpenTelemetry Logs Data Model：每条日志是一个事件（LogRecord），以单行 JSON 输出，便于下游日志平台检索与聚合。

## 示例清单

| 文件 | 演示内容 |
|------|----------|
| `快速开始.道` | 配置结构化日志、按级别记录带属性的事件、查看 JSON 记录 |
| `追踪关联.道` | W3C traceparent 在上下游传播，日志自动携带 TraceId / SpanId |
| `脱敏与采样.道` | 属性注入 → PII 脱敏 → 采样 的处理器链 |
| `尾部采样.道` | 按 TraceId 聚合，保留含错误的整条链路 |

## 运行方式

在仓库根目录执行（注意：日志默认输出到标准错误流，示例用 `输出="内存"` 后由 `打印` 输出结果，便于观察）：

```bash
cd 源码
python main.py ../示例/结构化日志/快速开始.道
python main.py ../示例/结构化日志/追踪关联.道
python main.py ../示例/结构化日志/脱敏与采样.道
python main.py ../示例/结构化日志/尾部采样.道
```

如需观察文件输出，把 `输出="内存"` 改为 `输出="文件", 路径="应用.日志"`，再用 `cat 应用.日志` 查看 JSON Lines。

## 要点

- **结构化 vs 文本**：文本日志面向人读（`级别 时间 位置 | 描述`）；结构化日志面向机器处理，字段固定、可建索引。
- **属性扁平化**：属性键用点分隔（如 `user.id`、`order.id`），不要把动态值拼进消息正文。
- **追踪关联**：请求入口 `创建追踪`、出口 `取追踪头`、下游 `载入追踪头`，让同一条请求链上的日志共享 TraceId。
- **生命周期**：程序退出前调用 `刷新()` 与 `关闭()`，确保缓冲区记录写出、文件句柄释放。
- **对接 Collector**：用 `创建OTLP导出器("http://localhost:4318/v1/logs")` 并通过
  `配置结构化日志(导出器=导出器)` 交给日志器，即可输出 OTLP/HTTP JSON；需要本地
  OpenTelemetry Collector 监听对应端口（示例见 API 手册「OTLP 导出与 Collector 对接」）。
- **集中配置**：服务名、环境等资源属性可由 `OTEL_SERVICE_NAME`、
  `OTEL_RESOURCE_ATTRIBUTES`、`DEPLOY_ENV` 等环境变量注入，用 `从环境加载资源()` 激活。
