# 道语言 × 本机 Ollama 对话示例

用道语言标准库直接调用**本机** ollama 的 HTTP API，与 `gemma4:e4b` 对话。不需要任何第三方 Python 包，只用到 `网络`、`编码`、`系统`、`文本` 四个标准库模块。

## 目录

| 文件 | 说明 |
| --- | --- |
| `单次问答.道` | 最小示例：发一条消息、打印回答（建议先跑这个验证环境） |
| `对话.道` | 主示例：多轮交互对话，带命令、思考过程开关、统计与容错（非流式） |
| `流式对话.道` | 打字机式流式输出：`stream: 真` + 逐行 NDJSON 回调 |
| `模型列表.道` | GET `/api/tags` 列出本机已安装模型，检查 `gemma4:e4b` 是否就绪 |

## 前置条件

1. 本机已安装 ollama 并启动服务（默认监听 `127.0.0.1:11434`）：

```bash
ollama serve
```

2. 拉取模型（本机实测：7.5B / Q4_K_M / 131072 上下文 / 约 6.1 GB）：

```bash
ollama pull gemma4:e4b
```

3. 确认服务与模型：

```bash
curl -s http://localhost:11434/api/tags
# 或直接用道语言跑：
源码/.venv/bin/python 源码/main.py 示例/AI对话/模型列表.道
```

## 运行

以下命令均在**仓库根目录**执行。示例只依赖标准库模块，不搜索自定义模块，因此不受工作目录影响：

```bash
# 1. 查看本机模型（不发对话请求，最快）
源码/.venv/bin/python 源码/main.py 示例/AI对话/模型列表.道

# 2. 单次问答（真实调用一次 gemma4:e4b，通常 10~40 秒）
源码/.venv/bin/python 源码/main.py 示例/AI对话/单次问答.道

# 3. 多轮交互对话（非流式）
源码/.venv/bin/python 源码/main.py 示例/AI对话/对话.道

# 4. 流式输出（打字机效果）
源码/.venv/bin/python 源码/main.py 示例/AI对话/流式对话.道
```

管道 / 非交互方式（便于脚本化）：

```bash
printf '/帮助\n你好\n/退出\n' | 源码/.venv/bin/python 源码/main.py 示例/AI对话/对话.道
printf '用一句话介绍道语言\n/退出\n' | 源码/.venv/bin/python 源码/main.py 示例/AI对话/流式对话.道
```

### 交互命令

`对话.道` 与 `流式对话.道` 通用（`流式对话.道` 没有 `/历史`）：

| 输入 | 作用 |
| --- | --- |
| `/帮助` | 显示命令列表 |
| `/清空` | 清空对话历史（保留系统提示） |
| `/历史` | 查看历史条数、轮数、累计 token（仅非流式示例） |
| `/模型` | 查看当前模型与服务地址 |
| `/思考` | 开关 gemma4 思考过程（`message.thinking`）的显示 |
| `/退出` | 结束对话；`退出`、`quit`、`exit`、`:q` 同样有效 |
| 空行 | 跳过 |
| 其它文本 | 作为提问发给模型 |

输入结束（EOF）也会自动优雅退出，不会抛异常栈。

## 流式输出

`对话.道` 用的是非流式请求（`"stream": 假`）：`请求()` 会 `read()` 完整个响应体才返回，所以必须等模型把整段回答生成完才能看到内容。`流式对话.道` 换成 `"stream": 真`，服务端每生成一小段就返回一行 JSON（NDJSON），客户端逐行处理，实现打字机效果。

**需要两层能力**（本次一并加入解释器）：

| 层 | 新增能力 | 作用 |
| --- | --- | --- |
| 网络层 | `从 网络 导入 流式请求` | 逐行 `readline()` 读取响应，每读到一行就回调道语言函数；回调返回 `假` 可提前终止；返回读取行数 |
| 输出层 | `打印(..., 结尾="", 刷新=真)` | 立即刷新 stdout 缓冲区。原来的 `打印` 只有 `结尾`，不带换行时内容会留在缓冲区，看不到逐字效果 |

最小骨架：

```道
从 网络 导入 流式请求
从 编码 导入 JSON

函数 收到(行)
    定义 块 = JSON.解码(行)
    打印(块["message"]["content"], 结尾="", 刷新=真)
    返回 真

定义 行数 = 流式请求("http://localhost:11434/api/chat", {
    "方法": "POST",
    "请求头": {"Content-Type": "application/json"},
    "数据": JSON.编码({"model": "gemma4:e4b", "messages": 历史, "stream": 真}),
    "超时": 120
}, 收到)
```

ollama 的流里每行形如：

```json
{"model":"gemma4:e4b","message":{"role":"assistant","content":"你"},"done":false}
{"model":"gemma4:e4b","message":{"role":"assistant","content":""},"done":true,"eval_count":339,"total_duration":20000000000}
```

注意点：

- `message.thinking` 也是逐块流式返回的。**gemma4:e4b 默认开启思考**，前几百个 token 都在 thinking 里而 `content` 为空；`流式对话.道` 默认显示思考过程（`/思考` 可关），否则用户会盯着一片空白以为卡住。
- `message.content` 是**增量片段**，要自己拼接成完整回答；`done: true` 那一行才带 `eval_count`、`total_duration` 等统计。
- 多轮历史里仍只放拼接后的最终 `content`，不放 thinking 片段。
- `流式请求` 是通用原语，回调收到的是**原始一行文本**，所以 SSE 的 `data: {...}` 前缀、`[DONE]` 等非 JSON 行需要在回调里用 `尝试/捕获` 忽略，或先做前缀判断。
- 连接失败、HTTP 4xx/5xx 会抛中文 `运行时错误`，示例用 `尝试/捕获` 降级并回滚本轮历史。
- 实测本机 `gemma4:e4b` 一次短问答产生 307 个数据块 / 339 token / 20 秒。

## 用到的道语言特性

- `从 网络 导入 请求, 流式请求` —— 标准库函数必须用「从…导入」取；直接 `导入 网络` 会被模块绑定过滤掉函数
- `从 编码 导入 JSON` —— `JSON.编码(...)` 与 `响应.JSON()`
- `从 系统 导入 取环境变量` —— 支持带默认值读取环境变量
- `从 文本 导入 去空格, 连接` —— 注意 `包含` 与内置函数同名，直接导入会冲突
- `打印(..., 结尾="", 刷新=真)` —— 流式输出必须刷新缓冲区
- 字典字面量、嵌套下标、反引号模板字符串、`否则如果`、`尝试/捕获`、`当 真` 无限循环

### 两个关键坑

1. **选项字典用中文键、协议 JSON 用英文键**：`请求` 的选项写 `{"方法": "POST", "请求头": {...}, "数据": ..., "超时": 120}`，而发给 ollama 的请求体写 `{"model": ..., "messages": ..., "stream": ...}`。
2. **非流式必须 `"stream": 假`**：`对话.道` / `单次问答.道` 用一次 `JSON` 解码，若用默认的流式 NDJSON 会解析失败；`流式对话.道` 则显式 `"stream": 真` 并逐行处理。另外 `数据` 必须先用 `JSON.编码` 转成文本，直接传字典会被 `str()` 序列化成非法的 Python 风格文本。

## 关于 gemma4:e4b 的 thinking

本机 `gemma4:e4b` 支持 thinking：`message.thinking` 是内部推理，`message.content` 才是最终回答。非流式示例默认只显示 `content`（`/思考` 可打开）；流式示例默认显示推理，避免回答开始前长时间空白。

多轮对话时**历史里只放最终 `content`，不要把 `thinking` 带回下一轮**（Gemma 4 官方建议），三个对话示例都按此处理。思考 token 会计入 `eval_count`，所以生成量看起来明显偏大。

## `/api/chat` 主要字段

请求体（流式时把 `stream` 改为 `true`）：

```json
{
  "model": "gemma4:e4b",
  "messages": [
    {"role": "system", "content": "你是一个简洁、友善的中文助手，回答尽量简短。"},
    {"role": "user", "content": "你好"}
  ],
  "stream": false
}
```

响应字段（非流式为单个对象；流式为每行一个对象，最后一行 `done: true`）：

| 字段 | 含义 | 示例里的用途 |
| --- | --- | --- |
| `model` | 实际使用的模型 | 打印模型名 |
| `message.content` | 回答（流式下是增量片段） | 打印；拼接后存入对话历史 |
| `message.thinking` | 思考过程（可能缺失，流式下同为增量） | `/思考` 开关显示 |
| `done` | 流式下标记最后一行 | 触发收尾统计 |
| `eval_count` | 生成 token 数 | 统计（在 `done` 行） |
| `total_duration` | 总耗时（纳秒） | 换算成秒显示 |

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| `无法连接 ollama：请求失败: Connection refused` | 服务没起，运行 `ollama serve` |
| `HTTP 404` 或 `model 'gemma4:e4b' not found` | 模型未拉取，运行 `ollama pull gemma4:e4b` |
| 非流式回答为空 / JSON 解析报错 | 检查是否漏了 `"stream": 假`，流式 NDJSON 无法一次解码 |
| 流式输出看不到逐字效果 | 确认用了 `打印(..., 结尾="", 刷新=真)`；`刷新` 缺省时内容留在缓冲区 |
| 流式模式长时间没有回答 | gemma4:e4b 默认先输出 thinking，`content` 为空属正常；用 `/思考` 查看推理 |
| 首次提问特别慢 | 首次要把约 6 GB 模型加载进内存，`load_duration` 很高；之后走缓存会明显变快 |
| 管道里提示与输出混在一起 | 管道/重定向下无终端行缓冲，属正常；`打印` 的 `刷新` 参数只影响缓冲区，不改变输出顺序 |
