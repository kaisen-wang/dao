# 语言自举旗舰示例：静态检查器对照说明

## 定位

`静态检查器.道` 是**旗舰级语言自举示例**，不是生产级检查工具的替代品。它刻意只用道语言自身能力完成「读文件 → 调诊断原语 → 结构化中文输出 → 统计并返回退出码」的完整闭环，用来证明道语言具备写自身工具链的表达力。生产环境请继续使用 `dao.lsp.features.compute_diagnostics` 及配套 LSP 服务。

## 文件

| 文件 | 作用 |
| --- | --- |
| `静态检查器.道` | 命令行静态检查器，调用 `诊断源码`，诊断走 `错误输出`（stderr），通过信息走 `打印`（stdout） |
| `自举自检.道` | 打印 `关键字表` / `内置函数名` / `标准库模块名` 的数量与示例；演示 `字节长度("你好") = 6` 与 `读字节(3)` |
| `../../源码/tests/test_examples_bootstrap.py` | 6 个回归测试，含 Python 侧与道语言侧同输入对照 |

## 运行命令

在 `源码/` 目录下执行（目标路径经环境变量传入，原因见下）：

```bash
cd /home/carson/code/test/道/源码

# 检查一个正确的 .道 文件（退出码 0）
DAO_CHECK_TARGET=/path/to/target.道 \
  ./.venv/bin/python main.py ../示例/自举/静态检查器.道

# 检查一个含错误的文件（退出码 2）
DAO_CHECK_TARGET=/path/to/bad.道 \
  ./.venv/bin/python main.py ../示例/自举/静态检查器.道

# 自检（用管道提供 stdin，避免 read 阻塞）
printf 'abc' | ./.venv/bin/python main.py ../示例/自举/自举自检.道

# 测试
./.venv/bin/python -m pytest tests/test_examples_bootstrap.py -q
```

退出码约定：`0` 通过、`2` 发现诊断、`3` 未指定目标或读取失败。

## 与 Python 版对照的范围

- **对照对象**：`dao.lsp.features.compute_diagnostics`（`源码/dao/lsp/features.py`）与道语言内置 `诊断源码`（`源码/dao/builtins/functions.py`）。
- **同一批输入**：未闭合字符串（词法错误）、残缺表达式 `定义 x = `（语法错误）、合法源码（无诊断）。
- **一致口径**：诊断条数、错误类型（`词法错误` / `语法错误`）、消息主体。Python 版消息前缀形如 `词法错误：…`，道语言版以独立的 `类型` 字段给出；测试统一抽取前缀后比较。
- **坐标差异**：Python 版 `range` 为 0-based LSP 坐标；道语言版 `行` / `列` 为 1-based。两者语义一致，但数值相差 1，不在「数值相等」的对照范围内。

## 已知限制

1. **目标路径传递**：`main.py` 的 `argparse` 只登记一个位置参数，直接追加第二个参数会被拒绝。因此脚本优先读 `命令行参数()[2]`（未来入口放行透传时自动生效），当前退回环境变量 `DAO_CHECK_TARGET`。这是入口限制，不是道语言限制。
2. **读字节会阻塞**：`读字节(n)` 底层是 `sys.stdin.buffer.read(n)`，在交互终端会等待满 n 字节。自检脚本用管道喂入短输入即可立即返回。
3. **诊断种类**：`诊断源码` 目前捕获词法/语法错误，命中一条即返回；不做语义静态分析，也不累积多条诊断。对照测试因此只断言「条数与类型一致」，不比较全部字段。
4. **无生产防护**：脚本假定文件可读、编码为 UTF-8；路径校验与权限处理仅覆盖基本失败提示。
5. **元数据结构**：`关键字表` / `内置函数名` / `标准库模块名` 返回 Python 列表，道语言侧用 `长度()` 与下标访问；内置函数数量与模块数量会随版本变动，测试只固定断言关键字数量 `79`。
