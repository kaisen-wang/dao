## 运行方式

### 关键前提：模块搜索依赖当前工作目录

解释器的模块加载器（`源码/dao/interpreter/statements/executor.py` 的 `exec_import`）按
`os.getcwd() + module_search_paths` 查找模块；`源码/main.py` 创建的 `Interpreter()` 未设置
`module_search_paths`（`源码/dao/interpreter/core.py` 中默认为空列表）。因此
`从 核心.引擎 导入 ...` 会被解析为 **`<当前工作目录>/核心/引擎.道`**。

**结论：必须先 `cd` 到本项目根目录 `示例/战棋/` 再运行**，否则一律报
`模块 '核心.引擎' 不存在`。以下命令均经实测，解释器为隔离环境
`/home/carson/code/test/道/源码/.venv/bin/python`：

```bash
# ① 旗舰入口（完整游戏流程）
cd /home/carson/code/test/道/示例/战棋
/home/carson/code/test/道/源码/.venv/bin/python /home/carson/code/test/道/源码/main.py 入口.道

# ② 端到端回归验证（6 项核心流程自检）
cd /home/carson/code/test/道/示例/战棋
/home/carson/code/test/道/源码/.venv/bin/python /home/carson/code/test/道/源码/main.py 回归验证.道

# ③ examples 两个演示脚本（cwd 同样必须是 示例/战棋/）
cd /home/carson/code/test/道/示例/战棋
/home/carson/code/test/道/源码/.venv/bin/python /home/carson/code/test/道/源码/main.py examples/试玩对战.道
/home/carson/code/test/道/源码/.venv/bin/python /home/carson/code/test/道/源码/main.py examples/AI演示.道
```

### 本轮修复

- **「对象没有属性 '行动'」**：`查询(战斗AI, 可选行动(?行动, ?理由))` 返回的解是字典，
  键为带 `?` 前缀的 `?行动` / `?理由`（见 `源码/dao/logic/solver.py` 的 `QueryResult.to_dict`）。
  原代码用 `解.行动` 点号访问，键不匹配而抛错。已在 `入口.道` 与 `战斗/行为树.道`
  改为下标访问 `解["?行动"]` / `解["?理由"]`。修复后旗舰流程完整跑通。

### 已知限制（本轮未改，均不阻塞运行）

1. **模块搜索强依赖 cwd**：属解释器 `exec_import` 设计（`search_dirs = [os.getcwd()] + ...`），
   非本项目缺陷。所有脚本必须从 `示例/战棋/` 启动，详见「运行方式」。
2. **逻辑查询结果键带 `?`**：`查询(...)` 返回字典的键是 `?变量名`，无法用 `.变量名`
   点号访问（`?` 非标识符字符），必须使用 `解["?变量名"]`。属解释器既有行为，
   .道 层按此写法即可。
3. **`断言` 条件内不支持直接写 `==`**：`断言 a == b, "msg"` 会被误判为失败，但
   `定义 ok = a == b` 正常。`回归验证.道` 已将比较结果先赋给布尔变量再断言。
   属解释器解析限制，本轮未改解释器源码。
4. **`角色.抽牌(数量)` 参数未生效**：`实体/角色.道` 的 `抽牌` 函数体每次只抽 1 张，
   忽略 `数量` 参数（如 `抽牌(5)` 实际只抽 1 张）。入口与回归脚本均按当前行为运行且
   能跑通；此为模块自身语义缺陷，修复会改变牌序与对局节奏，故本轮未改，留待后续。
5. **旧 CLI 注释**：`examples/*.道` 文件头 `用法: dao 试玩对战.道` 为早期示意，
   项目无 `dao` 命令，以「运行方式」章节命令为准。

> 本轮检查未发现「导入失败」或「静默失败」：24 个 .道 文件全部可加载、导出名全部可解析；
> 上述限制均为显式记录，不影响 `入口.道` 与 `回归验证.道` 的完整运行。
