## P0 — 阻塞正确性（建议立即处理）

### P0-1 修复约束解析 bug
- **位置**：`dao/parser/modules/logic_programming.py:180-184`（`parse_logic_constraint()`）
- **问题**：`LogicConstraint(variable="", bounds=(0, 0))` 硬编码,变量名与范围值从未真正传入。约束求解因此拿到的是占位值,`'?x 在范围 1..10'` 这类约束实际不生效。
- **影响**：逻辑编程的约束子系统功能性失效（不是性能问题,是结果错误）。
- **验收**：① 正确解析变量名与上下界；② 至少 3 个单元测试覆盖整数区间、变量引用、边界值；③ 一个端到端示例验证约束求解结果正确。
- **成本**：低（局部改动 + 测试）。

### P0-2 统一 VM 与 AST 语义（双模式一致性）
- **现状**：VM 模式刚修复内置函数注入（本次会话）；但代码审查报告 #9/#10 虽已修复,`test_dual_mode.py` 仅覆盖 8 个基础场景,未覆盖变量作用域、闭包、错误传播、成员访问等。
- **影响**：`--mode vm` 是宣传的核心特性,语义不一致会静默产生错误结果,且难以发现。
- **验收**：扩展 `test_dual_mode.py`,对同一批程序分别用两种模式执行并比对结果,覆盖：未定义变量报错、break/continue、闭包、内置函数、错误传播。
- **成本**：中（以测试为主,可能暴露少量实现差异需修补）。

- **现状**：`test_integration.py` 只跑示例文件；`test_new_features.py` 覆盖 OOP+FP+模式匹配,**不涉及逻辑/宏/并发的交互**。文档 `12-综合示例.md` 的跨范式融合无自动化测试兜底。
- **验收**：新增 `tests/test_cross_paradigm.py`,覆盖至少：并发+逻辑、逻辑+宏、宏+并发、OOP+逻辑四类组合,含错误传播与恢复场景。

### P1-2 低覆盖核心模块补测
- **证据**（覆盖率实测）：

  |------|--------|------|
  | `interpreter/concurrency.py` | 18% | 并发执行路径几乎无测试 |
  | `concurrency/async_await.py` | 19% | 异步/等待核心 |
  | `macros/ast_ops.py` | 19% | 宏 AST 操作 |

- **成本**：中高（工作量大但技术门槛低,可并行拆分）。

### P1-3 枚举与 OOP 深度集成
- **现状**：`oop_decl.py` 的 `parse_enum_decl()` 仅解析枚举值/变体参数,不支持枚举实现特征、枚举方法、值比较运算（`==`/`!=` 行为未定义）。
- **验收**：① `枚举 颜色 实现 可序列化` 可解析执行；② 枚举体内可定义方法；③ 枚举值相等性有明确定义与测试。
- **成本**：中（涉及 parser + interpreter + 测试）。
