# 道语言 `@` 注解功能设计规格（并行开发共享契约）

> 本文件是多个子代理并行开发的**唯一接口契约**。所有子代理必须严格按此规格实现，不得擅自更改接口名称、字段名、语义。

## 1. 目标与语义

为道语言新增 `@` 前缀的**运行时装饰器注解**。用于函数/类/变量声明，实现元编程包装（日志、缓存、注册、校验等）。

### 1.1 语法

```
@日志
函数  打招呼(名字)
    返回 "你好" + 名字

@缓存(10)
@计时
函数  fib(n)
    返回 n

@标记("用户模型")
类型  用户
    定义 名字 = ""
```

- `@` 后紧跟**标识符**（注解名），可选 `(参数列表)`。
- 参数支持位置参数与关键字参数（复用现有表达式解析）。
- 多个注解按**书写顺序堆叠**；语义应用顺序为**从下往上**（最靠近声明的先执行），与 Python 一致。
- 注解只能附着在：`VariableDecl`、`FunctionDecl`、`AsyncFunctionDecl`、`ClassDecl`、`AbstractDecl`、`EnumDecl`、`TraitDecl`。附着到其它语句时报**中文语法错误**。

### 1.2 运行时语义（关键）

对目标 `T` 与注解序列 `[A1, A2, ... An]`（书写顺序），应用顺序为 `An, ..., A2, A1`：

1. 在当前环境按注解名查找可调用对象（函数/内置函数/类）。找不到 → 中文运行时错误「注解 '名称' 未定义」。
2. 调用形式：`注解函数(T, *args, **kwargs)` —— **被装饰对象永远作为第一个位置参数**，其后是注解括号内的参数。
3. 若调用返回值**不是 `None`**，用返回值**替换** `T`；若为 `None`，保留原 `T`（便于纯标识型注解）。
4. 替换后的对象绑定到声明名（变量/函数/类）。
5. 注解**元数据**同时记录到对象的 `__注解__` 属性（若对象支持属性写入），供运行期自省；这一步失败（对象不可写属性）时静默跳过，不影响主流程。

## 2. 各环节接口契约（必须严格遵守）

### 2.1 Token（`dao/tokens.py`）

- 在 `TokenType` 的「标点符号」区新增成员：`注解 = auto()  # @ 注解前缀`。
- 位置紧邻 `感叹号` 之后。
- **不要**把 `@` 加入 `KEYWORDS`（它不是关键字，是符号）。

### 2.2 词法器（`dao/lexer/core.py`、`dao/lexer/readers.py`）

- `Lexer.tokenize()` 主循环中，在 `$` 分支之后、运算符兜底之前新增：
  ```python
  if char == "@":
      self.tokens.append(self._read_annotation())
      continue
  ```
- `LexerReaders` 新增方法 `_read_annotation(self) -> Token`：
  - 消费 `@`，随后读取标识符字符（`self._is_identifier_char`），产生 `TokenType.注解`，`value` 为注解名字符串（**不含 `@`**）。
  - `@` 后必须有标识符，否则抛中文词法错误「'@' 后需要一个注解名」。
  - 参数括号 `(`/`)` 与参数内容由**解析器**按现有表达式机制处理，词法器只负责 `@名称`。

### 2.3 AST（`dao/ast_nodes.py`）

- 新增节点：
  ```python
  @dataclass
  class Annotation(ASTNode):
      """注解：@名称 或 @名称(参数...)"""
      name: str = ""
      args: list[Expression] = field(default_factory=list)
      kwargs: dict[str, Expression] = field(default_factory=dict)
  ```
  放在 `TypeAnnotation` 系列之前（约第 820 行附近）。
- 给以下声明节点各加一个字段（**追加在现有字段末尾**，不得修改已有字段顺序，避免破坏位置参数构造）：
  ```python
  annotations: list[Annotation] = field(default_factory=list)
  ```
  涉及节点：`VariableDecl`、`FunctionDecl`、`AsyncFunctionDecl`、`ClassDecl`、`AbstractDecl`、`EnumDecl`、`TraitDecl`。
- 在 `dao/ast_nodes.py` 顶部的 `__all__`（若有）加入 `Annotation`；若无 `__all__` 则无需处理。

### 2.4 解析器（`dao/parser/statements.py` 等）

- `StatementParser.parse_statement()` 的 `match token.type` 新增分支：
  ```python
  case TokenType.注解:
      annotations = self.parse_annotations()
      stmt = self.parse_statement()
      if not isinstance(stmt, (VariableDecl, FunctionDecl, AsyncFunctionDecl,
                               ClassDecl, AbstractDecl, EnumDecl, TraitDecl)):
          raise 语法错误("注解只能用于声明（变量/函数/类/枚举/特征）",
                         token.line, token.column, self.source)
      stmt.annotations = annotations
      return stmt
  ```
- 新增方法 `parse_annotations(self) -> list[Annotation]`（放在 `dao/parser/modules/annotation.py` 新建文件，作为 mixin 加入 `StatementParser` 继承列表；也可直接放 `dao/parser/statements.py`，**由实现者自行选择但不要两处都放**）：
  - 循环消费当前 `TokenType.注解` token；
  - 每个注解读 `name = token.value`，`self.advance()`；
  - 若下一个是 `左括号`，解析调用参数：位置参数进 `args`，`名称=表达式` 进 `kwargs`（复用现有 `parse_call_args` 或手写等价逻辑）；
  - 注解之间必须是换行分隔（`换行` token），每个注解独占一行；连续两个 `@` 在同一行 → 中文语法错误。
- 类体内部方法/属性的注解：`dao/parser/modules/oop_decl.py` 的 `parse_class_body()` 中，在修饰符前缀循环（约第 247-259 行）里增加对 `TokenType.注解` 的处理，收集后回填到解析出的声明节点。
- **禁止**修改 `dao/parser/core.py` 的基类行为。

### 2.5 解释器（`dao/interpreter/statements/executor.py`）

- `StatementExecutor` 新增辅助方法：
  ```python
  def _apply_annotations(self, target, annotations: list[Annotation], env) -> object:
  ```
  按 §1.2 语义实现：逆序遍历，查找可调用对象，调用 `fn(target, *args, **kwargs)`，返回值非 `None` 则替换。所有错误用中文（如「注解 'X' 未定义」「注解 'X' 不可调用」）。
- 在以下方法中，`target` 创建完成后、绑定/返回前调用 `_apply_annotations`：
  - `exec_variable_decl()`（约第 213 行）—— 注解作用于 `value`；
  - `exec_function_decl()`（约第 309 行）—— 注解作用于 `func`；
  - `exec_class_decl()`（约第 608 行）—— 注解作用于 `DaoClass` 实例。
- 调用现有函数调用机制（查阅 `dao/interpreter/expressions.py` 的函数调用实现，如 `call_function` / `eval_call`），**不要自己实现调用逻辑**。
- `__注解__` 元数据写入失败时静默跳过。

### 2.6 字节码/VM（`dao/bytecode/compiler.py`）

- `BytecodeCompiler._compile_statement()` 为 `VariableDecl`/`FunctionDecl`/`ClassDecl` 生成字节码时，若语句带注解，生成等价的注解应用指令序列（可用现有 `CALL`/`LOAD_NAME`/`STORE_NAME` 等指令组合）。
- 目标是 `--mode vm` 下注解行为与 AST 模式一致。若现有指令集不足以表达，优先复用已有指令组合，不要新增复杂指令。
- 若实在无法支持，至少保证**忽略注解**时 VM 仍能正常运行（不崩溃），并在代码注释中说明限制。

### 2.7 类型检查器（`dao/types/checker.py`）

- `_check_statement()` 对带注解的声明：注解不参与类型推导（动态语义），但**不得因遇到新字段而报错**。默认无需修改，除非测试发现异常。

### 2.8 编辑器插件与文档

- VS Code 高亮：`编辑器插件/vscode/syntaxes/dao.tmLanguage.json` 增加 `@注解名` 的正则规则。
- Neovim 高亮：`编辑器插件/neovim/syntax/dao.vim` 增加对应 `syn match`。
- 新增文档：`文档/21-注解功能.md`，说明语法、语义、示例、与宏系统的区别。

## 3. 测试要求（每个子代理负责自己环节）

- 词法：`tests/test_lexer_annotation.py` —— 至少 3 例：`@名`、`@名(1, 键=2)`、非法 `@` 报错。
- AST/解析：`tests/test_parser_annotation.py` —— 至少 3 例：单注解、多注解堆叠、参数解析、非法附着报错。
- 解释器：`tests/test_interpreter_annotation.py` —— 至少 3 例：日志包装、缓存替换、返回 None 保留原对象、未定义注解报错。
- VM：`tests/test_vm_annotation.py` —— 至少 2 例：与 AST 模式行为一致。
- 所有测试中文错误消息断言用中文。

## 4. 错误处理统一要求

- 所有面向用户的错误消息必须是**中文**。
- 使用现有异常类：`词法错误`、`语法错误`、`运行时错误`、`类型错误`（`dao/errors.py`），不要引入新异常类型。

## 5. 并行开发边界（重要）

- 各子代理**只能修改自己负责的文件**，禁止跨界修改。
- 集成工作（全量测试、冲突修复、跨文件调整）由**主代理**统一完成。
- 若发现接口需要调整，**先报告主代理**，不要自行改动其它文件。
- 任何子代理不得运行全量测试（太慢且会受其他人未完成代码影响）；只运行自己环节的单测文件。
