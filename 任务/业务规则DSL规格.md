# 业务规则 DSL 规格（共享契约，2026-11-28）

## 目标

用「`@` 注解 + 逻辑规则」在**纯道语言层**实现一个可复用的声明式业务规则 DSL 示例库，不修改解释器核心（AST / VM / JIT 均不改动）。定位：展示道语言多范式融合能力，而非生产级规则引擎。

## 文件归属（独占，禁止越界）

- 实现代理：`示例/业务规则/**` + `源码/tests/test_examples_rules_dsl.py`
- 文档代理：`文档/25-业务规则DSL与Web示例.md` 等文档（见 Web 规格）
- 主代理：本规格、`任务/Web完整示例规格.md`、集成验收、工作日志

## 公共 API 契约（文档按此写）

库入口 `示例/业务规则/规则引擎.道`，导出：

| 名称 | 形态 | 语义 |
|------|------|------|
| `标注规则` | 注解函数 | `@标注规则(名称="拦截", 优先级=10, 条件="高风险")`，附着到函数；把 `{名称, 优先级, 条件, 处理器}` 登记进规则表并返回原函数（返回 `无` 会丢函数）。优先级数值大者先执行。 |
| `规则表` | 列表变量 | 已登记规则，元素为字典；键固定为 `名称` / `优先级` / `条件` / `处理器`。 |
| `判定` | 函数 `(对象, 知识库)` | 查询知识库中该对象命中的标签；按优先级降序取第一条条件命中的规则，执行其处理器；返回字典 `{"命中": 布尔, "规则名": 文本, "优先级": 数值, "结果": 处理器返回值}`，无命中返回 `{"命中": 假, "规则名": "", "优先级": 0, "结果": 无}`。 |
| `全部判定` | 函数 `(对象, 知识库)` | 同上但返回所有命中规则的结果列表（已按优先级降序）。 |
| `清空规则` | 函数 `()` | 清空规则表，供测试隔离。 |

规则条件用**正谓词标签**表达：业务侧把事实写成 `风险(对象, 标签)`（或用 `添加事实(知识库, "风险", 对象, 标签)` 动态注入），DSL 通过 `查询(知识库, 风险(对象, ?标签))` 得到命中标签集合，再与注解登记的条件比对。库顶部有 `定义 无 = 空` 别名（道语言的 `空` 即 Python `None`），模块末尾用 `导出` 控制对外可见名称。

## 硬约束（实测踩坑，必须遵守）

1. `规则` 是上下文关键字，注解函数不要命名为 `规则`；用 `标注规则`。
2. 道语言读不到 `__注解__`，注解参数必须在注解函数内捕获到规则表；不要在示例里读取 `__注解__`。
3. 注解附着到 `逻辑` 块不受支持；知识库只能由普通函数/变量标注或手工构造。
4. 规则体内**只有正谓词调用有效**：`非`、`剪枝`、比较式（如 `?分数 >= 90`）会被静默忽略。阈值类条件必须在道语言侧先算成标签事实（例如 `分数>=90` → `添加事实(kb, "风险", 人, "高分")`）。
5. 不要依赖 `并且` / `或者` 的短路行为；用嵌套 `如果` 或提前返回。
6. 逻辑查询结果字典的键带 `?` 前缀，取值用 `解["?标签"]`，不能用属性访问。
7. 注解参数在声明时求值，注解函数在装饰前必须已定义。
8. 测试中子进程一律用 `sys.executable`，禁止硬编码 `.venv/bin/python`。
9. 示例和演示脚本不得依赖外网、ollama 或特定绝对路径；模块搜索基于 cwd，测试须设置正确的工作目录。

## 最小可运行骨架（已实测）

```dao
定义 规则表 = []
函数 标注规则(处理器, 名称="", 优先级=0, 条件="")
    追加(规则表, {"名称": 名称, "优先级": 优先级, "条件": 条件, "处理器": 处理器})
    返回 处理器

@标注规则(名称="拦截", 优先级=10, 条件="高风险")
函数 拦截(对象)
    返回 "拦截:" + 对象

逻辑 风控库
    事实: 风险("甲", "高风险")
    规则: 命中(?人, ?标签) 如果 风险(?人, ?标签)

添加事实(风控库, "风险", "乙", "低风险")
定义 对象 = "乙"
定义 命中结果 = 查询(风控库, 命中(对象, ?标签))
# 命中结果 = [{'?人': '乙', '?标签': '低风险'}]
```
