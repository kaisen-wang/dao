## 公共 API 与示例契约（文档按此写）

目录 `示例/Web应用/`：

- `服务器.道`：单文件 HTTP 服务，默认端口 **18081**，通过 `从 系统 导入 取环境变量` 读取 `WEB示例端口` 覆盖（测试用环境变量动态选端口）；改动位置写在文件首行注释里。路由：
  - `GET /` → HTML 首页，`内容类型` 为 `text/html; charset=utf-8`
  - `GET /api/健康` → `{"状态": "正常"}` JSON
  - `POST /api/订单` → 请求体 JSON 含 `商品`/`数量` 时返回 201 与订单字典；缺字段返回 400；非法 JSON 由 `.JSON()` 的错误路径兜底为 400
  - `GET /api/用户/*` → 通配符路径，回显路径中的用户名（演示百分号解码/通配路由）
  - 未匹配路径由服务器默认 404 兜底
  - 所有处理器返回标准响应字典 `{"状态码": ..., "内容": ..., "内容类型": ...}`
- `客户端.道`：只请求本机 18081，演示：
  - `从 网络 导入 请求` + `从 编码 导入 JSON`
  - `请求(地址, {"方法": ..., "请求头": ..., "数据": ..., "超时": 5})`
  - 对网络异常与 5xx 做**有限重试 + 线性退避**（最多 3 次，`从 时间 导入 睡眠`）；4xx 不重试
  - 对 4xx/5xx/成功的响应分别打印确定文本；输出中不要包含时间戳、随机 ID 等不稳定内容
  - 至少覆盖 GET 健康接口、POST 订单成功、POST 缺字段失败三条链路
- `使用说明.md`：两个终端的运行命令（先服务器后客户端）、端点表、预期输出、常见错误（端口占用 / 4xx 不重试 / 4xx 语义是返回响应对象而非抛异常）。

## 硬约束（实测踩坑，必须遵守）

1. `请求` 对 HTTP 4xx/5xx **返回响应对象不抛异常**，重试判断必须检查 `响应.状态码`；`流式请求` 才抛异常。
2. `从 网络 导入 请求` 可用；`导入 网络` 不会拿到内置函数，避免后者。
3. 不依赖 `并且`/`或者` 短路；用嵌套 `如果`。
4. `打印(..., 结尾="", 刷新=真)` 可用，但示例输出以逐行稳定文本为主，便于断言。
5. 测试中子进程一律用 `sys.executable`（禁止 `.venv/bin/python`）；服务进程结束时务必 `terminate()` + `wait()`，且用 `daemon` 线程/超时读取避免卡死。
6. 端口 18081 若被占用，测试应跳过或换空闲端口（换端口时须同步服务端脚本；不得修改网络模块）。
7. 模块搜索基于 cwd，测试子进程工作目录设为 `示例/Web应用` 或仓库根（保持一致）。
8. 不修改 `源码/dao/**` 任何文件；不修改 `文档/标准库API/网络.md` 的 docgen 自动生成清单。
