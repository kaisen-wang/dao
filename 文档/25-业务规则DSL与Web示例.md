# 25. 业务规则 DSL 与 Web 完整示例

本章收录两条新增的示例线：一条用「注解 + 逻辑规则」在纯道语言层实现声明式业务规则 DSL，一条用内建 HTTP 服务端/客户端搭出可独立运行的完整 Web 示例。两者都**不修改解释器核心或标准库源码**，定位是展示道语言多范式融合与标准库能力的示例，而非生产级组件。

## 25.1 业务规则 DSL

### 25.1.1 定位与文件清单

业务规则 DSL 完全用道语言写成：用 `@` 注解把业务规则登记进规则表，用逻辑知识库保存事实，再用谓词查询完成判定。解释器（AST / VM / JIT）无需改动。

| 文件 | 作用 |
|------|------|
| `示例/业务规则/规则引擎.道` | 库本体，导出下述公共 API |
| `示例/业务规则/风控演示.道` | 演示优先级命中、无命中、动态改事实后重新判定 |
| `示例/业务规则/README.md` | 运行方法、DSL 语法、能力边界 |

运行（工作目录为 `示例/业务规则`）：

```bash
cd 示例/业务规则
python ../../源码/main.py 风控演示.道
```

演示登记了 4 个处理器：`拦截`（优先级 100 / 条件「高风险」）、`人工复核`（50 / 高风险）、`限额放行`（10 / 低风险）、`白名单直达`（80 / 白名单）；输出前缀依次为 `场景1-高优先级命中`、`场景2-无命中`、`场景3-动态事实后重新判定`、`场景3-再次改事实后重新判定`、`全部命中`。

### 25.1.2 公共 API

库入口为 `示例/业务规则/规则引擎.道`，导出：

| 名称 | 形态 | 语义 |
|------|------|------|
| `标注规则` | 注解函数 | `@标注规则(名称="拦截", 优先级=10, 条件="高风险")`，附着到函数；把 `{名称, 优先级, 条件, 处理器}` 登记进规则表并返回原函数（返回 `无` 会丢函数）。优先级数值大者先执行。 |
| `规则表` | 列表变量 | 已登记规则，元素为字典；键固定为 `名称` / `优先级` / `条件` / `处理器`。 |
| `判定` | 函数 `(对象, 知识库)` | 查询知识库中该对象命中的标签；按优先级降序取第一条条件命中的规则并执行其处理器。 |
| `全部判定` | 函数 `(对象, 知识库)` | 同上但返回所有命中规则的结果列表（已按优先级降序）。 |
| `清空规则` | 函数 `()` | 清空规则表，供测试隔离。 |

`判定` 返回字典：

```
{"命中": 布尔, "规则名": 文本, "优先级": 数值, "结果": 处理器返回值}
```

无命中时返回 `{"命中": 假, "规则名": "", "优先级": 0, "结果": 无}`。`全部判定` 返回上述字典按优先级降序排列的列表。库顶部有 `定义 无 = 空`——道语言的 `空` 即 Python `None`，作为契约中「无」的别名。

### 25.1.3 正谓词标签事实模型

规则条件用**正谓词标签**表达，而不是在规则体里写比较或否定：

```
定义 规则表 = []

函数 标注规则(处理器, 名称="", 优先级=0, 条件="")
    追加(规则表, {"名称": 名称, "优先级": 优先级, "条件": 条件, "处理器": 处理器})
    返回 处理器

@标注规则(名称="拦截", 优先级=10, 条件="高风险")
函数 拦截(对象)
    返回 "拦截:" + 对象

逻辑 风控库
    事实: 风险("甲", "高风险")

添加事实(风控库, "风险", "乙", "低风险")
定义 对象 = "乙"
定义 标签列表 = 查询(风控库, 风险(对象, ?标签))
# 标签列表 = [{'?标签': '低风险'}]
```

业务侧把事实写成 `风险(对象, 标签)`，或用 `添加事实(知识库, "风险", 对象, 标签)` 动态注入；DSL 通过 `查询(知识库, 风险(对象, ?标签))` 得到命中标签集合，再由引擎内部函数 `命中标签(对象, 知识库)` 用 `解["?标签"]` 取出标签，与注解登记的条件比对。阈值类条件要**先在道语言侧算成标签事实**，例如 `分数>=90` → `添加事实(kb, "风险", 人, "高分")`，再以 `"高分"` 作为 `条件`。演示文件里还保留了一条 `命中` 规则，但引擎实际查询的是 `风险` 谓词本身，不依赖该规则。

### 25.1.4 能力边界（与原生逻辑规则的区别）

- **规则体内只有正谓词调用有效**：`非`、`剪枝`、比较式（如 `?分数 >= 90`）会被**静默忽略**，不会报错也不会生效。
- **道语言读不到 `__注解__`**：注解参数必须在注解函数内捕获到规则表；不要在示例里读取 `__注解__`。
- **注解不能附着到 `逻辑` 块**：知识库只能由普通函数/变量标注或手工构造。
- `规则` 是上下文关键字，注解函数不要命名为 `规则`，用 `标注规则`。
- 不要依赖 `并且` / `或者` 的短路行为；用嵌套 `如果` 或提前返回。
- 逻辑查询结果字典的键带 `?` 前缀，取值用 `解["?标签"]`，不能用属性访问。
- 注解参数在声明时求值，注解函数在装饰前必须已定义。

## 25.2 完整 Web 示例

### 25.2.1 定位与文件清单

`示例/Web应用/` 用网络模块内建的 `创建服务器()` / `路由` / `启动` / `关闭` 搭单文件 HTTP 服务，并配一个只访问本机的客户端。无外部依赖、不改标准库源码。

| 文件 | 作用 |
|------|------|
| `示例/Web应用/服务器.道` | 单文件 HTTP 服务，默认端口 **18081**（可用环境变量 `WEB示例端口` 覆盖；改端口的位置写在文件首行注释里） |
| `示例/Web应用/客户端.道` | 本机客户端，演示请求、响应判断与有限重试 |
| `示例/Web应用/使用说明.md` | 两个终端的运行命令、端点表、预期输出、常见错误 |

### 25.2.2 端点表

| 方法 | 路径 | 行为 |
|------|------|------|
| `GET` | `/` | HTML 首页，`内容类型` 为 `text/html; charset=utf-8` |
| `GET` | `/api/健康` | `{"状态": "正常"}` JSON |
| `POST` | `/api/订单` | 请求体 JSON 含 `商品`/`数量` 时返回 201 与 `{"商品":..., "数量":..., "状态": "已创建"}`；缺字段返回 400 `{"错误": "缺少商品或数量"}`；非法 JSON 由 `.JSON()` 的错误路径兜底为 400 |
| `GET` | `/api/用户/*` | 通配符路径，回显（百分号解码后的）用户名，如 `{"用户": "张三"}` |
| — | 未匹配路径 | 服务器默认 404 兜底 |

所有处理器返回标准响应字典 `{"状态码": ..., "内容": ..., "内容类型": ...}`。

### 25.2.3 运行方式

开两个终端，先启动服务器、再运行客户端（工作目录均为 `示例/Web应用`）：

```bash
# 终端一：启动服务（监听 18081）
cd 示例/Web应用
python ../../源码/main.py 服务器.道

# 终端二：运行客户端
cd 示例/Web应用
python ../../源码/main.py 客户端.道
```

客户端至少覆盖 GET 健康接口、POST 订单成功、POST 缺字段失败三条链路，预期输出为：

```text
健康接口：HTTP 200 / 状态=正常
订单创建：HTTP 201 / 商品=键盘 / 数量=2
请求校验：HTTP 400 / 错误=缺少商品或数量
```

输出为逐行稳定文本，不含时间戳、随机 ID 等不稳定内容。若要改端口，需同时给两个进程设置同一个 `WEB示例端口`（如 `WEB示例端口=18082`）；端口占用与更多排错见 `示例/Web应用/使用说明.md`。

### 25.2.4 请求、响应与重试策略

客户端用 `从 网络 导入 请求, URL编码` + `从 编码 导入 JSON`，调用形如：

```
请求(地址, {"方法": ..., "请求头": ..., "数据": ..., "超时": 5})
```

其中 `数据` 只在 POST 时设置（用 `JSON.编码(数据)` 转成文本并配 `Content-Type` 请求头），GET 只带 `方法` / `请求头` / `超时`；响应体从 `响应.响应体` 取，再用 `JSON.解码` 还原。

关键点：

- **`请求` 对 HTTP 4xx/5xx 返回响应对象，而不是抛异常**；重试判断必须检查 `响应.状态码`（`流式请求` 才抛异常）。
- 对**网络异常与 5xx**（`响应.状态码 >= 500`）做有限重试：最多 3 次，**线性退避**（第 n 次失败睡眠 `0.05 * n` 秒）；**4xx 不重试**（如缺字段的 400 直接打印失败结果）。
- `睡眠` 与全局内置函数同名，示例写作 `从 时间 导入 睡眠 作为 休眠` 避免重复定义报错。
- 中文路径先用 `URL编码` 转成百分号形式再请求（如 `/api/%E5%81%A5%E5%BA%B7`），服务端会自动解码后匹配路由。
- 对 4xx / 5xx / 成功的响应分别打印确定文本，便于断言。
- 用 `导入 网络` 不会拿到内置函数，要用 `从 网络 导入 请求`。
- 不要依赖 `并且` / `或者` 短路；用嵌套 `如果` 判断状态码。
