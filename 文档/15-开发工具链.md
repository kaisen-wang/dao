## 15.1 零侵入调试器（`dao/debug/`）

调试器在**不修改解释器核心源码**的前提下提供断点、单步、变量查看与调用栈能力。源码位于 `源码/dao/debug/debugger.py`，通过 `源码/dao/debug/__init__.py` 导出。

### 核心 API（真实接口）

| 对象 | 说明 | 源码位置 |
|------|------|----------|
| `Debugger()` | 纯状态机：管理断点、单步开关、执行计数、暂停事件 | `debugger.py:77` |
| `设置断点(文件, 行号)` | 行号从 1 起；`文件=""` 表示通配任意文件；重复设置不产生副本 | `debugger.py:90` |
| `删除断点 / 列出断点 / 清空断点` | 断点管理 | `debugger.py:99-112` |
| `单步 = True` | 打开单步后每条语句执行前都触发事件 | `debugger.py:83` |
| `执行计数 / 事件列表 / 最后事件` | 执行统计与暂停上下文记录 | `debugger.py:84-86` |
| `暂停回调` | 可选回调，返回 `调试指令.暂停` 或 `"暂停"` 会抛 `调试暂停` 中断执行；默认只记录事件、不改变程序行为 | `debugger.py:87,135-138` |
| `查看变量(名称=None)` | 名称为空返回当前作用域变量字典，否则沿作用域链查找 | `debugger.py:147` |
| `查看调用栈()` | 返回最后一次暂停处的调用栈 | `debugger.py:153` |
| `复位()` | 清空计数与事件，保留断点与开关 | `debugger.py:159` |
| `DebugExecutor(debugger, 文件名="")` | `Interpreter` 子类，覆盖 `exec_statement` / `_exec_block` 插入钩子 | `debugger.py:166` |
| `暂停事件` | 含 `文件/行号/列号/语句类型/环境/调用栈/步数`，也可 `事件.查看变量()` | `debugger.py:50` |
| `断点 / 调试指令 / 调试暂停` | 断点数据类、控制指令枚举、暂停异常（均为中文命名） | `debugger.py:28-74` |

> 无障碍原则：调试器未启用、未命中断点且未开启单步时，钩子立即返回，不改变程序行为（`debugger.py:115-123`）。

### 可直接运行的示例

将以下代码保存为 `demo_debugger.py`（示例按 15.0 保存到 `/tmp/` 并用 `PYTHONPATH` 运行）：

```python
# -*- coding: utf-8 -*-
"""调试器最小示例：断点 / 变量查看 / 调用栈 / 单步"""
from dao.debug import Debugger, DebugExecutor
from dao.lexer import Lexer
from dao.parser import Parser

源码 = (
    "函数 加法(甲, 乙)\n"
    "    定义 和 = 甲 + 乙\n"
    "    返回 和\n"
    "\n"
    "定义 结果 = 加法(1, 2)\n"
    "打印(结果)\n"
)
ast = Parser(Lexer(源码).tokenize()).parse()

# 场景一：断点 + 变量查看 + 调用栈
调试器 = Debugger()
调试器.设置断点("", 2)  # 第 2 行设断点；文件名为 "" 表示通配任意文件
执行器 = DebugExecutor(调试器, 文件名="示例.道")
执行器.execute(ast, source=源码)

print("断点命中次数:", len(调试器.事件列表))
print("断点处调用栈:", 调试器.查看调用栈())
print("断点处变量 甲 =", 调试器.查看变量("甲"))
print("断点处变量 乙 =", 调试器.查看变量("乙"))

# 场景二：单步执行
单步调试器 = Debugger()
单步调试器.单步 = True
DebugExecutor(单步调试器).execute(ast, source=源码)
print("单步执行计数:", 单步调试器.执行计数)
print("单步事件行号:", [e.行号 for e in 单步调试器.事件列表])
```

运行（脚本保存为 `/tmp/demo_debugger.py`，在 `源码/` 目录下执行）：

```bash
cd 源码
PYTHONPATH=. ./.venv/bin/python /tmp/demo_debugger.py
```

实际输出：

```
3
断点命中次数: 1
断点处调用栈: [{'function': '加法', 'file': '', 'line': 5}]
断点处变量 甲 = 1
断点处变量 乙 = 2
3
单步执行计数: 5
单步事件行号: [1, 5, 2, 3, 6]
```

输出说明：

- 两处单独的 `3` 是道程序 `打印(结果)`（`1 + 2`）在场景一、场景二各执行一次的输出，**说明挂载调试器不改变程序运行结果**。
- 断点命中第 2 行（函数体内 `定义 和 = 甲 + 乙`）时，调用栈显示正处于函数 `加法` 中（由第 5 行调用），变量 `甲=1`、`乙=2` 可正确查看。
- 单步模式下共触发 5 个事件，行号顺序 `[1, 5, 2, 3, 6]` 即真实执行流：进入函数声明 → 调用 → 函数体两行 → 打印。

> 提示：若需要在暂停处真正**中断**执行（而非仅记录），可设置 `调试器.暂停回调 = lambda 事件: 调试指令.暂停`，此时会抛出 `调试暂停` 异常；可捕获异常的 `.事件` 查看上下文。

### DAP 调试适配器（IDE 接入，`dao/debug/dap.py`）

在上面这套状态机之上，`dao/debug/dap.py` 实现了一个基于 **stdio** 的 Debug Adapter Protocol 适配器，让 VS Code 等 IDE 能直接调试 `.道` 程序。它把 IDE 的 JSON 请求翻译成调试器状态操作，并把断点/单步暂停包装成 DAP 事件；被调试程序的 `打印` 输出以 `output` 事件回传，不会污染协议帧。

**启动方式**（在 `源码/` 目录下执行，适配器从 stdin 读请求、向 stdout 写响应）：

```bash
cd 源码
./.venv/bin/python -m dao.debug.dap
```

对应的 VS Code `launch.json` 配置片段：

```json
{
  "type": "dao",
  "request": "launch",
  "name": "调试道程序",
  "program": "${workspaceFolder}/示例/基础示例.道",
  "stopOnEntry": false
}
```

**已实现的请求**（`DAP适配器.处理消息` 按 `command` 分派）：

| 请求 | 行为 |
|------|------|
| `initialize` | 返回 `supportsConfigurationDoneRequest` / `supportsEvaluateForHovers` 等能力，并发出 `initialized` 事件 |
| `launch` | 读取 `arguments.program`，支持 `stopOnEntry`、`noDebug`；`configurationDone` 后才真正启动被调试线程 |
| `setBreakpoints` | 按 `source.path` 同步断点到 `Debugger`，返回 `verified` 断点列表；空列表清除该文件断点 |
| `configurationDone` | 响应完成后启动执行线程，避免错过客户端在启动前设置的断点 |
| `stackTrace` | 从暂停事件构造调用栈帧（含文件、行号、列号、函数名）；外层帧来自 `事件.调用栈` |
| `scopes` | 提供唯一的「局部变量」作用域，`variablesReference = 1` |
| `variables` | 展示当前环境的用户变量（内置函数已过滤），支持列表/元组/字典的嵌套引用 |
| `evaluate` | 用道解析器求值表达式（如 `a + 2`），失败时返回 `success=false` 与原因 |
| `continue` / `next` / `stepIn` / `stepOut` | 恢复执行；`next` 步过函数、`stepIn` 步入、`stepOut` 回到调用者；暂停时发 `stopped` 事件并阻塞到下一条控制请求 |
| `threads` | 返回单一「主线程」（`id=1`） |
| `disconnect` | 响应后断开连接并释放暂停的执行线程 |
| `setExceptionBreakpoints` | 空实现，仅为兼容 IDE 握手 |

**发出的事件**：`initialized`、`stopped`（`reason` 为 `breakpoint` / `step` / `entry`）、`continued`、`output`（stdout/stderr）、`terminated`、`exited`。

**帧工具与内嵌用法**（便于测试或其他传输层复用）：

```python
from io import BytesIO
from dao.debug.dap import DAP适配器, 编码消息, 解码消息

输出 = BytesIO()
适配器 = DAP适配器(BytesIO(), 输出)
for 序号, 命令, 参数 in [
    (1, "initialize", {}),
    (2, "setBreakpoints", {"source": {"path": "demo.道"}, "breakpoints": [{"line": 2}]}),
    (3, "launch", {"program": "demo.道"}),
    (4, "configurationDone", {}),
]:
    适配器.处理消息({"seq": 序号, "type": "request", "command": 命令, "arguments": 参数})
# 从 输出.getvalue() 中用 解码消息() 读出响应与事件帧
```

帧格式为 `Content-Length: <字节数>\r\n\r\n<UTF-8 JSON>`；`编码消息()` / `解码消息()` 支持多帧、残帧与大小写不敏感的头部。

**已知边界**：使用单线程调试模型（一个线程 ID）；暂不支持条件断点、变量写入、异常断点与反向调试；`stepOut` 按调用栈深度判断，嵌套层次很深时以「回到更浅栈帧的第一条语句」为准。

## 15.2 API 文档生成器（`dao/tools/docgen.py`）

## 15.3 内建测试运行器（`dao/tools/testrunner.py`）

项目的 Python 测试仍用 pytest，但 `.道` 程序自身的回归测试**不再依赖 pytest**：运行器直接发现、执行 `.道` 测试脚本，并汇总标准库「测试」模块生成的 `DaoTestSuite` 结果，输出中文报告。

**测试文件约定**：文件名匹配 `测试*.道` 或 `*_测试.道`（递归扫描，跳过隐藏目录与 `__pycache__`）。脚本用 `测试套件(名称)` 创建套件，`尝试 / 捕获` 包裹断言，成功调用 `套件.record_pass(名称)`，失败调用 `套件.record_fail(名称, 期望, 实际)`；也可 `打印(测试报告(套件))`（运行器会统一汇总，脚本自带的打印会被抑制以免重复）。

**命令行用法**（在 `源码/` 目录下执行）：

```bash
cd 源码
./.venv/bin/python -m dao.tools.testrunner /path/to/tests
./.venv/bin/python -m dao.tools.testrunner . --pattern '*_用例.道'   # 自定义模式，可重复
./.venv/bin/python -m dao.tools.testrunner . --quiet                 # 仅输出汇总
```

示例输出：

```
=== 道语言测试运行器 ===
测试文件: 2，成功: 1，失败: 1
用例总计: 2，通过: 1，失败: 1

[通过] /tmp/tests/测试加法.道 （套件 1，通过 1，失败 0，1.20 毫秒）
[失败] /tmp/tests/计算_测试.道 （套件 1，通过 0，失败 1，0.72 毫秒）
    - 减法断言: 期望 5，实际 ...

运行结果: 存在失败
```

**退出码语义**：`0` = 全部通过；`1` = 至少一个用例失败（或文件执行出错）；`2` = 未发现测试文件。可直接用于 CI。

**Python API**：

```python
from dao.tools.testrunner import 发现测试文件, 执行测试文件, 运行测试, 生成报告

文件列表 = 发现测试文件("/path/to/tests")     # 仅发现
单文件 = 执行测试文件(文件列表[0])             # 返回 文件结果（通过/失败/套件数/错误）
汇总 = 运行测试("/path/to/tests")             # 返回 汇总结果；汇总.退出码 即进程退出码
print(生成报告(汇总))
```

**已知边界**：脚本若未创建任何 `DaoTestSuite`，该文件记为失败（「未发现测试套件」）；脚本调用 `退出()` 会以文件级错误处理；本地模块导入基于测试文件所在目录解析。

## 15.4 AC-3 弧一致性与 `LessThanConstraint`（`dao/logic/constraints/`）

AC-3 提供与具体求解器解耦的通用弧一致性域缩减：反复修订各变量的候选值域，直到达到弧一致；任一域被裁为空则提前返回 `None` 表示不可满足。核心实现位于 `源码/dao/logic/constraints/ac3.py`，约束类位于 `core.py`。

### 核心 API（真实接口）

| 对象 | 说明 | 源码位置 |
|------|------|----------|
| `Domain(values)` | 变量候选值域，内部存 `frozenset`（自动解包 `LogicAtom`）；提供 `.values` / `is_empty()` / `copy()` | `ac3.py:40` |
| `ac3(constraints, domains, counter=None)` | 返回裁剪后的域字典，或 `None`（不可满足）；`counter[0]` 累计 `revise` 次数 | `ac3.py:180` |
| `revise(constraint, xi, domain_i, xj, domain_j)` | 对单条弧做一致性修订 | `ac3.py:111` |
| `build_arcs(constraints)` | 由约束集合构建待检查弧列表 | `ac3.py:161` |
| `LessThanConstraint(variable1, variable2)` | 「小于」约束 `variable1 < variable2`，AC-3 中体现 `A < B < C ⟹ A < C` 的传递推理 | `core.py:131` |
| `ConstraintSolver` | 高层封装：`set_domain()`、`propagate_domains()`（内部调用 `ac3`）、`solve_constraints()`（AC-3 引导的回溯搜索）、`last_search_stats` | `core.py:223-399` |

约束类型枚举 `ConstraintType` 含 `NUMERIC_RANGE / EQUALITY / INEQUALITY / TYPE / LOGICAL / LESS_THAN`（`core.py:16-25`），`revise` 按 `constraint.constraint_type.value` 分派裁剪逻辑（`ac3.py:130-158`）。

### 可直接运行的示例

将以下代码保存为 `demo_ac3.py`（示例按 15.0 保存到 `/tmp/` 并用 `PYTHONPATH` 运行）：

```python
# -*- coding: utf-8 -*-
"""AC-3 弧一致性 + LessThanConstraint 最小示例"""
from dao.logic.constraints.ac3 import Domain, ac3
from dao.logic.constraints.core import ConstraintSolver, LessThanConstraint
from dao.logic.core import LogicVariable

x = LogicVariable("?x")
y = LogicVariable("?y")

# 底层 API：x < y，两者初始候选域均为 1..5
约束 = LessThanConstraint(x, y)
初始域 = {x: Domain(range(1, 6)), y: Domain(range(1, 6))}
counter = [0]
结果 = ac3([约束], 初始域, counter)
print("底层 ac3 -> x 域:", sorted(结果[x].values))
print("底层 ac3 -> y 域:", sorted(结果[y].values))
print("revise 调用次数:", counter[0])

# 高层 API：用 ConstraintSolver 做域传播
求解器 = ConstraintSolver([LessThanConstraint(x, y)])
求解器.set_domain(x, range(1, 6))
求解器.set_domain(y, range(1, 6))
传播 = 求解器.propagate_domains()
print("propagate_domains -> x 域:", sorted(传播[x].values))
print("propagate_domains -> y 域:", sorted(传播[y].values))

# 不可满足时返回 None（提前失败）
矛盾 = ConstraintSolver([LessThanConstraint(x, y)])
矛盾.set_domain(x, [5])
矛盾.set_domain(y, [1])
print("空域结果:", 矛盾.propagate_domains())
```

运行（脚本保存为 `/tmp/demo_ac3.py`，在 `源码/` 目录下执行）：

```bash
cd 源码
PYTHONPATH=. ./.venv/bin/python /tmp/demo_ac3.py
```

实际输出：

```
底层 ac3 -> x 域: [1, 2, 3, 4]
底层 ac3 -> y 域: [2, 3, 4, 5]
revise 调用次数: 4
propagate_domains -> x 域: [1, 2, 3, 4]
propagate_domains -> y 域: [2, 3, 4, 5]
空域结果: None
```

输出说明：

- `x < y` 且二者都在 `1..5`：弧一致性裁掉 `x` 中的最大值 `5`（没有比它更大的 `y`）和 `y` 中的最小值 `1`（没有比它更小的 `x`），得到 `x = {1,2,3,4}`、`y = {2,3,4,5}`。底层 `ac3()` 与高层 `propagate_domains()` 结果一致。
- `counter[0] = 4` 是本例 `revise` 的调用次数，可用于性能诊断。
- 当约束不可满足（`x=5` 却要求 `x<y=1`）时，某变量域被裁为空，`propagate_domains()` 返回 `None`，调用方可据此提前失败，避免无谓的回溯搜索。

> 进阶：`ConstraintSolver.solve_constraints()` 在**所有未绑定变量都设置了候选域**时，会启用「AC-3 域缩减 + 最小剩余值（MRV）回溯」进行剪枝，并可用 `last_search_stats` 查看 `assignments / backtracks / ac3_calls / revise_calls`（`core.py:306-384`）。配套测试见 `源码/tests/logic_programming/test_ac3.py`。

## 15.5 小结

| 工具 | 入口 | 典型用途 |
|------|------|----------|
| 调试器 | `from dao.debug import Debugger, DebugExecutor` | 断点、单步、变量查看、调用栈；零侵入挂载到解释器 |

| 内建测试运行器 | `python -m dao.tools.testrunner 目录` | 发现并运行 `.道` 测试脚本，中文汇总与退出码，无需 pytest |
| AC-3 约束传播 | `dao.logic.constraints.ac3.ac3` / `ConstraintSolver` | 域缩减、传递推理、约束不可满足提前失败、搜索剪枝 |
| LSP 语言服务器 | `python -m dao.lsp` | 语法诊断、补全、悬停、定义跳转、文档符号（见第 14 章） |
