## 23.2 真 JIT：从空实现到运行时特化

### 23.2.1 旧实现的问题

`dao/jit/` 原先仅 110 行，`JitCompiler._specialize()` 把 `CodeObject` 的字段逐个复制为 `*_jit`，没有指令特化、内联或机器码生成；VM 仍走逐指令 `if/elif` 分派，热点函数每次调用还要构造 `Frame`。结论：JIT 是纯开销（评估报告 fib(25) 5490ms → 6213ms，20 万循环 1425ms → 1568ms）。

### 23.2.2 新实现

- `dao/jit/native.py`（约 340 行）：`NativeCodegen` 把热点 `CodeObject` 翻译为 Python 源码，按跳转目标切分基本块，块内生成顺序语句，用 Python 内置 `compile()` + `exec()` 在运行时生成可调用函数；操作数栈仍绑定在 `Frame.stack` 上，但消除了逐指令方法分派。
- 类型反馈守卫：`TypeFeedbackEntry.dominant_type()` 得到参数主类型，生成 `type(...) is not ... → _Deopt` 守卫；混合类型调用自动去优化回退到解释器路径。
- 去优化：`JitCompiler.handle_deoptimization()` 计数并移除专用体；同一热点最多去优化 3 次，之后永久回退，避免抖动。
- VM 集成（`dao/vm/core.py`）：热点键从「函数名」改为 `id(CodeObject)`，编译器持强引用防 id 复用与同名函数互相污染；顶层模块与热点函数优先调用生成的原生函数，未支持的操作码逐字节回退 `vm._dispatch`；递归通过 `vm._call` 复用同一原生函数，闭包父帧链、异常与返回值语义保持与原 VM 一致。

### 23.2.3 性能实测

基线（本报告下结论时，fib(24) 与 20 万次循环累加）：

| 负载 | AST | VM | VM + JIT（旧） |
| --- | --- | --- | --- |
| fib(24) | 3277 ms | 3555 ms | 3906 ms |
| 20 万次循环累加 | 1062 ms | 1398 ms | 1627 ms |

修复后主代理独立复测（每项 3 次中位数，单位 ms）：

| 负载 | AST | VM | VM + JIT（新） | JIT 相对 VM |
| --- | --- | --- | --- | --- |
| fib(24) | 3322 | 5082 | **795** | 快 6.4×（且快过 AST 4.2×） |
| 20 万次循环累加 | 1073 | 1447 | **500** | 快 2.9×（且快过 AST 2.1×） |

三次原始读数：fib — AST 3303/3385/3322、VM 5079/5082/5150、JIT 830/795/788；循环 — AST 1071/1073/1085、VM 1384/1447/1533、JIT 490/510/500（ms）。子代理独立实测（fib 0.79s / 循环 0.52s）与主代理复测量级一致。

另做了一组**进程内交替测量**（同一 Python 进程内构造 VM 反复执行 fib(24)，排除 CLI 启动与调用上下文差异）：VM 1.18s / 1.17s，JIT 0.325s / 0.322s，加速约 3.6×。两种测法的绝对耗时因调用上下文与 CPU 频率状态有差异，但结论一致：**JIT 明确快于 VM，也已快过默认 AST 解释器**；具体倍数随测法与负载波动，不作为固定承诺。

口径说明：这是**运行时代码生成 + 类型守卫特化**（生成 CPython 字节码由 CPython 执行），不是直接发射机器码的 C1/C2 级 JIT；加速来自减少分派与栈帧开销，收益依赖热点与类型稳定性。混合类型会触发去优化，回退后性能等于原 VM 路径。

## 23.3 关键字与导入体验

- `dao/parser/core.py` 定义 `CONTEXTUAL_KEYWORDS`（26 项）：步长、设置、默认、静态、获取、全部、规则、事实、异步、等待、通道、发送、接收、选择、超时等在「变量名/参数名/赋值目标」位置按标识符处理，结构语法（如 `遍历 i 从 0 到 9 步长 2`、`获取/设置` 属性、`事实/规则` 声明）保持不变；`parse_primary()` 对表达式中的上下文关键字做标识符回退，保留 `全部(...)`/`竞速(...)`/`查询(...)` 等结构形式。
- 保留字误用集中诊断：`定义 如果 = 1` → `“如果”是保留关键字，不能用作变量名`（含行列与源码片段）。
- `从 异步 导入 X` 的语句路由修正：语句开头的 `从` 一律按导入语句解析，模块路径段允许关键字 token。
- `从 数学 导入 *` 解析为 `ImportStmt(names=[("*", None)])`，运行时按模块导出列表绑定全部名称（无导出列表时过滤内置名与内部名），与精确导入/别名共存。
- `dao/stdlib/loader.py` 增加直觉别名：`异步` → `异步IO`、`加密` → `密码`，原模块名继续可用。
- 真实冒烟用例（AST 模式）：`函数 加(步长=1) 返回 步长+2` → `加(3)` 得 5；`定义 设置 = 7` → 7；`从 数学 导入 *` → `向上取整(3.2)` 得 4；`从 异步 导入 创建任务` 成功绑定。

## 23.6 遗留风险与后续建议

1. **VM/JIT 与 AST 仍有能力差异**：对 10 个随附示例做三模式差分后发现，VM 与 JIT 输出彼此一致，但相对 AST 仍缺少宏调用、类声明、异常捕获等支持（如 `宏系统示例.道`、`面向对象.道`、`基础示例.道`）；这些是 VM 既有的覆盖缺口，本次 JIT 特化未扩大也未缩小差异。需要 VM 语义对齐时，应在字节码编译/VM 侧补齐，而不是修改 JIT。
2. 本次 JIT 守卫只覆盖参数的**主类型**，未做算子级别数值特化、内联或机器码发射；浮点/混合类型热点会去优化回退。
3. 版本升至 1.3.0 后，`dist/` 下的产物需重建：本轮已重建 `dao-language-1.3.0.vsix`、`dist/nuitka/dao`（48 MB）与 `dao_1.3.0_linux_x86_64.deb`（45.3 MB）；原生二进制实测 `--version` 为 v1.3.0，VM / VM+JIT 下导入与成员运算结果正确，安装包内二进制与源产物逐字节一致（`dist/` 被 gitignore，不入库）。
4. xpassed 标记仍保留一项；两处 `xfail(strict=False)` 明确设计为「达成 xpass、未达成 xfail，如实记录」，不是过期标记，故未改动。

## 23.7 续作：VM 导入与成员运算符正确性

- **VM 导入语句**：字节码编译器新增 `IMPORT_STMT` / `EXPORT_STMT` 指令，VM 惰性复用一个 AST 解释器执行导入/导出（共享模块缓存），再把绑定写入当前栈帧；因此标准库精确导入、通配符、别名模块、本地 `.道` 模块、导出过滤、函数体内导入与中文报错在 `--mode vm` / `--mode vm --jit` 下均与 AST 模式一致。新增 `tests/test_vm_import.py`（24 passed）。
- **成员运算符修复**：差分测试发现 VM 中 `x 在 容器` 恒真——编译器没有为 `在` / `不在` 发射 opcode，容器值直接留在栈顶。新增 `CONTAINS` / `NOT_CONTAINS` 指令并在 VM 中用与 AST 解释器一致的 `left in right` 语义实现；列表、文本、字典键、条件判断、匹配守卫、JIT 路径与非法容器中文报错均有回归测试（`tests/test_vm_contains.py`，13 passed）。`示例/模式匹配.道` 的三模式输出已一致。
- **差分验证方法**：同一批示例分别以 AST / VM / VM+JIT 运行并比较退出码与输出；剩余差异仅集中在 VM 尚未支持的宏、类与异常捕获（见 23.6 第 1 项），JIT 与 VM 之间未发现新的语义分歧。
- **产物**：已重建 `dist/dao-language-1.3.0.vsix`（208 文件 / 307 KB）、`dist/nuitka/dao`（48 MB）与 `dao_1.3.0_linux_x86_64.deb`（45.3 MB），均基于本轮最新源码；原生二进制与安装包内的 dao 逐字节一致。
