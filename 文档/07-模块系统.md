# 7. 模块系统

模块系统是构建大型应用的基石。它解决了命名冲突、代码组织和依赖管理三大核心问题。"道"的模块系统设计力求简洁直观。

## 7.1 基本概念

- **文件即模块**：每个 `.道` 源文件自动构成一个模块
- **导出**：使用 `导出` 关键字将函数、类型、常量等暴露给外部
- **导入**：使用 `导入` 关键字引入其他模块的功能

## 7.2 导出

### 7.2.1 逐项导出

在需要导出的定义前添加 `导出` 关键字：

```
// 文件：数学工具.道

// 导出函数
导出 函数 加(甲, 乙)
    返回 甲 + 乙

导出 函数 减(甲, 乙)
    返回 甲 - 乙

// 导出常量
导出 常量 圆周率 = 3.14159

// 导出类型
导出 类型 向量
    初始化(x, y)
        本对象.x = x
        本对象.y = y

// 未导出的（模块私有）
函数 内部辅助函数()
    // 外部无法访问此函数
    返回 42
```

### 7.2.2 集中导出

在文件末尾统一导出，便于一目了然地了解模块的公共 API：

```
// 文件：字符串工具.道

函数 大写(文本)
    // ...

函数 小写(文本)
    // ...

函数 修剪(文本)
    // ...

函数 内部处理(文本)
    // 不导出

// 文件末尾集中导出
导出 大写, 小写, 修剪

// 或
// 导出
//     大写,
//     小写,
//     修剪

// 或
// 导出
//     大写, 小写, 修剪
```

## 7.3 导入

### 7.3.1 导入整个模块

```
// 导入整个模块，通过模块名访问
导入 数学工具

打印(数学工具.加(1, 2))     // 3
打印(数学工具.圆周率)       // 3.14159
```

### 7.3.2 导入特定项

```
// 只导入需要的函数
从 数学工具 导入 加, 圆周率

// 或
// 从 数学工具 导入
//     加, 圆周率

// 或
// 从 数学工具 导入
//     加,
//     圆周率


打印(加(1, 2))     // 3
打印(圆周率)       // 3.14159
```

### 7.3.3 重命名导入

```
// 避免命名冲突
从 数学工具 导入 加 作为 数学加法
从 字符串工具 导入 连接 作为 字符串拼接

打印(数学加法(1, 2))
打印(字符串拼接("你好", "世界"))
```

### 7.3.4 导入子目录模块

```
// 目录结构：
// 项目/
// ├── 主程序.道
// ├── 工具/
// │   ├── 数学.道
// │   ├── 文本.道
// │   └── 网络/
// │       └── 请求.道

// 用路径分隔符导入
导入 工具.数学
从 工具.文本 导入 大写
从 工具.网络.请求 导入 发送请求
```

## 7.4 包管理

### 7.4.1 包定义文件

每个项目根目录下有一个 `道.配置` 文件（类似 `project.yml` 配置文件）：

```
// 道.配置

名称 我的项目
版本 1.0.0
道版本 >=1.2.0
作者 张三
描述 一个示例项目
入口 主程序.道

依赖
    网络框架 >=2.0.0
    数据库驱动 ^1.5.0
    日志工具 1.2.3

开发依赖
    测试框架 >=3.0.0
```

主要字段：

| 字段 | 含义 |
|---|---|
| `名称` / `版本` | 包名与包版本，必填 |
| `道版本` | 该包要求的道语言版本约束，可选；支持 `>=`、`<=`、`>`、`<`、`==`、`^`、`~` 写法（如 `>=1.2.0`、`^1.2.0`）。打包时写入 `.道包`，安装时与当前解释器版本校验 |
| `作者` / `描述` | 包元数据 |
| `入口` | 导入顶层包名时加载的入口文件 |
| `依赖` / `开发依赖` | 依赖的其他包及版本约束 |

### 7.4.2 导入第三方包

```
// 导入第三方包
从 网络框架 导入 创建服务器, 路由
从 数据库驱动 导入 连接数据库
```

### 7.4.3 用 run / 运行 命令启动项目

在写有 `道.配置` 的项目根目录下，可直接用 `run`（或中文 `运行`）启动项目，无需手动指定入口文件：

```bash
dao run            # 或：dao 运行
python main.py run # 从源码运行时
```

命令会读取当前目录的 `道.配置`，按「入口」字段定位文件并运行；也可以显式指定项目目录：

```bash
dao run 路径/到/项目
```

「入口」字段兼容以下写法，均解析为实际的 `.道` 文件：

| 配置写法 | 解析结果 |
|---|---|
| `入口 主程序.道` | `主程序.道` |
| `入口 主程序` | `主程序.道` |
| `入口 接入层/入口.道` | `接入层/入口.道` |
| `入口 接入层.入口` | `接入层/入口.道`（点分模块路径转目录） |

运行前解释器会切换到项目根目录，因此入口文件中的相对模块导入（如 `从 领域层.领域 导入 工单`）可正常解析。若缺少 `道.配置`、未配置「入口」或入口文件不存在，命令会打印中文错误并以非 0 退出码结束。

### 7.4.4 打成依赖包（pack / 打包）

一个项目只要写好 `道.配置`，就可以直接打成可分发的依赖包（`.道包` 文件，本质是 ZIP 归档）：

```bash
dao pack                      # 或：dao 打包
python main.py pack 路径/到/项目
dao pack 路径/到/项目 -o 产物/我的库.道包
```

默认产物名为 `名称-版本.道包`，写在项目根目录。包内包含：

- `道.配置`（必须含「名称」「版本」，可选「道版本」约束，会随包一起分发）
- 项目内所有 `.道` 源文件，保持原有目录结构
- 根目录下的 `README.md` / `LICENSE` 等说明文件

以下目录与文件不会进入包：`.git/`、`.workbuddy/`、虚拟环境、`__pycache__/`、缓存目录、`道包/`（已安装的依赖）、`dist/`、`build/`、`测试/` / `tests/`，以及非 `.道` 的普通文件。归档内的路径会做安全性校验，拒绝绝对路径与 `..` 路径穿越。

### 7.4.5 安装与使用依赖包（install / 安装、packages / 包列表）

```bash
dao install 我的库-1.2.0.道包              # 装到当前项目的 道包/ 目录
dao install 包.道包 -p 路径/到/应用         # 指定目标项目
dao install 包.道包 --global                # 装到 ~/.道/包/，所有项目可用
dao install 包.道包 --force                 # 已安装不同版本时强制覆盖
dao install 包.道包 --skip-version-check    # 跳过「道版本」兼容性检查
dao packages                               # 或：dao 包列表，查看已安装包及道版本要求
```

安装后包目录结构与包解析器的搜索约定一致（`道包/<名称>/` 优先，`~/.道/包/<名称>/` 其次）。在消费方项目的 `道.配置` 中声明依赖，即可按包名导入：

```
// 应用项目的 道.配置
名称 我的应用
版本 1.0.0
入口 主程序
依赖
    我的库 >=1.2.0
```

```
// 主程序.道
从 我的库 导入 创建工具
从 我的库.工具.辅助 导入 内部函数
```

导入顶层包名时，解释器读取包配置的「入口」字段定位入口文件（兼容 `主程序`、`主程序.道`、`接入层.入口` 等写法）；导入子模块时按点分路径定位 `<包目录>/工具/辅助.道`。同一版本重复安装是幂等的，不会覆盖已有文件；版本不同时需显式加 `--force`。

如果包在 `道.配置` 里声明了 `道版本`，安装时会先校验当前解释器版本是否满足约束，不满足则打印中文错误并拒绝安装（例如「包 '数学库' 需要道语言版本 >=2.0.0，当前版本为 1.2.0」）。确实需要跨版本安装时可加 `--skip-version-check` 跳过检查；未声明 `道版本` 的旧包不受影响。`dao packages` 会在包名与版本后显示其道版本要求，例如 `数学库 1.2.0（道版本 >=1.2.0）`。

完整示例：

```bash
# 1. 打包库项目
dao pack 示例/我的库

# 2. 安装到应用项目
dao install 示例/我的库/我的库-1.2.0.道包 -p 示例/我的应用

# 3. 运行应用（依赖会自动从 道包/ 解析）
cd 示例/我的应用 && dao run
```

### 7.4.6 打包成可运行应用（build / 构建应用、run / 运行）

`.道包` 是给其他项目导入的依赖包；要把一个项目连同它**已安装的依赖**一起分发、直接运行，用 `build` 打成 `.道应用`：

```bash
dao build                                   # 或：dao 构建应用 / dao 打包应用
dao build 路径/到/项目 -o 产物/我的应用.道应用
dao build 路径/到/项目 --no-deps             # 不把 道包/ 里的依赖打进去
```

默认产物为 `名称-版本.道应用`，本质是 ZIP 归档，内含：

- `应用.配置` —— 应用清单：名称、版本、入口、道版本、打包时间
- 项目的 `道.配置` 与全部 `.道` 源码（保持目录结构）
- `道包/` 下已安装的依赖（用 `--no-deps` 可排除）

运行应用包：`dao run` 后跟 `.道应用` 文件时运行应用包，不带参数（或跟项目目录）时运行普通项目：

```bash
dao run 我的应用-1.0.0.道应用              # 或：dao 运行（中文命令）
python main.py run 应用.道应用 --mode vm
```

`dao run` 会把应用包解压到临时目录，按 `道.配置` 的「入口」运行，结束后自动清理。解压后的目录结构与普通项目一致，依赖仍按 `道包/` 解析，因此应用可脱离原项目运行。运行前会校验应用清单里的 `道版本` 约束（规则与依赖包相同）。

两种产物的区别：

| 产物 | 用途 | 打包命令 | 使用方式 |
|---|---|---|---|
| `.道包` | 库，供其他项目导入 | `dao pack` | `dao install` 后 `从 包名 导入 ...` |
| `.道应用` | 完整应用，可直接运行 | `dao build` | `dao run 应用.道应用` |

## 7.5 模块初始化

模块在首次被导入时执行其顶层代码（仅一次），后续导入直接使用缓存结果：

```
// 文件：数据库.道

// 这段代码在模块首次被导入时执行一次
打印("正在初始化数据库连接...")
定义 数据库连接 = 连接数据库("localhost", 3306)

导出 函数 查询(sql语句)
    返回 数据库连接.执行(sql语句)
```

## 7.6 条件导入

根据运行时环境选择不同的实现：

```
如果 系统.平台 == "浏览器"
    从 网络.浏览器端 导入 发送请求
否则
    从 网络.服务器端 导入 发送请求
```
