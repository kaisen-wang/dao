## 20.3 标准库（✅ 15 个模块）

`文本`、`数学`、`集合`、`时间`、`编码`、`文件`、`系统`、`测试`、`日志`、`网络`、`异步IO`、`密码`、`数据库`、`调度`、`大模型`。

- 标准库函数**只能用** `从 模块 导入 名称`；`导入 模块` 会过滤掉 `BuiltinFunction`。

- `大模型` 模块是第 15 个模块，接 §20.5 的接口层。
- 新增 stdlib 函数须同步：docgen 描述 / 工厂幂等 / 导出集合三类断言，以及文档 10、标准库 API 文档、文档 18、19 的清单。

## 20.8 结论与下一步

**已完成**：一门可用的多范式中文编程语言解释器（四范式 + 双执行模式 + 15 标准库），完整开发者工具链，LLM 接口层，以及一个经历 12 轮迭代、覆盖常驻 Agent 绝大部分 P0 能力的参考实现（更夫）。

**当前阶段的主要矛盾**不是功能缺失，而是**真实环境验证**：PRD §12 六项 DoD 全部未勾选，其中 p95 ≤60% 在本地同口径下实测未达成（101.34%）。

**建议的下一步优先级**：

1. **真实 GitHub 闭环**（DoD #4，解锁 FR-01/11/15 与 #5）：需独立账号、目标仓库、webhook 公网可达、分支保护与人工审批流程——这是唯一能一次性推进多项 DoD 的关键路径，但依赖外部账号与部署决策。
2. ~~**p95 负面结论的处理**（DoD #2）~~ **已于第十三轮处理**：根因是指标错配——「逐条 p95」测单条计算耗时，并发数学上无法降低它。已改为「端到端批完成时间比」（I/O-bound 负载），本地达标 38.69%/2.58x；确认「批处理优于单会话」仅在 I/O-bound 成立，真实 Worker 正是该场景。**剩余**：用真实 LLM/worktree 等待（live ollama）复验生产口径（文档 21）。
3. **真实 observe ≥1 周**（DoD #6）与 auto 模式门禁：需长驻部署 + 人工审计，短期不追求勾选。
4. **工具链发布**：VS Code 市场、nvim-lspconfig 上游 PR（需人工账号决策）。
5. **性能后端**：WASM / GraalVM 评估（远期，文档 16 剩余待办）。

> **诚实口径**：本文所有「✅ 完成」均指本地实现与测试通过，不等于生产环境验收；更夫 12 轮均为本地/回环模拟，不勾选 PRD §12 任何 DoD 项。
