# 10. 标准库概要设计

"道"的标准库旨在提供日常开发所需的核心功能，所有 API 均使用中文命名，遵循统一的设计风格。

## 10.1 标准库模块总览

| 模块 | 说明 | 核心功能 |
|------|------|---------|
| `文本` | 字符串处理 | 分割、连接、查找、替换、正则 |
| `数学` | 数学计算 | 三角函数、随机数、统计 |
| `集合` | 数据结构 | 有序字典、双端队列、堆、树 |
| `文件` | 文件系统操作 | 读写、遍历、监听 |
| `网络` | 网络通信 | HTTP 请求/服务、WebSocket |
| `时间` | 日期与时间 | 解析、格式化、时间戳互转、时区、日期加减、日历、计时 |
| `编码` | 数据编码 | JSON、XML、CSV、Base64 |
| `系统` | 系统交互 | 环境变量、命令行参数、进程 |
| `测试` | 测试框架 | 断言、测试套件、模拟 |
| `日志` | 日志记录 | 分级文本日志、格式化、输出；结构化日志（OTel 事件模型、处理器链、W3C 追踪传播） |
| `异步IO` | 异步编程 | 任务、子进程、TCP 服务、异步文件读写 |
| `密码` | 哈希与签名 | MD5/SHA-1/SHA-256/SHA-512、HMAC-SHA256、验证签名、UUID、随机令牌/随机字节 |
| `数据库` | SQLite 持久化 | 连接、执行、查询、事务、WAL |
| `调度` | 定时调度 | 延迟执行、周期执行、取消调度、等待全部 |
| `大模型` | 大模型接口 | 统一 Provider 抽象、对话/流式对话、模型列表 |
| `路径` | 路径处理 | 拼接、拆分、存在性判断、遍历、glob 匹配 |
| `进程` | 进程管理 | 创建子进程、捕获输出、超时、退出码、工作目录 |
| `归档` | 压缩归档 | zip/tar 打包与解包、成员列举、路径穿越防护 |
| `二进制` | 二进制序列化 | struct 定长打包/解包、字节互转、安全序列化、拒绝不可信 pickle |
| `国际化` | 国际化与本地化 | 区域设置、翻译表、复数形式、数字/货币/日期本地化格式 |

## 10.2 核心模块详细设计

### 10.2.1 文本模块

```
从 文本 导入 分割, 连接, 替换, 包含, 去空格, 正则匹配

定义 句子 = "  你好，世界！这是道语言。  "

// 去除首尾空白
打印(去空格(句子))  // "你好，世界！这是道语言。"

// 分割
定义 词语 = 分割("苹果,香蕉,橙子", ",")
打印(词语)  // ["苹果", "香蕉", "橙子"]

// 连接
打印(连接(词语, " 和 "))  // "苹果 和 香蕉 和 橙子"

// 替换
打印(替换("你好世界", "世界", "道语言"))  // "你好道语言"

// 包含检查
打印(包含("你好世界", "世界"))  // 真

// 正则表达式
定义 匹配 = 正则匹配("我的电话是13812345678", "[0-9]{11}")
打印(匹配)  // ["13812345678"]
```

```
从 文件 导入 读取, 写入, 追加, 存在, 列出目录, 逐行读取

// 写入文件

    如果 包含(行, "错误")
        打印(行)
```

### 10.2.9 日志模块

`日志` 模块提供分级日志，可打印到控制台、写入文件或两者同时输出，格式完全可配置（完整清单见 `文档/标准库API/日志.md`）。

```
从 日志 导入 配置日志, 默认格式

日志器 = 配置日志(输出="两者", 路径="应用.log", 格式=默认格式, 级别="信息")
日志器.信息("服务启动")
日志器.错误("连接失败")
日志器.记录("警告", "重试第 2 次")
```

`默认格式` = `{级别} {时间戳} {线程ID} {代码位置} | {描述信息}`，涵盖日志级别、时间戳、线程 ID、代码位置与描述信息。可用 `格式` 参数自由组合占位符（另有 `{线程名}`、`{名称}`、`{文件名}`、`{行号}` 等），用 `时间格式` 指定 strftime 风格时间格式，用 `级别` 过滤输出。`{代码位置}` 由解释器在调用日志方法时自动注入（相对于命令执行目录的路径:行号），无需调用者传入。

除文本日志外，`日志` 模块还提供**结构化日志（structured logging）**：把每条日志当作一个事件（event），以单行 JSON（JSON Lines）输出，字段遵循 OpenTelemetry Logs Data Model（Timestamp / ObservedTimestamp / SeverityNumber / SeverityText / Body / Attributes / Resource / Scope / TraceId / SpanId）。结构化日志支持处理器链（属性注入、脱敏、采样、追踪/资源注入）、W3C traceparent 追踪上下文传播、OTLP/HTTP JSON 导出（对接 Collector）、尾部采样与环境变量集中配置，便于日志平台检索、聚合与链路关联。完整说明见 `文档/标准库API/日志.md` 的「结构化日志」章节，可运行示例见 `示例/结构化日志/`。

结构化日志新增 API 清单：

| 函数 / 方法 | 签名（要点） | 说明 |
|------------|--------------|------|
| `配置结构化日志` | `(名称, 输出, 路径, 级别, 资源, 处理器, 批量大小, 异步, 导出器=空) -> DaoStructuredLogger` | 配置结构化日志器；传入导出器时以它为准 |
| 日志器方法 | `调试/信息/警告/错误/致命(消息, 属性=空)`、`记录(级别, 消息, 属性=空)` | 记录带属性的结构化事件 |
| `刷新` / `关闭` / `取记录` | `()` | 刷新缓冲、关闭导出器、取回字典形式的记录列表（需内存输出） |
| `创建追踪` | `(属性=空, 追踪ID=空, 跨度ID=空)` | 创建并激活追踪上下文（baggage） |
| `取追踪头` / `载入追踪头` | `() -> 文本` / `(traceparent 文本) -> 追踪上下文或空` | W3C traceparent 注入与提取 |
| `设置资源` | `(服务名, 主机名, 环境, 属性)` | 设置全局资源元数据 |
| `创建属性处理器` | `(属性=空)` | 合并静态属性到事件 |
| `创建脱敏处理器` | `(键=空, 模式=空, 掩码="***")` | 清除 PII 敏感信息（`规则` 是关键字，须用 `模式`） |
| `创建采样处理器` | `(比率=1.0, 保留错误=真)` | 按比率采样，错误事件始终保留 |
| `创建内存导出器` | `()` | 内存收集记录，便于测试 |
| `创建OTLP导出器` | `(端点, 头=空, 超时=5.0)` | OTLP/HTTP JSON 导出，对接 Collector |
| `创建尾部采样导出器` | `(导出器, 比率=1.0, 保留错误=真, 最大追踪数=1000)` | 按 TraceId 聚合，保留含错误的整条链路 |
| `从环境加载资源` | `()` | 从 `OTEL_*` 环境变量加载并激活资源元数据 |

```
从 日志 导入 配置结构化日志, 创建追踪, 取追踪头, 创建属性处理器

追踪 = 创建追踪(属性={"租户": "acme"})
头 = 取追踪头()  # W3C traceparent 字符串，注入下游请求头；下游用 载入追踪头(头) 恢复
日志器 = 配置结构化日志(名称="服务", 输出="文件", 路径="应用.日志",
                     资源={"服务名": "支付服务"},
                     处理器=[创建属性处理器(属性={"环境": "生产"})])
日志器.信息("支付成功", 属性={"user.id": "123", "order.id": "456"})
日志器.刷新()
日志器.关闭()
```

结构化日志默认输出到标准错误流（stderr）；示例程序可用 `2>文件` 重定向输出。

## 10.3 标准库设计原则

1. **命名一致性**：所有函数和类型使用中文命名，动词在前（如 `读取文件` 而非 `文件读取`）
2. **错误处理**：函数在遇到错误时抛出明确的异常，不使用错误码
3. **惰性优先**：处理集合和 I/O 时优先使用惰性求值，避免不必要的内存占用
4. **异步友好**：所有 I/O 操作同时提供同步和异步版本
5. **零依赖**：标准库不依赖第三方包，仅依赖虚拟机底层能力
