# 21. 注解功能（`@` 运行时装饰器）

注解（Annotation）是以 `@` 前缀写在声明之前的运行时装饰器，用于函数、类、变量等声明的元编程包装：日志、缓存、注册、校验、标记等。它借鉴 Python 装饰器的语义，但完全使用中文语法与中文错误消息。

## 21.1 语法

```
@名称
函数 问候(名字)
    返回 `你好，{名字}`

@名称(参数)
@另一个名称(键=值)
函数 计算(n)
    返回 n
```

- `@` 后紧跟**标识符**（注解名），可带一对括号的参数列表：`@名称`、`@名称(参数)`。
- 参数支持位置参数与关键字参数，复用现有表达式解析，例如 `@缓存(10)`、`@标记(用途="用户模型")`。
- 多个注解按**书写顺序堆叠**，每个注解独占一行；执行顺序为**从下往上**（最靠近声明的先执行），与 Python 一致。
- 注解只能附着在：`VariableDecl`（变量声明）、`FunctionDecl`（函数声明）、`AsyncFunctionDecl`（异步函数声明）、`ClassDecl`（类型声明）、`AbstractDecl`（抽象类声明）、`EnumDecl`（枚举声明）、`TraitDecl`（特征声明）。
- 注解写在**声明所在行的上一行**，可带缩进（类体内部的方法、属性同样支持）。

## 21.2 运行时语义

对目标 `T` 与注解序列 `[A1, A2, ... An]`（书写顺序），应用顺序为 `An, ..., A2, A1`：

1. 在当前环境按注解名查找可调用对象（函数、内置函数或类）。
2. 调用形式为 `注解函数(T, *args, **kwargs)` —— **被装饰对象永远作为第一个位置参数**，其后是注解括号内的参数。
3. 若调用返回值**不是 `空`**，用返回值**替换** `T`；若返回 `空`（或没有显式返回），**保留**原 `T`。因此纯标识型注解无需返回任何东西。
4. 替换后的对象绑定到原声明名。
5. 注解元数据同时写入对象的 `__注解__` 属性，供运行期自省；若对象不支持属性写入，则**静默跳过**，不影响主流程。

> 记忆口诀：**下先上后，目标打头；非空替换，空值保留。**

## 21.3 示例

### 21.3.1 日志包装函数

注解函数返回一个新函数，替换原函数，从而在不修改函数体的前提下加入日志。

```
定义 日志(目标, 标签="")
    函数 包装(名字)
        打印(`[日志:{标签}] 调用，参数: {名字}`)
        定义 结果 = 目标(名字)
        打印(`[日志:{标签}] 返回: {结果}`)
        返回 结果
    返回 包装

@日志("问候")
函数 问候(名字)
    返回 `你好，{名字}`

打印(问候("小明"))
// [日志:问候] 调用，参数: 小明
// [日志:问候] 返回: 你好，小明
// 你好，小明
```

### 21.3.2 缓存 / 替换目标

注解函数返回一个包装函数，拦截调用并缓存结果，实现「替换」语义。

```
定义 缓存表 = {}

定义 缓存(目标)
    函数 包装(n)
        如果 n 在 缓存表
            返回 缓存表[n]
        定义 结果 = 目标(n)
        缓存表[n] = 结果
        返回 结果
    返回 包装

@缓存
函数 慢计算(n)
    打印("真正计算一次")
    返回 n * n

打印(慢计算(4))   // 真正计算一次；16
打印(慢计算(4))   // 16（命中缓存，不再执行函数体）
```

再来看「返回 `空` 保留原对象」的情形。下面的注解只在声明时登记一次，不替换目标：

```
定义 注册表 = []

定义 登记(目标, 名称)
    注册表 = 注册表 + [名称]
    打印(`已登记: {名称}`)
    返回 空        // 显式返回空 → 保留原函数

@登记("加法")
函数 加法(甲, 乙)
    返回 甲 + 乙

打印(加法(1, 2))   // 已登记: 加法（声明时）；3
```

### 21.3.3 类标记注解

注解可用于类型声明，把元数据写入 `__注解__`，用于运行期自省。

```
定义 标记(目标, 用途)
    打印(`注册模型: {用途}`)
    返回 目标        // 返回目标本身，不替换；元数据仍会写入

@标记("用户模型")
类型 用户
    定义 名字 = ""

定义 u = 用户()
u.名字 = "张三"
打印(u.__注解__)      // 含本次注解的元数据
```

> 元数据写入是「尽力而为」的：若目标对象不允许写入属性，注解主流程仍然成功，只是不生成 `__注解__`。

## 21.4 堆叠与执行顺序

```
@计时
@缓存
函数 fib(n)
    返回 n
```

书写顺序为 `计时`、`缓存`，实际应用顺序为**先缓存、后计时**：`缓存` 先包裹原始的 `fib`，再由 `计时` 包裹缓存后的版本。因此调用 `fib` 时，`计时` 在最外层，`缓存` 在其内层。

## 21.5 错误处理

所有面向用户的错误消息均为中文，沿用现有的异常类型（词法错误、语法错误、运行时错误）：

| 错误场景 | 异常类型 | 错误消息 |
|----------|----------|----------|
| `@` 后没有标识符 | 词法错误 | `'@' 后需要一个注解名` |
| 同一行连续写两个 `@`（未换行分隔） | 语法错误 | 注解之间必须换行分隔 |
| 注解附着到非声明语句 | 语法错误 | `注解只能用于声明（变量/函数/类/枚举/特征）` |
| 注解名在当前环境找不到 | 运行时错误 | `注解 '名称' 未定义` |
| 注解名对应的对象不可调用 | 运行时错误 | `注解 'X' 不可调用` |

示例：

```
@不存在的注解
函数 你好()
    返回 "你好"
// 运行时错误：注解 '不存在的注解' 未定义
```

## 21.6 与 `!宏名()` 宏系统的区别

道语言同时提供 `@名称` 注解与 `!宏名()` 宏，两者用途不同，不可混用：

| 维度 | `@名称` 注解 | `!宏名()` 宏 |
|------|-------------|-------------|
| 执行时机 | **运行时**装饰已创建的声明对象 | **编译期**展开为新的 AST / 代码 |
| 操作对象 | 声明后的**值**（函数、类、变量值） | **代码块 / 语法结构**（`引述`、`注入`） |
| 定义方式 | 普通函数或可调用对象 | `定义宏` 关键字 |
| 调用形式 | 解释器自动调用 `注解函数(目标, ...)` | 显式写 `!宏名(参数)` |
| 命名空间 | 当前运行环境（普通变量作用域） | 独立的宏注册表 |
| 典型用途 | 日志包装、缓存替换、注册、标记元数据 | 新增语法糖、DSL、消除重复模板代码 |

**取舍建议：**

- 需要**改变语法结构**、生成新代码、避免运行时开销 → 用宏。
- 需要**包装现有函数/类**、延迟注册、缓存结果、附加元数据 → 用注解。
- 两者的名字互不冲突：例如 `文档/06-元编程.md` 中的内置宏 `@日志`、`@缓存` 是宏名，调用时写作 `!日志(...)`、`!缓存(...)`；而本节注解 `日志`、`缓存` 是环境里的普通函数，由解释器自动调用。同名不会互相覆盖。

## 21.7 编辑器支持

- **VS Code**：`编辑器插件/vscode/syntaxes/dao.tmLanguage.json` 已加入 `@注解名` 的 TextMate 规则，`@` 标记为 `punctuation.definition.annotation.dao`，注解名标记为 `entity.name.tag.annotation.dao`。支持中文注解名，匹配行首（允许缩进）的注解。
- **Neovim**：`编辑器插件/neovim/syntax/dao.vim` 已加入 `syn match daoAnnotation`，链接到 `PreProc` 高亮组，同样支持中文注解名与行首缩进。
- 两种编辑器均支持多个注解逐行堆叠高亮；注解参数中的字符串、数字等继续沿用既有的高亮规则。
