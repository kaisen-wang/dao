# VM 语义对齐报告（2026-11-28）

## 24.1 背景与目标

`--mode vm` 与默认 AST 解释器长期存在语义差异：单测全绿但真实程序会静默丢失语句、参数绑定错误或抛出 Python 原生异常。本报告记录以「AST 解释器为唯一语义基准」的对齐工作，覆盖默认参数、变长参数、关键字参数、解构赋值、成员/下标赋值、断言、常量、生成器、异步、展开、运算符重载、真值判定、除零、模式匹配守卫、并行语句等。

契约与文件划分见 `任务/VM语义对齐规格.md`。四路子代理并行：编译器委托发射、VM 运行时语义、opcode/JIT 回退、差分回归测试；主代理独立验收。

## 24.2 对齐前实测差异

主代理独立差分探针（21 个正确语法用例）对齐前共 11 项不一致：

| 用例 | AST | VM（对齐前） |
| --- | --- | --- |
| 默认参数 `函数 加(a, b=2)` | `3` | 未定义变量 `b` |
| 变长参数 `...剩余` | `[2, 3]` | 未定义变量 `剩余` |
| 关键字参数 `f(1, b=3)` | `-2` | 未定义变量 `b` |
| 解构赋值 `[甲, 乙] = [1, 2]` | `1 2` | 未定义变量 `甲` |
| 成员赋值 `p.x = 9` | `9` | 名称错误（属性不存在） |
| 下标赋值 `a[0] = 9` | `[9, 2]` | `[1, 2]`（赋值静默失效） |
| `断言 假` | 断言失败 | 什么都不做 |
| 常量重写 | 运行时错误 | 静默改写 |
| 生成器 `产出` | 逐个产出 | `NoneType` 不可迭代 |
| 异步函数 `等待` | `1` | 变量未定义 |
| `"啊" * 2.0` / `1 // 0` | `啊啊` / 中文除零错误 | Python `TypeError` / `ZeroDivisionError` |

另有枚举注解丢失、并行语句体不执行、列表/字典/集合展开失败、匹配守卫在外层同名变量存在时读到旧值等差异。

## 24.3 实施方案

1. **新增唯一 opcode `DELEGATE_STMT`**：操作数指向常量池中的 AST 语句节点，无栈效应。VM 复用已有内嵌 AST 解释器与桥接环境执行，把「VM 无原生等价」的语句一次性对齐，避免为每种语法新增指令。
2. **委托范围**：`断言`/`解构`/`产出`/`类型别名`/`异步函数`/`并行`/`选择`/`同步`/`逻辑块`；`成员或下标写入的赋值`；带默认值、变长参数、导出、yield 或注解关键字参数的函数声明；常量与导出变量声明。
3. **表达式层复用 `DELEGATE_EXPR`**：带关键字参数或位置参数展开的调用、含展开的列表/字典/集合/元组字面量。
4. **枚举注解复用 `APPLY_ANNOTATIONS`**：`BUILD_ENUM`/`STORE_LOCAL` 后应用，操作数 `(stmt, local_idx)`。
5. **常量语义**：`Frame.constants` 与 `Environment.constants` 别名共享；全局常量集合在 VM 实例上持久保存；原生 `STORE_*` 写入前检查。
6. **运行时语义统一**：`_binary_op` 集中实现运算符重载（只求值右操作数一次）、文本乘数值取整、`/`/`//` 中文除零错误；`_truthy`/`_unary_not` 复用 AST 的 `_is_truthy`；下标先 `int()`；未定义变量抛 `名称错误`；匹配守卫强制绑定与字典键表达式求值。
7. **JIT 同步**：`DELEGATE_STMT` 指令整段回退解释执行；native codegen 的算术/比较/真值改为调用同一批 VM 辅助方法，避免 JIT 绕过对齐语义；原有控制流与基本块直译保留，fib 快路径不受影响。

## 24.4 验收结果

- **主代理独立差分探针 30 例 × 三模式**：28 例 AST/VM/VM+JIT 输出与异常完全一致；剩余 2 例仅是除零错误的行列号不同（AST 报 `[行 1, 列 4]`，VM 原生指令只能报 `[行 0, 列 0]`），错误类型与文案「除零错误」一致。对齐前为 11/21 例不一致（见 §24.2）。
- **新增差分回归测试** `tests/test_vm_alignment_core.py`、`test_vm_alignment_delegate.py`、`test_vm_alignment_jit.py` 共 69 passed；另修正 `test_vm_import.py` 一处旧断言（未定义变量文案改为与 AST 一致的「变量 'X' 未定义」）。
- **全量测试**：`2896 passed / 2 skipped / 1 xfailed / 1 xpassed`（173.12s，基线 2827 passed；新增 69 项）。
- **静态检查**：新增测试文件 `ruff check` 全绿；改动产品文件的 F401/I001/SIM 告警均为 HEAD 既有风格问题，无 F821/E9 致命项。
- **JIT 性能回归**：20 万次循环 AST 1038ms / VM 1549ms / VM+JIT 630ms（三次中位数），JIT 仍显著快于 VM 与 AST；fib 示例三模式约 392/400/402ms（工作负载小，差异在噪声范围内）。
- **代表性示例三模式差分**：10 个示例（基础/面向对象/高阶函数/模式匹配/宏/枚举/生成器/新特性/综合/斐波那契）在修复两处集成缺口后 stdout 全部一致：
  - 函数式内置（`映射`/`筛选`/`折叠`/`排序`）此前只在桥接解释器惰性创建时注入，纯 VM 程序报「变量 '映射' 未定义」；现在 VM 构造时即注入包装后的解释器内置函数。
  - 类型对象的静态方法访问此前在 VM 中绕过 `_eval_class_member`，`find_method` 不覆盖 `static_methods` 导致崩溃；现在统一委托 AST 的类成员访问逻辑。
  - `基础示例.道` 的捕获异常详情仍只有行号/源码光标差异（VM 指令不存列号），其余输出一致。
- 两项修复已补充到差分测试（`test_vm_alignment_core.py` 共 69 passed）。
- **全量示例批量差分**（58 个 `.道` 示例 × 三模式）：46 例输出与 stderr 完全一致；剩余差异均非本次语义改动引入：
  - `计时宏.道`：耗时数值为运行时测量值，天然不固定；
  - `基础示例.道`、逻辑编程示例、`property_accessor/Person.道`：AST 在错误消息后附带源码行与光标片段，VM 原生指令只保存行号（错误类型与文案一致）；
  - 4 个异步示例自身在 AST 模式就因自定义 `睡眠` 与内置 `睡眠` 重名而失败，VM 报的是另一条中文错误（既有内置名遮蔽差异，不属于本轮对齐范围）。

## 24.5 已知边界

- 委托执行的函数由 AST 解释器持有闭包与参数绑定，VM 模式下这部分函数不走 JIT 特化；原生快路径函数（无默认值/rest/yield/导出/注解 kwargs）不受影响。
- 错误消息的行列信息在 VM 原生指令上只能取到指令行号，与 AST 节点列号可能不同；对齐的是错误类型与关键文案。
- VM/原生包的既有产物需重建后才会包含本次语义改动。
