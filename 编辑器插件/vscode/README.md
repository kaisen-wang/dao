# 道语言 VS Code 扩展

为「道」中文多范式编程语言提供编辑器支持。安装后，`.道` 文件即可获得语法高亮、括号匹配、注释切换，以及来自道语言 LSP 服务器的诊断、自动补全、悬停提示与跳转定义等能力。

## 功能

- **语法高亮**：基于仓库词法分析器 `源码/dao/tokens.py` 中的完整关键字表，对控制流、面向对象、函数式声明、逻辑编程、宏、并发、类型、异常处理、逻辑运算等分类着色；同时支持数值、字符串、反引号模板字符串（含插值）、文档注释、宏调用 `!`、逻辑变量 `?`、管道 `|>` 等语法元素。
- **括号匹配与自动闭合**：支持 `() [] {} （）` 及引号、反引号的配对；支持全角中文标点。
- **注释切换**：`//` 行注释、`/* */` 块注释；`///` 为文档注释，`注：` 作为中文行注释同样会被高亮。
- **LSP 语言服务**：由插件在后台以 stdio 方式启动仓库内置的解释器与 LSP 服务器，提供诊断、补全、悬停、跳转等能力。

## 安装与构建

### 方式一：安装 .vsix（推荐）

仓库 `dist/` 下提供已打包的 `dao-language-1.0.0.vsix`（含全部生产依赖，约 305 KB）。在 VS Code 中通过「扩展」面板 →「…」→「从 VSIX 安装…」选择该文件即可。

> **LSP 路径说明**：扩展本身不包含 Python 解释器与道语言源码。安装后，插件会优先从**当前工作区**寻找含 `源码/dao/lsp/` 的道语言项目（即你应在 VS Code 中打开道语言仓库根目录），并使用其中的 `源码/.venv/bin/python`。若打开的是其他项目，请手动把 `dao.pythonPath` 设为道语言环境的解释器绝对路径。

### 方式二：从源码加载

本插件依赖 `vscode-languageclient`。若未打包，可先安装依赖：

```bash
cd 编辑器插件/vscode
npm install
```

该命令会依据 `package.json` 安装 `vscode-languageclient`（^8.1.0）。安装完成后即可在 VS Code 中以开发模式加载本插件（见下节）。

### 重新打包 .vsix

```bash
cd 编辑器插件/vscode
npm install --omit=dev
npx @vscode/vsce package --out ../../dist/dao-language-1.0.0.vsix
```

打包产物只含生产依赖、语法文件与 LICENSE；`vsce` 本身不会进入产物。

## 从源码加载与调试

1. 用 VS Code 打开本插件目录：

   ```bash
   code 编辑器插件/vscode
   ```

2. 按 **F5**（或选择「运行 → 启动调试」），VS Code 会以「扩展开发宿主」窗口加载本插件。
   - 若首次运行提示选择调试配置，选择「扩展开发」。
   - 本插件未包含 `launch.json`，F5 会使用默认的扩展调试配置；如需自定义，可在 `.vscode/launch.json` 中指定 `--extensionDevelopmentPath`。

3. 在打开的扩展开发宿主窗口中，打开任意 `.道` 文件即可验证：
   - 关键字是否有颜色；
   - 括号是否能匹配跳转、输入开括号是否自动补全；
   - 打开「输出」面板，选择「道语言服务」通道，可查看 LSP 启动与通信日志（需开启 `dao.trace.server`，见下）。

4. 修改 `extension.js` 或语法文件后，在扩展开发宿主窗口中按 **Ctrl+R**（macOS 为 **Cmd+R**）重新加载窗口即可生效。

## 配置说明

在 VS Code 设置中搜索「道语言」，可配置以下项：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `dao.pythonPath` | `../../源码/.venv/bin/python` | LSP 服务使用的 Python 解释器路径。相对路径基于**本插件目录**解析，因此默认值正好指向仓库内置的虚拟环境；也可填写绝对路径。留空时自动回退到仓库内置环境。 |
| `dao.trace.server` | `off` | 是否在「输出」面板记录与 LSP 服务器的通信，可选 `off`、`messages`、`verbose`。排查问题时可设为 `messages`。 |

插件启动 LSP 时执行的命令等价于：

```bash
cd 源码 && <pythonPath> -m dao.lsp
```

通信方式为 JSON-RPC over stdio，工作目录固定为 `源码`，因此无需额外设置模块搜索路径。

## 常见问题

### 1. 语法有颜色，但没有诊断/补全/悬停

说明 LSP 服务未成功启动，按以下步骤排查：

1. 打开「输出」面板，选择「道语言服务」通道，查看是否有启动报错。
2. 将 `dao.trace.server` 设为 `messages`，重新加载窗口，观察是否收到客户端与服务器之间的消息。
3. 在终端手动验证解释器是否可用：

   ```bash
   cd 源码
   ./.venv/bin/python -m dao.lsp
   ```

   该命令会进入 stdio 等待状态（无输出属正常，按 Ctrl+C 退出）。若报 `No module named dao`，说明工作目录或解释器有误。

### 2. 提示找不到 Python 解释器 / 找不到 `dao` 模块

- 确认仓库根目录的 `源码/.venv` 虚拟环境存在，且其中已安装项目依赖（见 `源码/requirements.txt`）。
- 若 VS Code 从其他位置加载插件，默认的相对路径可能不再指向仓库内的环境，请在 `dao.pythonPath` 中填写解释器的**绝对路径**。
- Windows 环境下虚拟环境解释器通常位于 `源码\.venv\Scripts\python.exe`，需相应调整配置。

### 3. 注释、关键字高亮不符合预期

确认文件语言模式为「道语言」（状态栏右下角显示为 `道语言` 或 `dao`）。`.道` 扩展名会自动关联；若未关联，可在设置中通过 `files.associations` 添加 `"*.道": "dao"`。

### 4. 修改源码后语言服务未更新

LSP 服务器进程在插件激活时启动一次。若修改了 `源码/dao/lsp/` 下的代码，请在扩展开发宿主窗口中重新加载窗口（Ctrl+R / Cmd+R），或重启 VS Code，以重新启动语言服务进程。

## 已知限制

- 本插件源码中不包含 `vscode-languageclient` 依赖本体，首次使用需执行 `npm install`（离线环境请提前准备依赖）。
- 插件未附带 `launch.json` 与打包脚本，调试与打包按上文说明手动进行。
- 中文关键字的高亮依赖编辑器主题对 `keyword.*`、`storage.*` 等作用域的支持，不同主题下颜色可能略有差异。
